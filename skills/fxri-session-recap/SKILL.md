# 会话归档与上下文恢复

## 何时使用

- **归档模式**：一场会话接近尾声，需要把结论带出对话
- **恢复模式**：新会话开场，需要接上上次的工作现场
- 触发词：会话要结束了 / 归档本次会话 / 总结本次 / 恢复上下文 / 继续上次

**何时不使用**：会话中途的常规方案落盘与任务建档（用 fxri-plan-to-task）；与工作交接无关的对话总结。

## 能力边界（先读这段）

- 所有 agent 的共性约束：新会话读不到其他会话的内部上下文，对话记录本身不可跨会话传递
- 本技能的解法是把记忆**沉淀进仓库文件**（`.tasks/`），依赖「每次会话结束前归档」的纪律
- 个别 agent（如 Claude Code）可直读历史会话转录，属非通用的高级路径，本技能不依赖它

## 模式一：归档本次会话

> 目标：会话结束后，任何人（或新会话的 AI）只看仓库就能还原本次做了什么、为什么、还剩什么。

1. **回顾盘点**：梳理本会话的结论、关键决策、代码改动、未尽事项；与工作产出无关的闲聊不记。⚠️ 对话中产生的**决策及其理由必须记**（如「为什么选方案 B 不选 A」）——决策散落在对话里，会话一关就丢；用户明确要求记录的内容即使看似闲聊也照记
2. **逐条落盘**到任务文件（先查后写；文件格式与目录规范见 `../fxri-plan-to-task/references/task-spec.md`，技能独立安装时按仓库根 SPEC.md）：
   - 会话工作有对应任务 → 更新原文件：正文追加结论与决策，`updated` 同步
   - 无对应任务但有独立成果 → 按 fxri-plan-to-task 规范建档
   - 未尽事项 → 拆独立任务文件（`status: 待办`），不在正文留游离待办
3. **状态收尾**：整场完成且验收过的任务置 `status: 已完成` 并补 `completed: YYYY-MM-DD HH:mm`；未做完的保持原状态并写清当前进展
4. **归档**：终结态任务按 task-spec「手工归档步骤」执行（合并归档块 → 降序重排 → 写回 → 删源文件 → 清理空月份目录）
5. **归档提交同批（硬约束）**：归档文件必须与本次代码变更落在同一个 git 提交
6. **回报**：向用户列出本次沉淀的任务清单与归档位置，确认无遗漏后再结束会话

## 模式二：恢复上下文

> 目标：新会话快速重建现场，只读不改。

1. 读 `.tasks/active/` 全部任务文件（含 `{YYYYMM}/` 月份子目录）
2. 读最近归档：`archive/` 下最新月份文件，看尾部最新归档块（归档块降序排列）
3. 输出现场摘要：进行中/阻塞的任务、最近完成的任务、未完事项、建议的下一步
4. 全程只读，不做任何写操作；对存疑内容向用户确认后再动

## 失败模式

| 症状 | 处置 |
| --- | --- |
| 会话结束时多个任务混在一起说不清 | 按任务逐条对应拆开写；对应不上的问用户 |
| 未尽事项塞进已完成任务正文 | 必须拆独立任务，保持已完成任务的归档块干净 |
| 恢复时 active 有游离文件（不在月份目录） | 先按规范移入 `active/{YYYYMM}/` 再读 |
| 新会话仍说「找不到上下文」 | 检查归档文件是否已 git 提交、是否落在正确月份目录 |

## 可选加速（不构成依赖）

项目已安装 @fxri/toolkit 时，可用命令替代对应手工步骤，缺失不影响主流程：

- `toolkit tasks`：恢复模式查总览（替代人工翻目录）
- `toolkit tasks archive`：归档模式第 4 步自动化（含排他锁防并发；可 `--dry-run` 预演）
- `toolkit tasks check`：落盘后校验
- 任务目录非默认 `.tasks` 时加 `--dir <path>`
