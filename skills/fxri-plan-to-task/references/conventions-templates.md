# 规范载体文风与模板

> 本文件为 `conventions-spec.md` 的配套规范，承载载体的文风与模板层（T1–T6）。新建载体、归一存量载体文风，或按机械判定处置文风偏离时加载；结构层见 `conventions-spec.md` §1–§3。

多个仓库的载体在结构上早已一致，分歧集中在头注、用法说明骨架、引用写法、条文格式、规范词与标点这些原先未规定的层面；以下 T1–T6 为**唯一形态**，新载体照此起步、存量载体照此归一，偏离由 `toolkit conventions status` / `toolkit tasks check` 按可机械判定者软告警（只报不改，交人工确认）。

## T1 index 头注固定两行

`index.md` 首行形态标记之后、端清单之前，头注**恰为两行**，各一句 blockquote：

```markdown
<!-- toolkit-conventions: v3 -->
# 项目协作规范索引

> 本文件为规范载体唯一入口与唯一权威；规范全貌见下方索引，条文见各分册。
> 读面纪律：`history.md` / `retired.md` 属归档面，仅在审计 / 恢复时读，不在常规读面。
```

- 第 1 行说明载体定位（唯一入口 + 条文去向），第 2 行说明归档面读面纪律
- 头注只承载「读什么、去哪读」；检测面细则、维护步骤、指向 spec 等**不进头注**——它们是写作者须知、非每次建档必读，进了常驻面即违反 `conventions-spec.md` §1.1 元原则

## T2 用法说明固定骨架

`index.md`「用法说明」节固定三段，段名与次序为 载体形态 → 本项目约定（可选）→ 读写与维护；通用部分收敛为一句 + 指向本规范，不逐条复述规则正文：

```markdown
- **载体形态**：本项目采用「溯源索引式」（条文在外部规则层，本载体只索引）/「条文式」（条文在本载体分册）。
- **本项目约定**：（可选，如 `scope` 分类标签、分册命名等本仓特例；无则整段省略）
- **读写与维护**：读面与读写判定、写入归属、语义修订与退休流程一律见 `skills/<技能名>/references/conventions-spec.md`，本载体不另述。
```

- 「载体形态」取值即 `conventions-spec.md` §7 两种形态（可混用，需逐条说明时在括号内补述）
- 「读写与维护」指向 spec，不在此复述 §5 / §6 / §8 的规则正文

## T3 「单一事实源」列写法二分

索引表「单一事实源」列的写法按指向目标二分：

- **载体内分册**（条文就在本载体）→ 相对链接：`[common.md](./common.md)`、`[web.md](./web.md)`
- **载体外文件**（条文在项目规则层）→ 行内代码：`docs/ai-rules.md`、`AGENTS.md`、`skills/<技能名>/references/task-spec.md`
- 同格需补充说明时，链接 / 代码之后接短述（如 `skills/<技能名>/references/task-spec.md（口径随版本走）`）

理由：两类指向的可点击性不同——载体内相对链接点击即达；载体外路径跨仓后不可靠，故不作链接、只作行内代码指路。

## T4 分册条文模板

分册内每条条文固定为 小节标题 + 一句当前语义 + 四类子项，**子项次序固定为 要求 → 反例 → 理由 → 配套**：

```markdown
## C-<n>. {规则名}

{一句当前语义}。

- **要求**：{须做什么 / 不得做什么}。
- **反例**：{常见的错误做法}。
- **理由**：{为什么这样规定}。
- **配套**：{与索引 `C-<n>`、外部载体等的联动关系；无则省略本子项}。
```

- 子项名与次序固定；`配套` 无内容时整条省略
- 子项以 `- **{名}**：` 起头（全角冒号），内容用规范词（见 T5）
- **分册内不得写「确立来源」子项**：来源已由 `index.md` 索引行（活跃条目）与 `history.md` / `retired.md`（留痕与退休）承载，分册内重复即违反 `conventions-spec.md` §1.1 不变量 I4；`toolkit conventions status` / `toolkit tasks check` 对残留行软告警（跳过 fenced code block）

## T5 规范词分级

条文正文用统一强弱词，对标 RFC 2119 的 MUST / SHOULD / MAY：

| 词 | 强度 | 含义 |
| --- | --- | --- |
| `须` | 强制 | 必须遵守，违反即偏离 |
| `应` | 推荐 | 通常遵守，例外须有理由 |
| `可` | 可选 | 允许但不强制 |
| `不得` | 禁止 | 必须避免 |

同一强度不混用多种措辞——不用「必须」「应该」「不可以」「禁止」等近义词替代上表四词。

适用范围：条文正文、`index.md` 索引行与 `history.md`「修订内容」列。`history.md` 的规范词归一属措辞层（非语义变更），按 `conventions-spec.md` §3.2 措辞归一例外原地改写、不新增留痕行；引号内引述的外部文档原文不改。

## T6 标点与代码

- 标识符、文件路径、文件名、命令、配置项、规则 ID 一律用**行内代码**包裹（如 `C-17`、`index.md`、`toolkit conventions status`、`scope`）
- 中文引述、术语、举例名用全角直角引号「」，不用英文引号或书名号
- 中英文混排的空格处理随仓库既有排版习惯，不作硬性要求
