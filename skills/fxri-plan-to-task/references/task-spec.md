# 任务文件规范（通用版）

> 面向多人 + AI 协作，任何语言项目可直接使用，仅依赖文件读写能力。本文件为 SKILL.md 的配套规范；fxri 生态内实现级权威版本见 toolkit 仓库 SPEC.md。

## 1. 目录结构

```
.tasks/
├── active/                    # 进行中的任务
│   └── {YYYYMM}/              # 月份子目录，如 202609
│       └── {YYYYMMDD}-{用户名}-{任务简述}.md
└── archive/                   # 已终结任务归档
    └── {YYYYMM}/
        └── {YYYYMMDD}.md      # 按完成日期归组的归档文件
```

目录名 `.tasks` 为默认约定，项目可自定（如集中式任务库按项目分子目录），内部子结构不变。

## 2. active 任务文件

### 2.1 命名

`{YYYYMMDD}-{用户名}-{任务简述}.md`

- 年月日 = 任务创建日，`YYYYMMDD` 直接拼接（不加 `-`）
- 用户名 = git 用户名；任务简述 = 不含空格的短语

### 2.2 frontmatter

```yaml
---
owner: 唐启云          # 负责人（git 用户名）
status: 进行中         # 待办 / 进行中 / 阻塞 / 已完成 / 已放弃
created: 20260902     # 创建日 YYYYMMDD，须等于文件名日期前缀
updated: 20260902     # 最近更新日 YYYYMMDD
completed: ''         # 完成时间 YYYY-MM-DD HH:mm；仅终结态必填
depends_on: []        # 依赖的任务文件名（可带 .md），目标必须存在且不得成环
scope: app            # 影响范围
---
```

- `已完成` / `已放弃` 为终结态：进入时必须补 `completed`（真实收工时间）。⚠️ `completed` 必须当场执行命令取真实系统时间（Windows `Get-Date -Format "yyyy-MM-dd HH:mm"`，macOS/Linux `date "+%Y-%m-%d %H:%M"`），禁止凭记忆估算、取对话时间或做时区换算——工具对「完成时间晚于当前系统时间」会告警（时间源错误的典型症状）；完成时间恰为零点整（如 `2026-09-05 00:00`，只填日期被自动补零的典型特征）亦会告警，需人工核实
- 正文以 `# 任务标题` 开头；游离待办子项必须拆为独立任务文件

## 3. 归档文件

- 命名 `{YYYYMMDD}.md`，日期 = 任务完成时间日期；放入 `archive/{YYYYMM}/`
- 文件头：`# {YYYYMMDD} 归档` + 引言（如自动生成说明）
- 每个任务块：

```markdown
## {年月日}-{用户名}-{任务简述}

> 负责人：{owner}　状态：{status}　范围：{scope}　完成时间：{completed}

（任务正文）
```

- 块间以 `---` 分隔；**全文件按完成时间降序**（最新在前）
- 元数据行以 `> ` 开头、四字段齐全、以全角空格分隔

## 4. 手工归档步骤（有序）

1. 确认任务 status 为终结态且 `completed` 已填
2. 计算目标文件 `archive/{completed 的 YYYYMM}/{completed 的 YYYYMMDD}.md`
3. 读取已有归档文件（不存在则新建含文件头），把任务块加入
4. 全文件按 `completed` 降序重排，块间补 `---` 分隔
5. 写回归档文件
6. 删除 active 源文件；月份子目录与 `active/` 若已空则一并删除

## 5. 自查清单（校验）

- [ ] frontmatter 存在且七字段齐全
- [ ] status 为五枚举之一；终结态已填 completed
- [ ] completed 为 `YYYY-MM-DD HH:mm` 且日期真实存在，且不晚于当前系统时间（时间须来自当场命令输出，非估算）
- [ ] created 为 YYYYMMDD 且等于文件名日期前缀
- [ ] 文件名符合 `{YYYYMMDD}-{用户名}-{任务简述}.md`
- [ ] 任务文件放在 `active/{YYYYMM}/` 月份子目录，不直放 active 根目录
- [ ] `.tasks/` 下无游离于 active/ 之外的任务文件（直放 `.tasks` 根目录或漏建 active/ 层的 `{YYYYMM}/` 均不会被校验与归档）
- [ ] active 内无跨文件同名任务
- [ ] depends_on 目标存在且无循环依赖
- [ ] 正文无「待实施 / 待核对 / 待评估 / TODO」等游离标记与未勾选的 `- [ ]`
- [ ] 若按项目约定提交代码：确认 `.tasks/` 全部改动（本次归档文件 + active 剩余任务）已纳入 git 提交范围，与代码变更同批提交

## 6. 协作约定

- 任务区是多写者共享区：先查后写，同一需求共用一个任务文件
- 强制约束到归档为止：提交、发版、推送不是必经步骤，是否执行取决于用户的全局 / 个人 / 项目规则；若提交代码，先归档、后 git commit，任务记录与代码变更落在同一提交
