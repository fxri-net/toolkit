# 规范载体规范（conventions）

> 面向多人 + AI 协作，任何语言项目可直接使用，仅依赖文件读写能力。本文件为 SKILL.md 的配套规范，定义 `.tasks/conventions/` 的目录结构、索引与分册结构；
> 读写判定、修订、表格形态与自查见 `conventions-maintenance.md`，存量迁移见 `conventions-migration.md`，
> 文风与模板见 `conventions-templates.md`，任务文件规范见 `task-spec.md`。

## 1. 载体结构

> `.tasks/` 外层骨架（`active/` / `archive/` / `conventions/` 三目录与命名）以 `task-spec.md` §1 为真源；本节只展开 `conventions/` 内部结构。

```
.tasks/
├── active/                    # 进行中的任务
├── archive/                   # 已终结任务归档
└── conventions/               # 项目协作规范载体
    ├── index.md               # Z1 常驻：唯一入口与唯一权威；首行为形态标记
    ├── history.md             # Z3 归档：规范演进记录（只追加；写入与读取频次低）
    ├── retired.md             # Z3 归档：已退休条目（按需创建）
    ├── common.md              # Z2 按需：全端通用条文（按需创建）
    ├── <端名>.md              # Z2 按需：各端专有条文（按需创建）
    └── <分类标签>.md          # Z2 按需：按主题下沉的条文（按需创建）
```

- `index.md` 是唯一入口：端清单在此声明、每条活跃规范在此留一行指针（首列为稳定 ID），任务开始时只读它即可掌握规范全貌
- `history.md` 是修订留痕：规则语义变更在此追加；与 `index.md` 分离，避免「每次语义变更追加」的写与「每次建档常驻读」的读两类频次互相陪绑
- `retired.md` 是退休台账：条目作废即从索引迁出至此并冻结语义；与 `index.md` 分离，使废弃正文不再落入任何常规读面
- 分册**按需创建**，判据是「该归属下有无需独立承载的条文」，不设条数阈值——溯源索引式项目可能始终只有 `index.md`
- 目录与任务目录同在 `.tasks/` 根层，纯 Markdown 随 git 走；默认 `.tasks` 目录名可随任务区自定而变，内部结构不变
- 非任务文件：`toolkit tasks` 各子命令不读其内容，`check` 不因内容告警；仅在**载体形态异常**时给软告警（旧单文件残留、缺 `index.md`、标记与结构不一致）；
   **入口层现场异常**（壳标记与当前 toolkit 不一致、壳被 gitignore 覆盖）另见下段入口壳

### 1.1 三分区与不变量

载体按**读面**分三区，这是全规范的中心约束——凡变更须先问「这条进不进常驻读面」：

| 分区 | 文件 | 读面 | 承载 |
| --- | --- | --- | --- |
| Z1 常驻 | `index.md` | 每个任务开始时必读 | 端清单 + 活跃条目的索引行 |
| Z2 按需 | `common.md` / `<端名>.md` / `<主题>.md` | 索引命中其归属时读 | 活跃条文的正文 |
| Z3 归档 | `history.md` / `retired.md` | 仅审计 / 恢复时读 | 语义演进留痕、已退休条目 |

不变量（写入、修订与迁移时须恒真）：

- **I1 分区唯一**：同一条目不得同时出现在 Z1/Z2 与 Z3。
- **I2 常驻只含活跃**：Z1 索引不含任何已退休条目。
- **I3 分册只含活跃条文**：Z2 分册不含已退休条文的正文。
- **I4 条文只存一处**：同一条文正文只承载于一处（Z2 分册 或 外部单一事实源，二者其一）。
- **I5 ID 永不回收**：`C-<n>` 只追加、不重排、不复用；退休后其 ID 仍在 `retired.md` 占位。
- **I6 语义活性**：Z1「当前语义」是活的（随修订更新），Z3「退休时语义」是冻结的（退休后不再改）。
- **I7 读面无废文**：凡会被常规读取的位置（Z1 + Z2）不得含废弃正文。

> **元原则**：载体新增的任何字段、文件、表格，须能证明它**不进常驻读面**，方允许引入——常驻面每多一列、每多一行，都由全体任务平摊成本，而归档面只在小概率的审计 / 恢复场景被读到。

载体可另配套**入口壳（一阶触发面）**：在**已存在的**项目级技能目录下生成 `toolkit-conventions/SKILL.md`，目录名与 frontmatter `name` 同名（Agent Skills 标准要求）。

- **落点**：19 个内置候选目录见下表；多 agent 并存时**每处各写一份**、互不覆盖，一个都不存在时回落 `.agents/skills/`
- **内容**：壳只作入口、不承载条文，正文指回任务区 `conventions/index.md`
- **生成**：由 `toolkit init` 幂等生成，可安全删除、重跑补回；只在已有目录内落盘，不为未安装的 agent 凭空建目录，本包源仓库自身不生成
- **版本分流**：已存在的壳按标记版本判定——标记不旧于当前版本保持不变，落后或无标记就地更新为当前版本
- **标记版本**：壳标记独立于载体版本演进，当前为 `v2`；机制引入即从 `v2` 起，从未有过 `v1` 壳（区别于载体「无标记即 v1」）
- **标记位置**：壳首部为 frontmatter，故 `<!-- toolkit-conventions-entry: v2 -->` 退居其后、须全文件扫描（载体标记只看首行）
- **告警**：壳标记与当前 toolkit 不一致、或被 `.gitignore` 覆盖时，`toolkit conventions status` 与 `toolkit tasks check` 软告警
- **告警合并**：标记不一致可重跑 `toolkit init` 就地更新；同类告警在多落点并存时**合并为一条**并内联全部落点路径，不按壳逐条重复
- **体检范围**：只扫下表 19 个内置候选目录（`findEntryShells`）；用户手工把壳拷到未收录目录（如 `.bob/skills`）不参与体检
- **与技能薄壳的关系**：同一批候选目录还承载项目面技能薄壳，即在真源 `<仓库根>/.agents/skills/` 之外的其他已存在候选目录生成 `fxri-*` 薄壳
- 两类壳不同名并存、互不覆盖；入口壳由 `toolkit init` 生成，技能薄壳由 `toolkit skills install --scope project` 分发

规范触发面共三层，**任一层可用即可触达**：① 全局技能 `fxri-plan-to-task`（随包分发到各 agent 全局技能目录，
其工作流第 1 步即要求读 `conventions/index.md`）——**不依赖项目内任何文件、恒在兜底**；② 上述项目级入口壳（用户不主动发问也能被 agent 读到）；
③ `AGENTS.md` 指针块（仅在文件已存在时幂等追加，不存在不新建，跳过时提示仍有第 1 层可触达）。三层同时缺席的唯一情形：
装包后未跑 `toolkit skills install`（或 agent 不加载全局技能），
且项目既无 `AGENTS.md` 又未跑 `toolkit init`——`init` 检测到尚未安装全局技能时会在「下一步」中补一行 `toolkit skills install` 指引（已安装则不重复提示），
把这一情形收敛为「用户忽略了 `init` 的提示」。

## 2. index.md 结构

首行为形态标记，其后三节固定顺序：端清单 → 索引 → 用法说明（演进记录已移出，见 §3.2）。

### 2.0 首行标记

```markdown
<!-- toolkit-conventions: v3 -->
# 项目协作规范索引
```

- 标记置 `index.md` **首行**；仅**破坏性结构变更**递增 `v<n>`，措辞修正不递增；无标记即「引入机制前的形态」（v1）
- 标记不写包版本号——写包版本会让「发版即全员过时」
- 载体标记只看首行，正文示例里的同形注释不参与判定
- **不得显式书写 `v1` 标记**：v1 的定义即「无标记」，若把首行写成版本段为 `v1` 的形态标记会被判为未知版本（形态异常）；需要停用时用现行标记（`v2` / `v3`）表达，不写 `v1`

### 2.1 端清单（唯一权威）

```markdown
## 一、端清单

> 端名与任务 frontmatter 的 `scope` 取值共用同一套词表；保留字 `index` / `common` 不得作端名。

| 端名 | 说明 |
| --- | --- |
| web | 前端主站 |
| server | 后端服务 |
```

单端项目写一行或留空表并注明「本项目单端，规范全归 common」。

### 2.2 索引（首列稳定 ID）

```markdown
| ID | 规则 | 当前语义 | 归属 | 单一事实源 |
| --- | --- | --- | --- | --- |
| C-1 | 四级时间源 | 时间取证优先级：当场打点 > 聊天记录时间戳 > git 提交时间 > 系统时间兜底 | common | skills/<技能名>/references/task-spec.md（口径随版本走） |
```

- **列集合固定为五列**：`ID | 规则 | 当前语义 | 归属 | 单一事实源`，列名与次序均不得增减或调换——列集合即读接口，漂移会破坏机械读写；
   `toolkit tasks check` / `toolkit conventions status` 检出列集合偏离（列名 / 次序 / 列数不符）并软告警（只报不改，须人工确认后按本规范归一）
- **ID**：`C-<n>`（`C` 表 conventions），**去补零、不带端前缀、只追加不重排不回收**；插入或重排不漂移，废弃条目不回收其 ID（容量不是问题，去补零取的是可读性）
- **引用**：载体内部引用一律行内代码包裹（如 `` `C-17` ``），便于机械匹配；v1 遗留的裸「第 N 条」在升级时改写（见 `conventions-migration.md` §10.2）
- **归属**：取值必须对应一个实际承接处——`common`、端清单中的端名、或载体目录下存在的分类标签分册名，否则为悬空指针（需修正）
- **单一事实源**：条文正文去哪看。已指向项目现有规则层（AGENTS / 全局规则 / skills）时填指向；条文就在本载体分册内时填分册名（如 `common.md`）
- **不含「状态」「确立来源任务」两列**（区别于 v2）：Z1 只收录活跃条目，故「状态」恒为活跃、不必占列；「确立来源任务」属留痕信息、交 git 历史承载，退休条目则记于 `retired.md`

### 2.3 用法说明

写明本项目采用哪种形态、读写判定要点、以及规则层源头变更时的同步纪律。骨架与写法见 `conventions-templates.md`（T2）；通用部分收敛为一句并指向本规范，不逐条复述规则正文。

## 3. 分册与留痕文件

### 3.1 分册结构

```markdown
# 全端通用规范（common）

> 归属：common（所有端适用）。条文全文见本节，索引见 index.md。

## C-1. 四级时间源

（条文全文）
```

端分册同构，首部 `# {端名} 规范`、`> 归属：{端名}`；分类标签分册同构，首部 `# {标签} 规范`。小节标题用稳定 ID（`## C-<n>. {规则名}`），与 `index.md` 索引一致，便于互引。
条文正文的子项与次序见 `conventions-templates.md`（T4）；
分册内不写「确立来源」行——来源已由 `index.md` 索引列与 `history.md` 承载（见 `conventions-templates.md`）。

### 3.2 history.md 结构

演进记录独立成文件，**仅追加、不改旧行**：

```markdown
# 规范演进记录

> 元规则：规则语义变更时不得覆盖旧语义直接丢史——在「演进记录」追加一条（规则 ID → 修订内容 → 修订来源任务；修订内容新立条目直接写其语义、语义变更写「旧语义」→「新语义」），`index.md` 索引表只保留当前语义；规则层源头变更（`AGENTS.md` / `docs/rules/ai.md` / skills 条文）随该变更同批落盘。
> 表语义边界：本表只记**规范语义变更**；载体结构升级、入口壳生成 / 删除、条目退休均不入表（退休见 `retired.md`）。

| ID | 修订内容 | 修订来源任务 |
| --- | --- | --- |
```

- **首列记为行内代码包裹的裸 ID `C-<n>`，不写规则名**（规范名以 `index.md` 索引表为准；规则改名等沿革信息作前置括注记入「修订内容」列，如「（原名「X」）」）。此为硬性要求：
   `toolkit tasks check` 与 `toolkit conventions status` 检出非 ID 首列并软告警（只报不改——历史行只追加不改旧行的元规则下，补齐须人工确认）
- **「修订内容」列只记该条自身语义**：新立条目直接写其语义；语义变更写「旧语义」→「新语义」（箭头两侧文本加全角引号）。两条禁令——不得写自指套话（如「（本次起入表）」「新立条目：」，表内每行本就是入表记录、
   自指零信息量）；不得复述 `index.md` 索引列信息（如「；条文全文落 `common.md`」与索引「单一事实源」列重复，违反 §1.1 不变量 I4）。规范名沿革作前置括注（如「（原名「增量判别」）」）。
   **措辞归一例外**：措辞层归一（表格形态归一见 §9，规范词归一见 `conventions-templates.md` T5）属非语义变更，可原地改写旧行、不入 `history.md` 留痕行。
   `toolkit tasks check` / `toolkit conventions status` 检出禁用语料并软告警（只报不改，改写须人工确认）
- **表头固定**：须恰为 `ID | 修订内容 | 修订来源任务` 三列，逐格一致（含列名与次序）；`toolkit tasks check` / `toolkit conventions status` 检出表头偏离并软告警
- **表语义边界写死**：载体结构升级（如 v1 / v2 → v3）、入口壳生成 / 删除、条目退休都不入表——表只记**规范语义**变更

### 3.3 retired.md 结构

退休台账独立成文件，**只增不改**（退休时语义一经冻结不再改动）：

```markdown
# 规范退休记录

> 元规则：条目作废即从 `index.md` 迁出至本表并冻结退休时语义；编号不回收（见 §8）。本表属 Z3 归档、不进常规读面。

| ID | 规则 | 退休时语义（冻结） | 归属 | 后继 | 退休来源任务 | 条文去向 |
| --- | --- | --- | --- | --- | --- | --- |
| C-7 | 旧示例规则 | （退休当时的语义原文） | web | `C-41` | 20261016-某任务 | 已删分册小节 `web.md` |
```

- **表头固定**：须恰为 `ID | 规则 | 退休时语义（冻结） | 归属 | 后继 | 退休来源任务 | 条文去向` 七列，逐格一致（含列名与次序）；
   `toolkit tasks check` / `toolkit conventions status` 检出表头偏离并软告警
- **退休时语义（冻结）**：退休当时的语义原文，不再随修订变动（区别于 Z1 的活语义）
- **后继**：替代它的新条目 ID；无则填 `—`
- **退休来源任务**：执行这次退休的任务
- **条文去向**：三层清理的落点记录（删除了哪处分册小节、外部单一事实源如何处理）
