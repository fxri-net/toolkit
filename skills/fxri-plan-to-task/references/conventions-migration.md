# 规范载体存量迁移

> 本文件为 `conventions-spec.md` 的配套规范，承载载体存量的形态迁移（v0 → v1、v1 → v2、v2 → v3）。仅在迁移存量载体或排查形态异常时加载；日常结构、读写判定与自查见 `conventions-spec.md`。

## 10.1 旧单文件 → 目录形态（v0 → v1）

触发：`toolkit tasks check` 报旧 `conventions.md` 存在；或用户直接要求迁移。

**三段式**（可中断，中途停下不丢内容）：

1. **机器搬骨架**：建 `conventions/`，旧文件**整体**搬为 `index.md`（原文一字不丢），删除旧文件——此刻 `index.md` 是原文快照，功能上与旧文件等价
2. **AI 提归属建议**：读原有条目，逐条给出「`common` / 某端」建议与理由（旧文件无端信息，语义分流无法机械完成），形成待确认清单
3. **用户逐条确认**：确认后写索引行 + 把条文全文拆入对应分册；**未确认的条目保持原样留在 `index.md`**，不强推

补充要求：

- 迁移与内容重排分开做：先完成形态迁移（结构到位），再谈条目归属调整，避免一次变更混合两种风险
- 端清单在迁移时同步建立：从项目已有 `scope` 取值与实际子项目构成归纳，经用户确认写入端清单节
- 旧文件已不存在时不重复迁移

## 10.2 v1 → v2 结构升级

触发：`toolkit conventions status` 报「需升级」；`toolkit tasks check` 报形态告警（标为 v2 缺 `history.md` 或索引表首列非 `ID`；有 `history.md` 但首列仍是 `#`）；或用户直接要求升级。

优先用 `toolkit conventions upgrade`（纯机械，可 `--dry-run` 预演），动作序：

1. **发 ID**：按现有条序 `1..n` 发 `C-1..C-n`，索引表首列由 `#` 改 `ID`
2. **切 `history.md`**：原 `index.md`「演进记录」节整表平移为独立 `history.md`（表头首格归一为 `ID`），`index.md` 撤该节；标题归一 `# 项目协作规范索引`，首行补形态标记（版本段写 `v2`）
3. **改内部引用**：裸「第 N 条」（仅 N ≤ 索引表最大序号者）改写为 `` `C-<n>` ``；带外部文档限定词前缀的引用（如 `AGENTS.md` 质量门第 5 条、`SPEC.md` 协作模型第 3 条、`task-spec.md` 第 6 节）一律不动；改写清单进报告
4. **分册小节归一**：分册小节标题改 `## C-<n>. {规则名}`

补充要求：

- **ID 映射不落盘**：映射由 `upgrade` 输出（实跑与 `--dry-run` 均打印）；真值可由 git 历史复现（迁移提交的父提交即 v1 原件），故不落盘代价近零
- **先判后写**：遇形态异常（标记与结构不一致）拒绝执行并给非 0 退出码，**不写任何文件**，提示人工确认
- `upgrade` 幂等：已是 v2（或更高）时原样返回，不做二次改写
- **手工迁 v2 与工具升级的落点不同**：手工迁移按本节在首行写版本段为 `v2` 的形态标记、停在 v2；用 `toolkit conventions upgrade` 升级则不落 v2——工具从 v1 输入链式直达 v3（`v1 → v2 → v3`，见 §10.3），仅手工路径停在 v2
- 手动迁移时按同一动作序执行

## 10.3 v2 → v3 结构升级

触发：`toolkit conventions status` 报「需升级」；`toolkit tasks check` 报形态告警（标为 v3 缺 `history.md` 或索引表首列非 `ID`；有 `history.md` 但首列仍是 `#`）；或用户直接要求升级。

优先用 `toolkit conventions upgrade`（纯机械，可 `--dry-run` 预演；v1 输入将链式升级 v1 → v2 → v3），动作序：

1. **索引表删两列**：删「状态」「确立来源任务」两列
2. **`history.md` 表头归一**：v2 存量 `history.md` 沿用「规则 ID / 名称」旧表头，首格归一为稳定 ID `ID`（与索引表首列同归一）
3. **退休条目迁出**：把原状态为 `已废弃` 的行迁入 `retired.md`（首部补 `# 规范退休记录`、元规则与 7 列表头），并从 Z1 索引表删除；同步删除 Z2 分册内对应小节（三层清理的索引 + 分册两层）
4. **`retired.md` 按需建**：无退休条目则不创建该文件
5. **来源 / ID 补录报告**：`history.md` 中 ID 列仍用规则名者、来源列含多任务者，输出人工复核报告——**不做全自动改写**（历史行只追加不改旧的元规则下，改写须人工确认）
6. **用法说明 / 写入纪律复核**：`index.md` 表外的自由文本（用法说明、写入纪律）若仍残留 v2 措辞（如「填『确立来源任务』」「把『状态』改为『已废弃』」），输出人工复核报告——升级只机械归一索引表列结构，不改写描述该表的自由文本
7. **标记升 v3**：`index.md` 首行改为 `<!-- toolkit-conventions: v3 -->`

补充要求：

- **先判后写**：遇形态异常（标记与结构不一致）拒绝执行并给非 0 退出码，**不写任何文件**，提示人工确认
- **dry-run 迁移报告**：`--dry-run` 打印将删的列、将迁出的条目与将删的分册小节、待人工复核项，供人工确认后再实跑
- `upgrade` 幂等：已是 v3 时原样返回，不做二次改写
- 手动迁移时按同一动作序执行
