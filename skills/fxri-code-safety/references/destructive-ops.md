# 破坏性操作：允许范围、预览与回收站

> 由 `../SKILL.md` 按需加载。命令参数以 `toolkit <命令> --help` 为准，本文件只写判断与边界。

## 一、允许范围

| 侧 | 允许根 | 说明 |
| --- | --- | --- |
| 项目 | 仓库根及其子目录 | 以 git 根或 `.tasks` 根判定，不以当前目录猜 |
| 全局 | 家目录下的本工具目录与已登记技能目录 | `~/.agents/skills`、各 agent 全局技能目录、`~/.toolkit` |
| 备份 | 项目与全局 `.toolkit/backup` | 只清带 `manifest.json` 的已知目录 |
| 临时 | 系统临时目录下自建目录 | 一次性产物，可安全删除 |

受保护目标本身不得作为删除对象：磁盘根、家目录、`AppData` / `LocalAppData` / `ProgramData`、`Program Files`、`Windows`。
其子目录仍按所属允许根判断——「在允许根内」不等于「可以整目录清空」。

## 二、预览与确认

1. 能列目标的命令先列：`toolkit trash list`、`skill status`、`upgrade --dry-run`。
2. 支持 `--dry-run` 的写命令一律先预览；没有预览能力时，先在方案里写清目标与数量。
3. 非交互环境执行清理需显式确认参数（如 `--yes`），不得默认替用户确认。
4. 部分失败时保留未处理项，并在 stderr 报告跳过原因；下一次重试不重复已成功项。

## 三、符号链接与 junction

- 删除链接只摘链，不跟随目标；避免把真实目标一起搬走。
- 恢复链接只恢复链接本身；悬空链接按跳过回报，不猜测目标。
- 迁移与回收站都按同一口径处理，不复制链接目标内容。

## 四、项目内回收站

用户可见删除默认进回收站，由用户决定恢复或彻底清理；缓存、锁、临时与派生数据仍永久删除。

| 命令 | 用途 |
| --- | --- |
| `toolkit trash list [--scope project\|global\|all] [--command <name>] [--older-than <days>]` | 查看条目与来源 |
| `toolkit trash restore [id] [--to <dir>] [--overwrite] [--dry-run]` | 恢复到原路径或指定目录 |
| `toolkit trash prune --keep <n>` / `--older-than <days>` / `--all` | 按策略彻底清理 |
| `toolkit trash stats` | 条数、占用与来源分布 |

- `--scope` 缺省：查询与恢复为 `all`；`prune` 在项目内只清项目、`~` 下只清全局。
- `--keep` 按每个回收站根分别保留，不跨面挤占。
- 用户可见命令加 `--no-trash` 才永久删除；批量永久删除前须再次确认。
- 回收站不是备份：只防误删，不防磁盘损坏、外部清理工具与整盘格式化。

## 五、本机清理工具

- 只清清理工具自报可清理项，不整目录删除 `AppData` 下的开发工具目录（包管理器缓存、版本管理器、编辑器数据）。
- 清理前列白名单：项目根、`~/.agents/skills`、`~/.toolkit`、包管理器全局目录、版本管理器安装目录。
- 清理前先备份配置与版本锁文件；清理后按 `incident-recovery.md` 的检查项验证工具链。
- 自动清理计划（定时任务 / 空间不足触发）须先停用或改为白名单模式，再执行手动清理。
