# 误删恢复：止损、取证与重建

> 由 `../SKILL.md` 按需加载。目标是先保住还能恢复的数据，再重建开发环境；顺序颠倒会覆盖可恢复证据。

## 一、先止损

1. 停掉正在执行的清理脚本、定时清理任务与空间自动释放计划。
2. 停止向受影响磁盘继续写入：暂停构建、安装、同步与大文件下载。
3. 若删除仍在进行，先终止进程再处理残留；不要边恢复边清理。
4. 记录当前时间、执行过的命令与清理工具名称，供后续取证。

## 二、取证

| 证据 | 位置 / 方式 |
| --- | --- |
| 本工具回收站 | `toolkit trash list --scope all`，`~/.toolkit/trash/<id>/manifest.json` |
| 项目内回收站 | `<仓库根>/.toolkit/trash/<id>/manifest.json` |
| 清理工具日志 | 工具自身的日志 / 历史记录 / 隔离区 |
| 版本控制 | `git status`、`git reflog`、未推送提交与 stash |
| 系统快照 | 文件历史、时间机器、卷影副本等宿主快照 |

先确认哪些内容在回收站、快照或版本控制里仍可恢复，再决定重建；无法恢复的部分如实告知用户，不假装已恢复。

## 三、恢复顺序

1. **系统与 shell**：确认 shell 配置、PATH 与终端可用。
2. **版本管理器与运行时**：恢复 `fnm` / `nvm` 等安装目录，装回基线 Node 版本（以项目 `.node-version` 为准）。
3. **包管理器**：恢复 pnpm / npm / corepack 的全局目录与配置。
4. **全局工具**：按原版本重装全局 CLI；本工具用项目内或全局安装均可，重装后跑一次 `--version` 确认。
5. **技能与规则**：`toolkit skill install` 恢复技能产物，`toolkit rule compose` 恢复全局规则快照。
6. **项目依赖**：按锁文件安装，先 `pnpm install --frozen-lockfile`，失败再排查配置。
7. **本地配置**：恢复 `.toolkitrc.local.json`、编辑器与终端配置；个人偏好按需补回。

每步完成后跑对应自检（如 `toolkit status`、`toolkit skill status`、项目构建），通过后再进入下一步。

## 四、禁止项

- 不在取证前重装同目录，避免覆盖残留文件。
- 不从陌生脚本或非官方镜像恢复工具链。
- 不用「全盘清理」验证恢复是否成功。
- 不把未恢复的部分写成「已修复」；恢复清单逐项勾选并留痕。

## 五、收尾检查

- [ ] 清理计划与定时任务已停用或改为白名单模式
- [ ] 运行时、包管理器、全局工具版本与项目基线一致
- [ ] 技能、规则、项目依赖已按锁文件恢复
- [ ] 回收站与快照中仍可恢复的条目已处理完毕
- [ ] 恢复过程中发现的新风险已回写方案或任务档
