# 文档站写作规范

> 本技能版本 0.1.0（随 @fxri/toolkit 同批分发）。被问版本时即报此值（不读磁盘、不跑 CLI）；与 `toolkit skills status` 的磁盘值不一致即说明会话上下文已过期，开新会话即可。

## 何时使用

- 新建文档站，需要确定顶栏、侧栏与分类骨架。
- 调整现有文档站的分类、页面标题、侧栏命名或页面归属。
- 统一站内索引与链接文案，或评审导航与标题是否一致、能否长期扩展。

不适用：页面正文文风、配图与视觉设计、部署流水线。

## 核心口径

- **显示名**：页面面向读者的名字；**标识**：命令名、配置键等机器可识别的名字。
- **显示单位**：CJK 字符每个 1 单位；以空格分词的语言每个词 1 单位；数字、缩写与专有名词（CLI、API、SQL）各按 1 单位。
  长度约束一律按显示单位计，不写死某种语言。
- 条文只写「显示名 / 标识 / 项目主语言」，具体用词与译名由各站按自身语言确定。

## 页面标题与引用

| 位置 | 写法 |
| --- | --- |
| 页面 H1 | `显示名（标识）`，标识取命令名或配置键；多个标识用 ` / ` 分隔 |
| frontmatter `title` | 已声明即须与 H1 逐字一致；未声明不强制补（VitePress 以 H1 作标题） |
| 索引 / 目录表 | 目标页完整标题（含标识） |
| 行内引用与链接文案 | 显示名，可带分组前缀（如「CLI 参考 · 任务管理」），不带标识 |
| 侧栏 | 可用短别名（如「任务区」指「任务管理」）：须指向同一对象，且在同一导航分组内唯一；跨组可重名，不要求与 H1 逐字一致 |

- 专名开头的标题（`API 总览`、`SQL 参考`）属合理用法，不按「标识前置」处理。
- 显示名在同一导航分组内不得指向两个不同页面；冲突时改其中一个显示名，不改标识。
- 标题改名会改变页内锚点：不逐页保留旧 H1 锚点，页面 URL 不变即可；确需兼容深链时手写 `<a id="旧锚点"></a>`。

## 分类骨架

按用户意图分组，不按技术分层分组；按仓库实际裁剪，不硬凑。

| 分组 | 定位 | 收纳内容 |
| --- | --- | --- |
| 开始 | 第一次跑通 | 首页、快速开始 |
| 指南 | 场景化怎么做 | 操作手册、完整攻略、使用手册、开发指南、接入 |
| 参考 | 查询型内容 | CLI、API、配置 |
| 原理 | 为什么这样设计 | 架构、内核 |
| 升级 | 版本迁移 | 升级总览、API 对照、检查清单 |
| 开发 | 构建发布与协作 | 构建产物、分发接入、发版流程 |
| 帮助 | 求助与记录 | 常见问题、更新日志、贡献指南 |

分组名取 2–4 显示单位，禁止「内核与配置」这类「与」字复合名；纯页面条目豁免长度限制，一级项与任意层级分组名不豁免。
同一概念全站统一用词，并在项目内固定一组译名（如快速开始、操作手册、常见问题、更新日志），不混用同义词与英文缩写。

## 顶栏与扩展

- 一级项不超过 5 个：首项固定为快速开始直链，末项固定为帮助下拉，中间顺序为指南 → 参考 → 原理 / 升级 / 开发 / 领域组。
- 单个页面直接作一级直链，不包成单项下拉；下拉项 2–8 个，超出时按二级分组收纳。
- 更新日志、常见问题、贡献指南不单独占一级入口，统一由帮助承载。
- 新增页面优先并入现有分组；确需新增一级分类时须满足长度上限，并复核顶栏是否仍不超过 5 项。
- 侧栏二级分组仅在同类条目超过 8 个时启用；升级文档按 `upgrade-<major>/` 独立目录扩展。
- 单页超过 300 行或同时承载两类读者时拆分；`changelog.md` 等生成镜像不拆。
- 每站提供 `404.md`（首页、常见问题、更新日志入口），旧 URL 不重定向但可继续导航；404 页排除站点地图与站内搜索索引。

## 校验方式

- 导航与侧栏以 `docs/site-nav.json` 为单一真源，站点配置只做引用展开；检查器读数据，不解析站点配置。
- 机器可检的阈值交给工具：`toolkit docs nav check`（顶栏项数与首末项、帮助必备项、分组名显示单位长度、404 的 `search: false`、
  单页体量告警）与 `toolkit docs dist check`（构建产物中站点地图与搜索索引排除 404）。
- 工具未安装时相关检查跳过并提示，不阻断与该工具无关的仓库；命令与本技能条款不一致时以条款为准，同时修命令。
- 单页超过 300 行（排除 `changelog.md`）输出 warn，只提示不阻断；更严格的正文可读性门禁属站点自选。
- 标题与索引的一致性由站点自检脚本守护：已声明 `title` 的页面校验 title=H1，索引链接文案校验等于目标页标题。

## 落地步骤

1. 先定分组与命名，再改 `nav` / `sidebar` 配置。
2. 改页面标题：先改 H1，已声明 `title` 的同步改；再改索引与行内引用。
3. 修复站内链接与锚点（标题改名会改变页内锚点）。
4. 把 `toolkit docs nav check` 与 `docs dist check` 纳入既有 verify 门禁，工具缺失时跳过。
5. 记录 patch 变更集，按仓库发版链路发布。

## 常见错误

- 把常见问题、更新日志各挂一个顶栏入口，导致一级项膨胀。
- 用「接入与运维」「适配与答疑」这类复合长名，既超长度又混装两类内容。
- 标题写成「标识（显示名）」或只留标识，索引与正文引用又各用一套写法。
- 导航指向锚点（如 `/cli#配置选项`）而不是独立页面，搜索与面包屑不可用。
- 校验写成页面白名单，新增页面就失效。
