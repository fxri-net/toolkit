# 方案规范对照

> 由 `../SKILL.md` 按需加载。目标：让「方案是否符合本项目规范」成为建档前的固定步骤，而不是靠用户提醒。

## 何时使用

- 方案已定稿、准备建档或请求执行授权之前。
- 方案涉及新命令、新配置、新技能、新文档页、删除 / 迁移 / 覆盖等可能触达规范的动作。
- 复核已落档任务时，检查原方案是否做过规范对照。

## 规范来源优先级

按顺序找，命中即用，不要求全读：

1. 项目规范载体（如 `.tasks/conventions/index.md` 或等价索引）。
2. 项目根规则文件：`AGENTS.md`、`CLAUDE.md`、`README.md`、`docs/rules/` 等。
3. 配置、schema 与对外契约。
4. 既有代码、测试与目录约定。
5. 用户在当前对话中明确提出的约束。

没有规范载体时，从第 2 步开始；仍无可用来源时，在任务档写明「未发现项目规范」，不要编造。

## 对照步骤

1. **判命中**：逐条看来源里的适用面，只取与本次方案相关的条款。
2. **写结论**：命中的条款与方案如何满足，写入任务档的影响范围或验证方式。
3. **写无命中**：没有命中时写「规范对照：无命中（理由）」，不空泛带过。
4. **处理新事物**：项目已有登记机制（事实表、索引、配置键清单等）时先登记；没有登记机制时，
   写明新增假设或规则，并询问用户是否沉淀。不得把新概念硬套进旧条目。

## 输出写法

可简写为：

- `- 规范对照：<来源> <ID / 条款> → <结论>`
- `- 规范对照：无命中（理由：本次仅调整内部实现，未触达对外契约）`

## 反例

- 只读了规范索引，没有把命中项与结论写进任务档。
- 方案出现新概念，却强行归入一条不相关的旧规范。
- 以「没有找到对应条目」为由跳过，不说明理由。
- 把项目专属规则写成通用规则，或把通用规则硬塞进某个项目。
