# 开工闸门：闸门态与授权态（细节）

> 由 `../SKILL.md`「开工闸门」按需加载。主文件只留判定要点，完整词表、护栏与恢复流程在此。
> 两套状态是不同维度：闸门态回答「本轮允许做哪类动作」，授权态回答「方案级授权凭证是否在手、是否暂停」。
> 另有一套磁盘上的「任务状态」（待办 / 进行中 / 阻塞 / 搁置 / 已完成 / 已放弃），三者互不推导——
> 任务档写 `status: 进行中` 不代表授权态是 A（跨会话即 U）。
>
> **维护纪律**：新增或压缩关键词族时，先更新末尾「关键词族落点表」再动正文；表内落点为空即视为未承载，不得当作已覆盖。

## 一、闸门态

| 闸门态 | 允许 | 典型输入 |
| --- | --- | --- |
| 讨论态（含评估） | 分析需求、回答问题、输出方案与建议；允许落档（仅维护 `.tasks/active`），不改代码、文档、技能等其它仓库文件、不跑实现命令、不提交 | 需求清单、意见、问题、继续评估、连续落档 |
| 方案态 | 输出结构化方案并标注「等你说开始」；仍不改代码 | 方案成型、等用户拍板 |
| 定稿态 | 方案冻结、可开工但仍不写代码；「方案可以 / 定稿 / 没问题 / 落档」停在这里 | 方案定稿、等开工授权 |
| 执行态 | 按当批计划写代码 / 文档 / 技能、跑实现命令、归档、验收、提交 | 授权判据齐备（执行指向 + 范围唯一 + 已定稿） |

## 二、授权态与转移

同一句在不同授权态含义不同（典型是「继续」：未开工=继续评估、已暂停=恢复执行），故按状态转移判定而非词面判定。

| 授权态 | 含义 | 转移 |
| --- | --- | --- |
| U 无授权 | 未给方案级授权，可处于讨论 / 方案 / 定稿任一闸门态 | 授权判据齐备 → A |
| A 执行中 | 已获当批授权，正在推进（含批次待续） | 暂停词 / 用户提问 / 岔开话题 → P；取消词或方案变更 → U |
| P 已暂停 | 授权挂起未撤销 | 恢复词 → A（回显 → 复核 → 继续）；取消词 → U |

状态不确定一律按 U；状态靠任务档的 `status: 进行中` 与正文进度锚点重建，不靠记忆。

## 三、状态相对词表

| 词族 | 代表词 | U | A | P |
| --- | --- | --- | --- | --- |
| 开工 | 开始、开工、动手、开干、执行、落地、按计划做、照这个做，以及目标型动词「处理 / 处理掉 / 搞定 / 修掉 / 直接改」与显式授权语「授权 / 同意 / 照做 / 交给你」（示例非闭集） | 转 A（需范围唯一 + 定稿） | 幂等，回显范围 | 转 A |
| 恢复 | 继续、接着、往下、恢复、来吧 | 讨论态，继续评估 | 推进当前步骤；批次内转下一任务 | 恢复执行（回显 + 复核） |
| 暂停 | 停、停一下、先停、暂停、等一下、先到这、收工 | 不适用 | 转 P，写进度锚点 | 保持 P |
| 取消 | 取消、算了、不做了、停掉、别做了、放弃 | 维持 U | 转 U | 转 U |
| 撤销动作 | 回退、复原、撤回刚才的改动 | 对象级授权 | 执行回退，状态不变 | 执行回退，状态不变 |
| 限制 | 先别、不要、别提交、只改 X | 维持 U | 叠加约束，粘性到本批次结束 | 叠加约束 |
| 委托与裁量 | 你看着办、随你、都行、按你的建议来 | 一句确认：先回显「我打算做 X」等点头 | 不改变状态，按当前批次继续 | 不改变状态 |
| 状态词 | 方案可以、定稿、没问题、OK、好、行 | 最多转定稿 | 不改变状态 | 不改变状态 |
| 不可逆 | 发版、推送、发布、删远端、全局安装 | 逐次授权 | 逐次授权 | 逐次授权 |

## 四、护栏

- **动词搭配**：「开始 / 继续 + 评估、讨论、看、想、分析、复核、检查、对比」属讨论态；「+ 做、改、写、实现、执行、落地」才是执行
- **「继续」双重歧义**：会话内且有 active 上下文 → 恢复执行 / 推进下一步；新会话、无上下文或明确带「上次 / 做到哪」→
  按 `fxri-plan-recap` 恢复现场，只读
- **否定优先**：先别 / 不要 / 不用 / 别提交 覆盖同句开工词
- **疑问、引述、假设、元讨论不动作**：现在开始吗、他说开始、如果开始、开始这个词太宽
- **显式覆盖**：「别评估了，直接做」以最后的显式动作意图为准
- **条件与定时**：条件满足后先回显再执行；定时不自动触发
- **反问例外**：AI 上一轮明确问「是否开始」时，用户答「可以 / 好 / 开始」构成授权
- **反问后的含糊**：反问之后仍回「嗯 / 行吧 / 随便 / 你定」→ 视为未授权，回方案态并明确说「那我先不动，要开始时告诉我」；
  不重复追问、不自行开工
- **微操作边界**：有明确单点对象（把 X 改成 Y、删掉这段、跑一下某测试）→ 对象级执行，范围止于指明对象；
  无对象或指代方案清单（把这些都改一下、统一掉）→ 回方案态
- **委托的两种粒度**：委托当前这一步（「这个你看着办」且对象明确）→ 对象级执行；
  委托整个方案（「剩下的你看着办」）→ 回方案态，先列将做什么再确认，不得整批直接跑
- **授权判据（示例非闭集）**：执行指向明确（开工词、目标型动词「处理 / 搞定 / 修掉 / 直接改」或显式授权语「授权 / 同意 / 照做 / 交给你」）
  + 范围唯一（指向已定稿方案 / 计划表 / 单点对象）+ 无只读诉求与否定词 → 执行；由目标型动词或授权语触发时先一句话回显「按 X 执行」再动手
- **三类不构成授权（硬阻断）**：① 同句只读诉求（列计划表 / 列清单 / 先看看 / 评估）且无执行段；② 方案未定稿或含待定项；
  ③ 范围不唯一（多可选路径 / 指代不清）——命中任一即回只读或方案态，执行指向再明确也不放行
- **只读诉求优先**：同句既含只读诉求又含执行指向时，本轮只交付只读产物；展示型计划表输出即本轮终点，不得同轮建档、改文件、提交；
  同句含执行段（列计划表并开工、出表后直接做）时按执行段走，先表后执行
- **反问只问一次**：语义明显指向开工但示例词表未覆盖（开整 / 上手 / 干起来 / 走起）时反问一句「要我开始吗」，不静默也不自行开工；
  反问后用户以同一短语重复、范围与反问时一致、期间无否定 / 新对象 / 新歧义 → 视为确认直接执行，否则回方案态再问，不连续两次拒绝

## 五、恢复与失效

- **恢复三联**：回显范围（恢复哪项、暂停在哪）→ 复核现场（`git status`、任务档进度锚点、期间方案是否变更）→ 再动手；方案变过则回定稿
- **暂停时写进度锚点**：属暂停流程内的动作，随暂停一并获准，范围只限任务档正文锚点与 `updated`
- **失效条件**：会话结束、上下文重置、方案变更、范围扩张、取消词、工作区被外部改动
- **批次授权不跨会话**：新会话一律回 U，须重新给开工词；不把「批次授权」写进任务档正文
- **不可逆动作**：任何授权态都逐次授权，不随「继续」继承
- **状态自证**：动作前用一句话自证授权态（U 无授权 / A 执行中 / P 暂停），作为给用户的确认信号；说错即用户可立即纠正。
  仅在状态切换、授权措辞含糊或代词式指令时出现，不每轮重复
