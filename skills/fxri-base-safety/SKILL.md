# 破坏性操作安全

> 本技能版本 0.1.1（随 @fxri/toolkit 同批分发）。被问版本时即报此值（不读磁盘、不跑 CLI）；与 `toolkit skill status` 的磁盘值不一致即说明会话上下文已过期，开新会话即可。

## 何时使用

- 讨论、方案或评审阶段出现删除、清理、覆盖、迁移、卸载、批量改写、回收站等动作。
- 即将执行上述动作，或在代码里实现删除 / 清理逻辑。
- 已经发生误删，需要止损、取证与恢复。
- 本技能覆盖「动作会造成什么后果、授权前是否讲清、执行边界与恢复路径」；普通只读查询、无删除风险的代码修改、发版授权、提交信息与文本编码不在范围内。

## 读取地图

| 你在做什么 | 必读 |
| --- | --- |
| 方案 / 评审要披露影响 | 本文件「方案阶段披露」+ `references/destructive-ops.md` |
| 执行删除、清理、迁移 | 本文件「执行前检查」+ `references/destructive-ops.md` |
| 已经误删，要止损与恢复 | `references/incident-recovery.md` |

## 方案阶段披露（请求授权之前）

涉及删除 / 清理 / 覆盖 / 迁移 / 卸载 / 批量改写时，方案的影响范围必须写明四项，缺一不得请求执行授权：

- **影响对象**：删什么、覆盖什么、涉及项目面还是全局面、大致数量。
- **不可恢复部分**：永久删除、覆盖后无法回退、远端或已发布内容不可撤销。
- **回滚方式**：回收站、备份、git 或「无」；回收站只防误删，不防磁盘损坏与外部清理。
- **需用户确认项**：范围取舍、保留条数、是否永久删除、是否跨面执行。

披露后等用户确认再动手；用户确认的是方案，不等于后续每个不可逆动作都已获授权。
评审计划时发现缺少这四项，标「需要确认」，不得直接放行。

## 删除分层

| 层 | 例子 | 默认处置 |
| --- | --- | --- |
| 缓存 / 锁 / 临时 / 派生 | 缓存目录、锁文件、构建产物 | 永久删除 |
| 用户可见产物 | 技能产物、薄壳、状态账、迁移备份 | 项目内回收站；显式永久删除才跳过 |
| 外部 / 系统目录 | 家目录、AppData、Windows、Program Files | 拒绝删除，交人工确认 |

分层按路径根与归属账判定，不按名字猜；符号链接与 junction 只摘链，不搬目标内容。

## 执行前检查

1. 目标必须位于允许根内：项目根、临时目录、`.toolkit/backup`、已登记技能目录；受保护目录本身一律拒绝。
2. 先列目标清单；命令支持 `--dry-run` 时先预览，批量删除前报数量。
3. 优先用 `toolkit` 命令（`trash` / `skill uninstall` / `upgrade --prune-backups`）；
   项目侧递归删除统一走安全删除封装，不直接 `rm -rf` 或 `Remove-Item -Recurse` 清外部目录。
4. 无法删除、降级为保留或部分失败时，在 stderr 说明原因与下一步，不静默吞掉。
5. 需要跨多个根执行时逐个根确认，不把范围扩到未确认的目录。

## 误删恢复

先止损，再取证，最后重建：停掉清理任务与自动计划 → 查 `toolkit trash list`、清理工具日志与快照 → 按 `references/incident-recovery.md` 的顺序恢复。
取证完成前不要继续写入或重装，避免覆盖仍可恢复的数据。
