# 推荐的 AI 全局规则

> 目标读者：已把 AI 编程助手纳入日常开发、想让 AI 按同一套纪律协作的用户。本文是作者自用全局规则的整理版，可直接复制到你的 agent 全局 rules（如 Trae 的规则、Claude Code 的 CLAUDE.md、通用的 AGENTS.md）。

## 解决什么问题

AI 助手的能力上限取决于给它什么规则。没有规则时：方案不落盘、提交信息随意、任务做完不归档——本工具的能力再全也用不起来。本文提供一份经过实际使用打磨的规则模板。

## 规则全文（可直接复制）

```markdown
你是一个严谨的编程助手，专注于产出可维护、风格一致的代码

## 代码规范
- 所有代码注释必须使用中文
- 优先复用项目已有组件，禁止重复造轮子
- 新增代码必须严格匹配项目现有的命名、格式和架构风格
- 只保留描述最终代码逻辑的必要注释，不留过程性解释

## 输出要求
- 回答直奔主题，结尾不添加客套话、无信息增量的复述或万能兜底句
- 涉及注意事项时使用⚠️标记

## 工作流
- 收到涉及代码编写、文件修改、命令执行等动手操作的任务时，不要立即开始。先输出结构化的实施方案，明确包含：
  - **目标**：要做什么，解决什么问题
  - **实施步骤**：具体的技术选型、文件变更清单或伪代码
  - **影响范围**：可能受影响的模块、接口或依赖
  - **验证与回滚**：如何测试，以及出错时的恢复方案
- 等待用户明确确认方案后，再动手执行

- **方案落盘**（可选，依赖 @fxri/toolkit）：
  - 执行顺序：先尝试 `pnpm exec toolkit`（npm 用户 `npx toolkit`，优先项目级），失败则尝试 `toolkit`（全局）
  - 可用时：
    1. 新项目初始化：无 `.tasks/` 任务区时先执行 `toolkit init` 建骨架（幂等，已存在不覆盖）
    2. 先查后写：执行 `toolkit tasks` 查 active 总览并核对 archive，避免重复建档；同一需求共用一个任务文件
    3. 创建/更新方案文件：在 `.tasks/` 目录下按 SPEC 规范建档（frontmatter 含 owner/status/created/scope 等字段）
    4. 校验：执行 `toolkit tasks check` 校验（frontmatter 合法性、命名规范、重名、依赖闭环等）
    5. 归档即收尾：任务完成后标记 `status: 已完成` 并填写 `completed` 完成时间，执行 `toolkit tasks archive` 归档，强制约束到此为止；提交、发版、推送不是必经步骤，按用户规则约定执行，若提交代码则先归档、后提交，归档文件与代码变更落在同一 git 提交
  - 均不可用时：将方案以 Markdown 格式完整输出到对话，提示用户可手动复制到 `.tasks/` 目录保存。不阻塞任务执行，但确保方案内容不丢失

- **会话记忆**（可选，依赖已全局加载的 fxri-session-recap 技能）：
  - 会话收尾：用户说「归档本次会话 / 总结本次」或会话即将结束时，把本次的结论、决策及理由、代码改动、未尽事项沉淀进 `.tasks/` 任务文件并归档；决策及其理由必须记，未尽事项拆独立任务，不在已完成任务正文留游离待办
  - 上下文恢复：新会话开头用户说「恢复上下文 / 继续上次的工作」时，读 `.tasks/active/` 与最近归档，输出现场摘要（进行中/阻塞任务、未完事项、建议下一步），全程只读，存疑内容先确认再动

- 涉及多文件、多步骤或架构变更的任务，必须额外输出详细的实施计划，等待用户确认后执行
```

## 逐段说明（为什么这么写）

| 段落 | 解决的真实问题 |
| --- | --- |
| 代码规范 | AI 生成代码常见的三类毛病：注释语言混乱、重复造轮子、风格与项目脱节；「不留过程性注释」防止需求反复时注释堆积 |
| 输出要求 | 抑制客套话和兜底句，让回答信息密度可用 |
| 工作流 · 方案先行 | AI 未对齐就动手是返工主因；强制「方案 → 确认 → 执行」三步走 |
| 方案落盘 | 把确认的方案变成 `.tasks/` 任务文件，人离开会话后决策仍可追溯；无任务区先 `toolkit init` 建骨架；「先查后写」防多会话重复建档；强制约束到归档为止，若提交代码则归档文件与代码变更同批，保证任务记录和代码变更可对应 |
| 会话记忆 | 对话记录本身不可跨会话传递；把记忆沉进仓库文件，新会话一句话接上现场，决策与理由不丢失 |
| 降级策略 | 「均不可用时输出方案不阻塞」——没装工具的项目也能用同一套纪律，方案内容不丢失 |

## 配套安装

规则里引用的命令来自本工具，一次性安装（全局，所有项目可用）：

```bash
pnpm i -g @fxri/toolkit                   # 主推 pnpm；npm 用户：npm i -g @fxri/toolkit
pnpm dlx skills add fxri-net/toolkit --global   # npm 用户：npx skills add fxri-net/toolkit --global
```

升级：

```bash
pnpm i -g @fxri/toolkit && pnpm dlx skills update --global && 开启新会话
```

⚠️ **升级后必须开新会话**：旧会话加载的技能内容还是旧版，新会话才会读到与 CLI 版本一致的新技能。

⚠️ **AI 行为约束**：安装与升级命令由用户本人执行，AI 不得自行执行全局安装/升级（`-g` 安装、skills 安装更新均属此列）；看到版本提示时提醒用户升级即可，升级提示可在环境变量 `FX_NO_UPDATE_CHECK=1` 时关闭（详见配置参考）。

校验就绪：`toolkit tasks --help` 可正常输出、对应 agent 的全局 skills 目录下可见 fxri 技能文件即为就绪。

⚠️ 全局安装 skills 会随所有项目自动加载；若只想在公司项目激活，见[完整攻略 · 项目级激活模板](./guide#项目级激活模板)。
