# 本机接入（setup）

> 一条命令完成本机接入：安装 AI 技能、配置全局规则、设置生效范围。只碰全局层，在任意目录可执行；项目初始化用 `toolkit task init`。

```bash
toolkit setup                   # 交互向导
toolkit setup --yes             # 非交互：按默认值执行
toolkit setup --dry-run         # 只输出逐项动作清单，不写盘
toolkit setup --rules full      # 指定全局规则预设
toolkit setup --skills project  # 指定技能分发范围
toolkit setup --no-scope --no-usage
```

## 流程

1. **检查环境**：Node 版本与是否可交互；已就绪项只作状态展示。
2. **要配置哪些内容？** 四项勾选：

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 安装 AI 技能 | 勾选 | 写到全局技能目录或项目内技能目录（按所处目录自动判定）；勾选后重新进入技能与目标选择，上次选择只作默认勾选，须确认才执行 |
| 配置全局规则 | 未组合过时勾选 | 生成规则文本并复制；勾选后进入模块选择，显式给了 `--rules <preset>` 才直接按预设组合；确认的组合写入组合缓存，下次 `rule compose` 作为默认 |
| 设置生效范围 | 不勾 | 写到本机作用域配置，决定哪些项目生效；首步选配置层的末位有「退出」，其余操作在 `toolkit scope` 菜单里进行 |
| 开启使用统计 | 不勾 | 写到本机统计配置，事件只留本机、不上传；选中后进入 `toolkit usage setup`，首步末位有「退出」 |

勾选页的初始值取自上次确认的勾选（四项完整保存，未勾选同样记住），首次执行用上表默认值。

3. **开始配置**：串行执行，逐步打印。
4. **配置完成**：逐项结论、失败项的重试命令与下一步。

## 行为约定

- 只做本机接入，不初始化任务区：任务区与规范载体是项目内的事，进入项目后技能会自行初始化；手工兜底时执行 `toolkit task init`。
- 有交互的步骤一旦勾选就必进交互，不因「已配置」替用户跳过；上次保存的技能 / 规则选择只作默认勾选，须确认才执行，不替用户直接确认。
  规则步骤与 `rule compose` 共用同一份组合记忆：确认的组合即成为下次 `rule compose` 的默认组合；`--yes` 两者都不读不写。
  勾选页与步骤内的选择页都不设出口项：首步勾选页按 ESC 取消整次接入（`0`），步骤内的选择页按 ESC 取消该步、按成功返回并继续下一步。
- 勾选记忆只在确认勾选后更新：`--dry-run`、ESC 取消与非交互 `--yes` 都不写入，也不会被 `--yes` 读取（零交互模式不替用户做范围决定）。
- 单步失败不中断后续，末尾汇总未完成项与重试命令；全部失败才非 0 退出。
- 规则一步只生成文本并复制到剪贴板，不写任何 Agent 配置；粘贴位置由结尾提示给出。
- 项目内的提交规则快照不由 setup 刷新；需要更新时执行 `toolkit rule sync`（显式同步，不挂 prepare / setup 自动化）。
- `--yes` 与「设置生效范围」「开启使用统计」互斥：零交互模式不写任何范围决定，也不开启采集；技能与规则在 `--yes` 下按已保存选择 / 指定预设直接执行，不进入选择。
- 非 TTY 且未给 `--yes`：提示改用 `--yes`，以无交互退出码结束。
