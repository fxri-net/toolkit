# 适用场景

> 目标读者：想知道「这套东西和我有没有关系、该从哪一步开始」的人。先对号入座，再按三步起点进入操作手册或完整攻略。

## 个人 AI 重度用户

**你现在的样子**：一个人同时在几个仓库里让 AI 干活；会话一关，方案、决策和踩过的坑都跟着消失，下次重来一遍。

**这套工具怎么做**：方案与决策落成 `.tasks/` 下的任务文件，归档后留在仓库里；AI 技能让每次会话按同一套流程走；
反复出现的做法沉淀进规范载体，越用越省事。

**装上就位**：装一次 CLI（`pnpm add -g @fxri/toolkit`）并跑一次 `toolkit setup`，技能、规则与生效范围一次配好。
之后回到正常的开发节奏——建档、校验、归档、沉淀由技能跟着对话自己走，不必记命令，也不用额外开流程。

**落地后得到什么**：换电脑、换会话都不丢上下文，历史决策可检索；AI 产出格式稳定。

深入阅读：[快速开始](./getting-started) · [操作手册](./handbook) · [任务管理](./cli/task)

## 团队 AI 协作开发

**你现在的样子**：几个人（每人又各带几个 AI）同时改一个仓库，任务记录散在群聊和各自脑子里，经常重复实现或互相覆盖。

**这套工具怎么做**：任务唯一键（日期-负责人-简述）+ 先查后写 + 归档排他锁；格式与规则校验前置到任务落盘时；
多人多 AI 的产出保持同一格式。

**装上就位**：项目内装依赖（`pnpm add -D @fxri/toolkit`，版本随仓库锁定，成员与 CI 一致），
一次 `toolkit skill install --scope project` 后队友 clone 即用。
之后照常协作：任务记录、格式校验、归档在对话里自然发生，需要看全局进度时问一句即可。

**落地后得到什么**：谁在做、做到哪、为什么这么做都能从仓库查到；新人接手不用口口相传。

深入阅读：[快速开始 · 完整安装](./getting-started#完整安装) · [完整攻略 · 工作流总览](./guide#工作流总览) · [任务管理](./cli/task)

## 公司 / 组织内部统一

**你现在的样子**：各团队各用各的 AI 规则与技能，产物格式五花八门；想把一套做法推广到全公司，又不想强迫所有人改工作方式。

**这套工具怎么做**：技能与规则随包分发、版本锁定；作用域按项目、目录、标记或 git 远端决定生效范围，
个人项目不受打扰；内网环境可装（见[常见问题 · 国内网络优先走哪条渠道](./faq#国内网络优先走哪条渠道)）。

**试点接入**：选一个试点仓库装一次并跑 `toolkit setup`，再用作用域设定只在公司项目生效（个人项目零打扰）。
跑两周后想知道推广效果，让 AI 出一份统计即可。

**落地后得到什么**：统一规范不靠行政命令，靠工具默认值；新人 clone 仓库即得到同一套协作方式。

深入阅读：[作用域](./cli/scope) · [技能分发](./cli/skill) · [全局规则](./cli/rule) · [内部推广](./adoption)

## 技术负责人 / 规范沉淀者

**你现在的样子**：团队里反复出现同一类返工，经验停在老员工脑子里；AI 每次都从零开始，风格各不相同。

**这套工具怎么做**：把反复出现的做法写进规范载体（`.tasks/conventions/`），结构升级与体检由工具托管；
再用技能与全局规则，把规范变成 AI 的默认做法。

**装上就位**：项目里一次接入后，任务区与规范载体骨架随首次建档自动就位，归档时技能会引导规范沉淀。
规则由 AI 组合进各 agent 的全局入口，之后照常开发，规范随任务自然沉淀。

**落地后得到什么**：规范可检索、可校验、可分发；新人由 AI 带着按规范做事。

深入阅读：[规范载体](./cli/convention) · [全局规则](./cli/rule) · [完整攻略 · conventions/](./guide#conventions-规范沉淀地)

## 开源项目维护者

**你现在的样子**：贡献者水平参差，提交信息、文档与更新日志风格各异；维护者大量时间花在「按模板重写」上。

**这套工具怎么做**：提交信息规则、CHANGELOG 分组、文档站校验三件套；技能把同一套要求分发给贡献者的 AI。

**装上就位**：装一次技能与规则；文档站校验与更新日志由 CI 与技能承担，维护者只在发版时确认。
贡献者的 AI 按同一格式产出，不必人工按模板重写。

**落地后得到什么**：贡献者的 AI 按同一格式产出；发版与文档漂移可机检。

深入阅读：[发版与更新日志](./cli/release) · [文档站校验](./cli/docs-check) · [提交信息规则](./rules/commit)

## v1 存量工程

**你现在的样子**：项目还在 1.x，配置段名、技能旧名与任务区形态都是老版本。

**这套工具怎么做**：`toolkit upgrade` 一键迁移（预演 → 执行 → 复检），失败有手工兜底与备份。

**迁移三步**（一次性）：

1. `toolkit status` 看迁移提示
2. `toolkit upgrade --dry-run` 预览清单
3. `toolkit upgrade` 执行，再 `toolkit status` 复检

**落地后得到什么**：迁移可回滚、可复检，不用手工改一堆文件。

深入阅读：[升级迁移](./cli/upgrade) · [v1 → v2 升级](./upgrade-v2)

## 谁适合用（角色速查）

核心是**开发人员**（全功能：任务协作、发版 CHANGELOG 与配套工具链），但不限于开发——只要工作产物在 git 仓库里、有 AI 助手代操作，就能用：

| 角色 | 典型用法 |
| --- | --- |
| 产品经理 | 把需求清单整理成 Excel/CSV（列名写「任务名/负责人/状态/截止日期」等常见叫法即可），让 AI 执行导入转成规范任务文件，开发接手就是标准格式；需求里的手机号/邮箱落盘自动脱敏 |
| 项目经理 | 按负责人/范围/状态过滤任务总览，导出 XLSX 做汇报；任务依赖闭环校验提前暴露排期断链 |
| 测试 / QA | 缺陷修复与回归任务跟踪（状态含「阻塞」，适配缺陷流转），归档后作为测试记录可追溯 |
| 运维 / SRE | 变更与发布任务台账；内网 URL、IP、密钥落盘自动掩码；发版记录走多语言 CHANGELOG |
| 技术负责人 | 全景总览查成员负载，格式校验保证多人 + 多个 AI 产出一致 |
| 独立开发者 / 自由职业者 | 跨会话工作记忆：AI 会话关掉，结论还在仓库里 |

## 不适用

- 需要 Jira 级项目管理（甘特图、看板、消息通知、打卡型工时统计）的团队；
- 工作产物不进 git 的协作场景（客服工单、招聘流程等）；
- 需要在线多人实时编辑任务面板的团队。
