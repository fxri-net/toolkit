# 内部推广

> 目标读者：自己用着好、想在公司里推广的人。这里有可直接发出去的介绍、试点方案与决策者问答，不需要再自己整理材料。

## 一句话介绍（可直接复制）

> 方弦工具集把 AI 会话里的方案与交付沉淀成仓库里的任务与规范，再通过技能与规则让 AI 按同一套做法干活；
> 支持按项目限定生效，数据只留本机。

## 30 秒讲稿

1. **现在的问题**：方案定完就散在对话里，换个人、换个会话就要重新讲一遍；几个人各带几个 AI 同时改一个仓库，经常重复实现。
2. **我们的做法**：方案落成仓库里的任务文件，完成后归档并沉淀成规范；技能与全局规则让 AI 每次都按这套流程走。
3. **得到什么**：谁在做、做到哪、为什么这么做都能查到；新人 clone 仓库就得到同一套协作方式。
4. **升级**：装过旧版本的人升级 CLI 后在项目内跑 `toolkit upgrade`，旧工程与本机数据一次迁到当前版本；`toolkit status` 可自查。

## 3 分钟讲稿

- **痛点三行**：决策随会话消失 / 多人多 AI 互相覆盖 / 规范停在个人脑子里。
- **机制三行**：任务文件（`.tasks/`）+ 规范载体（`.tasks/conventions/`）+ 技能与规则（随包分发，AI 自动照做）。
- **落地一行**：先在一个仓库试两周，用三项指标判断要不要推广。

## 试点方案

| 项 | 建议 |
| --- | --- |
| 范围 | 1 个仓库：改动频繁、两三个人以上协作 |
| 周期 | 2 周 |
| 指标 | 任务留档率、返工与重复沟通次数、沉淀出的规范条数 |
| 成功判据 | 团队不看文档也能复述流程；周会能直接引用任务记录 |
| 止损判据 | 两周无人使用，或产出格式反而更乱：停掉试点，删掉仓库内产物即还原 |

## 决策者问答

| 问题 | 一句话回答 |
| --- | --- |
| 数据会不会外传 | 默认全部留在本机，使用统计默认关闭、不联网，详见[隐私与数据边界](./usage/privacy) |
| 要不要全员装 | 不必；试点仓库用 devDependency 即可，版本随仓库锁定（见[完整安装](./getting-started#完整安装)） |
| 和 Jira / Confluence 冲突吗 | 不替代工单与文档站：工单管排期状态，这套管 AI 会话里的方案、决策与规范（见[适用场景](./scenarios)） |
| 成本与许可 | MIT 协议，无服务端、无订阅，装不装只取决于团队 |
| 安全与脱敏 | 落盘默认脱敏，可扫描并归一本机路径，详见[隐私脱敏](./config/redact)与[隐私体检](./cli/privacy) |
| 试点失败怎么退 | 删掉仓库内的 `.tasks/` 与配置即还原，没有后台要清理 |

## 推进清单

- [ ] 选一个试点仓库（1 个，两三人以上）
- [ ] 装 CLI：`pnpm add -D @fxri/toolkit`
- [ ] 跑 `toolkit setup` 完成本机接入
- [ ] 进项目首次用到时，技能会自动建好任务区（无需手工）
- [ ] 跑两周，让 AI 出一份使用统计作为指标
- [ ] 复盘：继续 / 扩大 / 停止

## 常见阻力

| 说法 | 回答 |
| --- | --- |
| 我们已经有 Jira 了 | 不替代工单。Jira 管排期与状态，这套管 AI 会话里的方案、决策与规范，两者可以并存 |
| AI 写的东西能信吗 | 产出全部落在 git 里，可 diff、可 review；格式与并发由工具兜底 |
| 会不会把代码传到外面 | 无服务端、无上报；使用统计默认关闭，开启也只写本机 |
