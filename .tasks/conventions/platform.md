# 平台与路径规范（platform）

> 归属：platform。涉及路径判定、跨平台命令时适用。索引见 index.md。

## C-32. 现场路径形态须归一

生产代码对「**同一资源的不同路径书写形态**」做比对或归属判定时，须先取**磁盘真实形态**（`fs.realpathSync.native` 等）再比较——比对两侧、以及作为边界基准的值（如 home、仓库根）与其父链逐级目录，都要过归一函数；只做纯字符串归一不足以替代真实形态归一。

- **要求**：须归一的书写差异包括 Windows 8.3 短名 / 长名（`C:\Users\RUNNER~1\…` ↔ `C:\Users\runneradmin\…`）、软链 / 实链（macOS `/var` ↔ `/private/var`）、盘符与段大小写、分隔符。`normalizePathForCompare` 这类「分隔符转正斜杠 + 去尾斜杠 + 折叠大小写」只解决**书写层**差异，对短名 / 软链一律无能为力；两者须叠加使用、不得互相替代，且真实形态归一在路径不存在时回退原串，保证「本就不可命中」的场景行为不变。
- **反例**：`inspectLocalConfigIgnore` 以 `git rev-parse --show-toplevel` 返回的**长名**仓库根，与来自 `os.tmpdir()` 的 **8.3 短名**目标路径做前缀比对，`isInsideWorktree` 误归 `outside-repo`，「本地配置未被 gitignore 覆盖」告警被**静默吞掉**（连同违反 `C-26`）；`config.ts` 本地层 `stopAtHome` 的 home 边界同因失配，存在把 `~/.toolkitrc.local.json` 误当项目本地层命中的风险。两处本地自检全绿，仅在 CI 的 Windows runner（临时目录为短名）才暴露。
- **理由**：形态差异是否出现取决于运行机器的用户名长度、临时目录设置与文件系统挂载方式，缺陷在作者机器上默认不可见且**静默降级**，直达用户真机。
- **配套**：与索引 `C-23`「测试假现场须与真实现场形态一致」、`C-29`「门禁与测试的环境无关性」配套——`C-23` 管「测试的假现场形态失真」、`C-29` 管「门禁步骤依赖运行环境」，本条管「**被测实现**对现场形态差异的归一缺失」；三者同属「形态差异只在特定环境暴露」一族，互为补充。

## C-42. 多系统与多 Shell 支持

平台差异须集中隔离，不得让某项能力只能在单一操作系统或单一 shell 上运行；对外命令须在目标平台的全部常见宿主中可执行。

- **要求**：平台分支只允许出现在命令 / 路径生成函数与平台适配层，业务逻辑不得出现 `process.platform` 判断；生成函数须接受可注入的平台参数，Windows 与 POSIX 两条分支各有单测；Windows 侧命令须同时满足 PowerShell 与 cmd 的解析规则（经 `powershell -NoProfile -Command` 包装或等价方式），POSIX 侧须满足 bash / sh；文档与技能给出多平台写法；新增能力不得绕过 `verify` 的 windows / macos 任务。
- **反例**：把 `"exe" "script" args` 这种只在 cmd 下成立的写法写进跨平台 Hook；只在本机单平台手工跑一遍就标「已验证」；文档只写一种 shell 的命令。
- **理由**：使用者的系统与宿主 shell 不由工具选择；单平台可用会在另一平台静默失败（如 PowerShell 把第二个引号串当表达式直接报错），静默失败比显式报错更难发现。
- **配套**：与 `C-23`「测试假现场须与真实现场形态一致」、`C-29`「门禁与测试的环境无关性」、`C-33`「类型检查须覆盖测试文件」配套——前者要求两平台分支都有用例，后两者保证门禁本身不被环境绑定。
