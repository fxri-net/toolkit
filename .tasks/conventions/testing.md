# 测试规范（testing）

> 归属：testing。写或改测试时适用。索引见 index.md。

## C-23. 测试假现场须与真实现场形态一致

测试中用于模拟现场（安装布局、目录结构、路径形态等）的假数据，须与真实环境可能出现的形态一致；被测逻辑对现场形态存在分支判据时，每一种真实存在的形态都要有对应用例覆盖，不得只造一种。

- **要求**：造现场前先枚举被测逻辑会遇到的真实形态（如 pnpm 项目内 / pnpm 全局 / npm、yarn 的真实目录），逐种造现场并断言；形态判据本身也要有纯函数级用例，端到端用例则要跑通「形态变化 → 行为仍正确」。
- **路径别名**：路径写法同属现场形态——真实路径与链接别名（符号链接 / junction / 临时目录短名）都要有用例；CI runner 的临时目录常是别名，本地不一定复现，须主动用链接指向同一目录补测。
- **反例**：稳定入口解析的守卫只在「项目内 pnpm 布局」成立，而测试假现场清一色写成 `<home>/node_modules/.pnpm/…`——该形态属项目内布局，全局布局（`.pnpm` 与 `node_modules` 并列）无人覆盖，守卫在全局布局下恒假也拦截不到，缺陷直达用户真机；且判定层只比对 realpath，`status` 仍报「正常」，症状被二次掩盖。
- **反例（路径别名）**：技能版本递增的写回前校验用原始目录拼内存覆盖键，而 lint 先取 realpath，别名根下覆盖键失配、回落磁盘旧内容，误报版本不一致；本地临时目录不是别名故全绿，windows / macos CI 才暴露。
- **理由**：假现场与真实现场形态不符时，测试通过只证明「该形态下正确」，对未覆盖形态零信息量，并给出虚假的安全感。
- **配套**：与索引 `C-17`「测试不复刻被测实现」配套——后者管「逻辑同错复刻」，本条管「现场形态失真」，两者都会让实现缺陷原样漏过，互为补充。

## C-44. 仓库自检脚本的每次改动都要有假现场用例

仓库自检脚本（`scripts/check-*.mjs`）新增或修改校验逻辑时，须在对应测试文件里补假现场用例：一条断言「合规时退出码 0」，一条断言「违规时报出含具体目标的 error」。

- **要求**：沿用既有范式（临时目录搭假仓库 + `spawnSync` 跑脚本）；脚本为兼容裁剪场景而做的容错（缺失文件直接跳过等）也须有用例锁住，防止下次改动把容错改回抛异常。
- **反例**：`check-consistency.mjs` 加规则模块体量棘轮时未配用例，脚本在假现场缺 `templates/rules/` 时直接抛 `ENOENT`，把既有两例测试打破；同一文件上一次加「references 引用校验」也没补用例，同类问题第二次才被发现。
- **理由**：自检脚本本身不在被测面内，没有用例时它失效了也无人察觉；「临时改错再改回」的一次性手测不产生回归保护。
- **配套**：与索引 `C-23`「假现场形态须真实」配套——C-23 管现场是否真实，本条管有没有现场。

## C-56. 测试文件按被测主题归并

补测试时归并到既有同主题文件，不按任务另起；源模块删除或合并时同批删除其测试；每版发布前盘点冗余用例。

- **映射**：按被测主题建文件（如 `tasks/validate` 的 `validate-line` / `validate-import`；命令入口对应 `skills-lint-cli` 这类文件），文件内再用 `describe` 分主题。
- **补测**：只在既有同主题文件追加用例；仅当被测主题确实没有对应文件时才新建，不按任务或日期再起一个。
- **退役**：源模块删除或合并时，同批删除或合并其测试文件，不留孤儿用例与失效 mock。
- **盘点**：每版发布前人工过一遍——重复断言（同一行为在两个文件各断言一遍）、只测实现细节、对应行为已移除的用例，删除或合并。
- **存量**：不强制批量合并既有碎片（如 skills 19 个、scope 15 个），只约束新增；确需合并时单独评估。
- **反例**：同一模块在三个任务里各建一个 `xxx-2.test.ts`；`conventions-status` 与 `validate-conventions` 对同一行为各断言一遍；模块删除后测试仍引用已删实现；为刷改动行覆盖率写只走主路径的空断言。
- **理由**：覆盖率按改动行判定会提高补测频次；不归并则测试文件随任务线性膨胀，重复断言还会让「改一处漏一处」成为常态。
- **配套**：与 `C-23`（假现场形态）、`C-44`（自检脚本要现场）配套——三者分别管现场真实性、脚本可测性与文件组织。

## C-57. 测试临时目录前缀与入口

测试临时目录只能通过 `helpers.tempDir` / `tempPath` 创建，前缀统一为 `fxts-tk-`，不得直接引用系统临时目录。

- **入口**：`tempDir(prefix)` 建目录并登记，`tempPath(prefix)` 只生成唯一路径（供 `vi.hoisted` 沙箱与「路径不存在」用例）；两者运行时校验前缀，非 `fxts-tk-` 直接抛错。测试文件（除 `helpers.ts` 等实现文件）不得出现 `tmpdir` 标识符；`process.env.TEMP|TMP` 仅允许 `vi.hoisted` 白名单文件使用。
- **前缀**：`fxts` 为品牌段、`tk` 为产品段，测试与生产短命目录共用同一前缀族（`fxts-tk-clip-` / `fxts-tk-src-` / `fxts-tk-node18-`），便于按前缀统一识别与回收；历史前缀 `fxri-` / `tk-` 不再新增，需要时用 `--prefix` 一次性清理。
- **兜底**：`setup-temp.ts` 在文件结束与进程退出时删除登记项；`scripts/clean-temp-residue.mjs` 在 `pnpm verify` 单测前后按前缀与年龄门槛清扫。`FX_TOOLKIT_KEEP_TEST_TEMP=1` 保留现场时，`verify` 跳过清扫与残留判定，保留只到下次不设开关的门禁。
- **反例**：自起 `fxri-` / `tk-` 前缀；把前缀放进变量再传给本地 wrapper；给 `makeDir("my-")` 这类非白名单包装传参；在 `src/__tests__` 之外放测试文件。
- **理由**：系统不回收 `%TEMP%`（Windows 无自动清理，POSIX 轮转周期以天计），`mkdtemp` 只保证唯一；只统一前缀仍可被变量与包装绕过，入口化 + 运行时断言 + 守卫才能根治。
- **配套**：与 `C-56`（测试文件按被测主题归并）同册——C-56 管测试文件组织，本条管临时目录命名、入口与回收。
