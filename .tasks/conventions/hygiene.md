# 任务区与协作规范（hygiene）

> 归属：hygiene。写任务区文本、设计人机协作文案时适用。索引见 index.md。

## C-38. 任务区不出现参考仓库名

`.tasks/` 内文本（任务档正文、归档叙述、frontmatter 字段值）指称外部仓库时，一律用**通用措辞**（如「接入方仓库」「被参考仓库」「外部仓库」），不得写实名。

- **要求**：书写任务区文本前，凡需提及本仓以外的仓库，一律改用通用称谓；做技术验证 / 对照参考时同样只写「被参考仓库」这类泛称，不列被参考对象的实名清单。判据取「**是否以具体名称指涉某个外部仓库**」，与 `C-36` 的视角判据正交（本条管用词、`C-36` 管内容归属）；依赖包名 / 被调接口名等属本仓事实者照写。
- **反例**：在任务档正文或归档叙述里列举被参考仓库的实名（如「已把 `foo-web`、`bar-service` 的规范升级至最新版」），或把实名当作 frontmatter 字段的示例值——本仓文本随 git 分发后即携带外部仓库的目录命名，而读者只具本仓视角、无从判断该名与本仓的关系。
- **理由**：任务区是仓库自述面，只承载本仓事实；实名指涉外仓既污染本仓文本，又把某次会话偶发的参照对象固化成仓库事实，还随分发外泄无关仓库信息。
- **配套**：与索引 `C-36`「跨仓库改动各自归档」配套——`C-36` 管「记不记他仓的事」（视角），本条管「写不写他仓的名」（用词），两者同属任务区文本治理，互为补充。
