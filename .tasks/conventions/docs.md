# 文档规范（docs）

> 归属：docs。写文档页面、正文段落、版本括注时适用。索引见 index.md。

## C-25. 版本括注口径

文档中的 `（x.y.z 新增）` 类版本括注，只用于标注**命令 / 技能 / 配置项 / 单一能力点**的首次引入版本，且须紧邻该对象本身；描述**跨版本演进的产物清单**时不得在句末挂版本括注。

- **要求**：括注单一能力点时须点明对象（如「配置项 1.7.0 新增」）；后续扩展史一律由 `CHANGELOG.md` 承载，文档不复述「x.y.z 又扩展了什么」；与 `--help` 同源的命令清单以 `--help` 文本为准、不加版本括注。
- **反例**：`初始化项目任务区（生成 .tasks/ 骨架、conventions/ 规范载体与技能入口壳，1.7.0 新增）`——产物跨 1.7.0（`init` 与 `.tasks/` 骨架）、1.10.0（conventions 目录化）、1.11.0（v2 载体与入口壳）三代，`1.7.0 新增` 挂句末必然失真。
- **理由**：把「首次引入版本」（稳定事实）与「跨版本演进清单」（易变事实）混在一处，任何一次能力演进都会让括注失同步，且读者无从判断该括注指向哪一代产物。

## C-40. 文档信息架构

面向用户的文档按**读者要做的事**组织，不按能力上线时间追加；版本史交 `CHANGELOG`，不进标题。

- **排序**：总览 → 基础概念 → 按任务分组的操作页 → 参考 / 排错；新增页面按主题插入，不一律追加末尾
- **标题**：只写能力名（如 `tasks（任务管理）`），不写「（x.y.z 新增）」——版本括注按 `C-25` 只用于正文中紧邻对象的首次引入说明
- **体量**：单页正文 ≤150 行且 ≤12k 字符；总览页正文 ≤80 行。正文行不计表格、代码块、标题与空行；总行数 >300 只作拆分提醒、不作阻断
- **体量检测**：正文行与字符数由 `scripts/check-docs-readability.mjs` 在 `pnpm verify` 内硬校验；超限即拆页或下沉到 references
- **精简不失真**：并句、改结构、迁移位置都可以，不得删事实；确需删减事实须用户明确指示，AI 不主动做有损压缩
- **无损检测**：`scripts/check-doc-loss.mjs` 按版本 tag 比对整句覆盖率，只提示疑似丢失、不阻断
- **页模板**：每页四段——一句话用途与适用场景 / 常用命令示例 / 子命令与选项 / 边界与注意（⚠️ 列表）；参考类页面（配置 / API / 退出码）按字段或条目主题组织，不套「常用命令 / 子命令」两段
- **总览页**：必须有命令总览表（命令 / 用途 / 常用子命令 / 分页）与「按场景找命令」导航
- **页脚**：每页 `## 相关页面` 只列 1–3 条主题参考，上一篇 / 下一篇交给主题自带 `docFooter`（按侧边栏顺序自动生成，生成页同样覆盖），不手写导航
- **豁免**：自动生成页（如 `toolkit changelog doc` 产出的更新日志镜像）不参与本条
- **反例**：新命令一律追加到文档末尾，导致基础配置排在进阶能力之后；把版本号写进标题，导航随版本持续膨胀；把数百字的校验规则塞进表格单元格
- **理由**：文档的第一成本是「找到该读哪页」；按时间追加会把检索结构退化成变更流水账，单页超限则让读者承担全量阅读成本

## C-43. 段落级可读性

正文段落按「主干 + 例外」两级结构书写，一段只讲一件事。

- **要求**：单段单行 ≤120 字符；单句全角分号 `；` ≤2 个；并列项 ≥5 个一律改为列表或表格。
- **要求**：例外分支降级为子项或成组列表，不用括号嵌套承载；长枚举（目录、agent、环境变量）不进句子。
- **反例**：`README.md` L76 用 917 字符讲完分发形态、分层、交互与作用域四件事；`conventions-spec.md` L51 把 19 个候选目录内联进一句。
- **理由**：段落是阅读的最小单位。分支全塞进主句，等于把解析成本转嫁给读者；AI 读长句同样会漏条件，人则直接跳读。
- **配套**：`C-40` 管页面怎么排，本条管段落怎么写；`C-41` 不构成把密度当省 token 手段的理由。检测入口为 `scripts/check-docs-readability.mjs`，挂在 `pnpm verify` 内、阈值与本条同值。
