# 新增 fxri-text-encoding 技能并补规则层铁律

## 背景

源实现项目（外部仓库）反复出现同一类故障：`publish.ps1` 丢失 UTF-8 BOM 后，Windows PowerShell 5.1 按系统 ANSI（中文 GBK）解码，中文注释变乱码并导致整份脚本语法报错（`Missing closing '}'`）；补回 BOM 后重打包又再次丢失，说明根因在「每次重新生成文件的那一步」而非产物本身。

复盘的结论是：这类故障的本质是**生产者写入的字节 ≠ 消费者默认的解码方式**，与「哪个操作系统」无关——同一份无 BOM 的 UTF-8 文件，PowerShell 5.1 解码失败、PowerShell 7 与 Node 正常、Excel 打开 CSV 乱码、`cat` 首行多出不可见字符。既有三个技能均为流程类（建档 / 发版 / 收尾），无处置此类问题的载体，故新建窄技能承载细则。

用户明确要求：不写项目级门禁，改为「开发任意项目、任意步骤都能遵守」的规范。技能正文按需加载，无法保证「任意步骤」都进上下文，因此采用双层：规则层一句常驻铁律（`docs/ai-rules.md` 代码规范）+ 技能承载完整细节（按需加载）。
