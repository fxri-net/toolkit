# 载体表格紧凑化与格式化豁免托管

## 背景

用户对照了另一个已安装 prettier 的宿主仓库，其规范载体 `.tasks/conventions/index.md` 源码里塞满对齐空格（实测空格占比 34.9%，1790/5127 字符），本仓库载体因未装 prettier 而保持紧凑（9.3%）。根因是**宿主仓库对 `.tasks/**/*.md` 跑了 prettier**——prettier 对 GFM 表格做列对齐填充（按 `string-width` 计 CJK 宽度），属刻意行为；官方立场是「生成物 / 机器读写文本走 `.prettierignore`」。

这些填充字符在 Markdown 预览里不显示，却让源码可读性变差、token 成本上升，而 CLI 写路径（`setRowCell`）输出本为紧凑形态，两边拉锯还会产生混排。判断结论：**紧凑是规范形态，填充是偏离**，工具侧应把这一立场声明化：

- **隔离**（防再生）：`toolkit init` 幂等托管 `.prettierignore`，让格式化器不碰任务区；
- **归一**（治存量 + 兜底）：新增 `toolkit conventions format` 把任务区全部 md 的表格压回紧凑形态；
- **检出**：`conventions status` 与 `tasks check` 软告警填充态，让偏离可被发现；
- **声明**：规范与文档写明「紧凑为规范形态」。

## 实施方案

1. `src/conventions/format.ts`：修 `splitRow` 的裸 `split("|")`——转义竖线 `\|` 会被切错，归一前须改为转义感知切分；`setRowCell` 仍以「`| ` + cells.join(` | `) + ` |`」输出紧凑形态，作为规范化不动点。
2. 新增归一模块 `src/conventions/compact.ts`：
   - `compactTableLine(line)`：把单个表格行归一到紧凑形态（保留分隔行的对齐标记 `:---` / `---:`）；
   - `compactMarkdown(content)`：逐行扫描整个 md，**跳过 fenced code block**（``` 与 ~~~，含语言标记与嵌套口径），对表格行做紧凑化；幂等（已是紧凑形态的行输出不变）；
   - `listMarkdownFiles(root)` / `filledTableLines(root)`：遍历任务区全部 md（载体三件 + `active/` + `archive/`）、检出填充态行（目录不存在容错为空结果）；
   - `formatConventions(tasksDir, options)`：逐文件归一，产出报告（文件数 / 变更文件数 / 变更行数），支持 `dryRun`。
3. `src/cli.ts`：新增 `conventions format` 子命令（`--dir` / `--dry-run` / `--format json`，与 `changelog --history format` 同构）；更新 conventions 域描述与裸 `conventions` 帮助文案（子命令 2 → 3）。
4. `src/init.ts`：新增 `.prettierignore` 幂等托管（复用 `# @fxri/toolkit` marker 与 `isRowCovered` 思路）——仅当仓库有 prettier 迹象（devDeps 有 prettier / 存在 prettier 配置 / 已存在 `.prettierignore`）时写入忽略任务区；任务区外置时不写；toolkit 源仓库跳过。
5. `src/conventions/status.ts`：新增「表格形态」体检项，检出载体表格填充态（warn）。
6. `src/tasks/validate.ts`：`validateConventions` 与任务文件校验补填充态 warn，经 `tasks check` 暴露（`--fix` 不代改，指向 `conventions format`）。
7. 三方一致同步：
   - docs 逐篇触达核对（结论见「影响范围」）；
   - `skills/fxri-plan-to-task/references/conventions-spec.md` 新增「紧凑为规范形态」节 + 写入纪律；`skills/fxri-plan-to-task/SKILL.md` 版本双写递增；
