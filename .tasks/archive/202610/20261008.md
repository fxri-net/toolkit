# 跨仓库痕迹治理与归档纪律

## 背景

本工具首个真实接入的宿主仓库，在开发期被选作规范示例值、并被直接在本仓库内改动其内容，使本仓库文本里散落该**接入方仓库名**——出现在通用示例值（`SPEC.md` / docs / skills / 源码注释 / 测试）、发版历史（`CHANGELOG.md` 与其镜像）以及历史归档叙述与 frontmatter `scope`。

根因不是「写错了词」，而是**任务档的视角**：任务档是仓库自述，跨仓库是会话属性而非仓库属性；当初把接入方仓库的工作记进了本仓库的任务档。故治理分两手——立纪律防再生 + 一次性脱敏存量。使用者诉求：仓库文本一律不体现跨仓库痕迹，像每个仓库的独立任务一样。

延续来源链：`archive/202610/20261007.md`「载体表格紧凑化与格式化豁免托管」（同属「任务区文本治理」主题，非同一需求，故重新建档）。
