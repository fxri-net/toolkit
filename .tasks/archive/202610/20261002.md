# 归档冲突标记归一

## 背景

多人协作时同一天各自归档不同任务：先提交者推上去后，后提交者 pull 会与本地归档文件产生 git 冲突。根因是归档文件 `archive/{YYYYMM}/{YYYYMMDD}.md` 为**按日聚合的单一可变文件**，归档动作是「读旧 → 合并 → 按 `completed` 降序重排 → 整文件重写」，两个写者落在同一日必然冲突（`.archive.lock` 只防同机并发进程，跨机 git 层无效）。

冲突的本质是**确定性重算**：双方差异恒为「各新增一个任务块」，合并规则唯一（并集去重 + 按 `completed` 降序重渲染），无歧义。缺的是工具识别冲突标记的能力——当前 `normalize` 不认识 `<<<<<<< / ======= / >>>>>>>`，`parseArchiveBlocks` 会把标记行当作块正文，`--fix` 无法干净解决冲突文件，得人工手改。

## 实施方案

1. `src/tasks/normalize.ts`（唯一行为变更点）
   - 新增冲突标记识别：按 git 默认 7 字符口径匹配 `<<<<<<<`（后接标签）、`|||||||`（base，diff3 风格）、`=======`（无标签）、`>>>>>>>`（后接标签）；
   - 新增并集解析：命中冲突区时保留 ours 与 theirs 两侧内容、丢弃 base 段与全部标记行，两侧之间补块间 `---` 分隔，交回既有解析链路；
   - `fixArchiveFile`：读取文件内容后先做冲突并集解析，命中则计一次修复、动作记为「解决冲突标记」，再走既有「补元数据 / 范围归一 / 漂移迁移 / 降序重排 / `renderArchiveFile` 写回」——`renderArchiveFile` 天然按标题去重 + 降序，输出即无标记的规范归档文件；
   - `checkArchive`：检出冲突标记即报一条 `fixable: true` 问题（「含 git 冲突标记，可 --fix 自动解决」），并跳过该文件其余检查项（避免在未解析的冲突内容上产生噪声问题）。
2. 测试 `src/__tests__/normalize.test.ts`
   - 构造两侧各一块的冲突归档文件，跑 `fixArchive` 后断言结果等于「两侧块并集 + 按 `completed` 降序」且无任何标记残留；
   - 断言 `checkArchive` 报出 fixable 的冲突标记问题。
3. 文档 / 技能 / 规范同步（三方真实一致）
