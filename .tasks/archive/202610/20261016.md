# 规范载体v3三分区与跨平台补强

> 来源链：延续 `20260916-唐启云-规范载体目录化与端分类`（`.tasks/conventions.md` 单文件 → 目录形态，确立端分类与读取分层）与 `20260926-唐启云-规范载体v2与入口壳`（v1 → v2：稳定 ID `C-<n>`、`history.md` 独立、入口壳），本次把载体由 v2 升到 **v3 三分区**，并补齐 Windows 以外平台的兼容性缺口。

## 背景

用户真实诉求：**减少任务开始时「常驻读取」的 token 与上下文占用**。当前 v2 载体的痛点是「规范已作废，AI 每次开工仍读到废弃条目」——既有索引行（状态置 `已废弃` 但**不删行**），又有分册内条文（`common.md` 恒叠加、作废条目不删），双重占用。

经对四个接入方仓库实测（读面行数 80–573，本仓 111），确认 v2 的四个缺陷：

- **D1**：`common.md` 恒叠加，巨型 common 项目（某接入方仓库 428 行）token 收益被淹没——三分区只缩 `index.md` 对该项目仅约 4.5%；
- **D2**：作废行滞留常驻面（某接入方仓库 C-3 实证）；
- **D3**：无「生效范围」的结构化加载维度（只能按端）；
- **D4**：`scope` 多值语法分裂（`+` 与 `/` 混用）；
- **D7**：`conventions-spec.md` §8 明文「作废不删分册条目」与实践冲突（某接入方仓库实测作废条目的分册小节**确已删除**）。

## 目标

1. 载体升 **v3 三分区**，把「废弃即迁出」落为机制，使常驻与按需读面**只含活跃条文**；
2. 补 **Z2 按需裁剪**维度（分类标签分册），让 `common.md` 巨型项目能按标签下沉、按 `scope` 命中片加载；
3. 收敛载体纪律（`scope` 多值统一 `+`、`history` ID 统一 `C-n`、来源列格式归一）；
4. 补 Windows 以外平台兼容性缺口（macOS CI job、路径归一口径统一、`.gitattributes`）。
