# 载体升级路线规则与检测缺口补齐

> 来源链：延续 `20261016-唐启云-载体表头归一与形态防漂移`（见 archive/202610/20261016.md）——该任务把三表表头由列名常量单源派生、补「残留 v2 列 / 表头首格非 ID」检测；本次在同一主题上继续排查「升级路线与规则完整性」，补齐剩余 6 处「规则 ↔ 检测」不对称与措辞边界缺口。

## 背景

对「所有新老规范是否都有完整的升级路线和规则」做全覆盖盘点，确认主干完整：v0 旧单文件 `conventions.md` → v1（手工三段式，§10.1）、v1 → v2 → v3 与 v2 → v3（`upgrade` 链式，§10.2 / §10.3）、v3 幂等、abnormal 拒绝自动处理、形态残留软告警、入口壳落后由 `init` 就地重写。

排查同时暴露 6 处不对称，A–C 为「规则明写、自动检测未覆盖」（违背 C-28：规则可自动检出却缺检测入口须同批补），D–F 为措辞 / 边界缺口：

- **A 索引表列集合**：spec §2.2 定义 v3 五列、§12 只说「不含两列」，但 `checkTableShape` / `validateTableShape` 只检残留 v2 两列——缺列 / 次序不符检测不到；缺「归属」列时 `checkIndex` 因 `ownerIdx !== -1` 静默跳过归属校验。
- **B history / retired 表头**：§12 写明完整表头，检测只查首格是否 `ID`，中间列偏离不可见。
- **C 表头列数 vs 分隔行列数脱节**：无任何校验（S1 已修工具自身写入侧，手写表格仍无兜底）。
- **D §10.2 step2「首行补标记」未指明补哪个版本**（`upgrade` 链式直达 v3，手工迁 v2 应写 `v2`）。

# 规范载体v3三分区与跨平台补强

> 来源链：延续 `20260916-唐启云-规范载体目录化与端分类`（`.tasks/conventions.md` 单文件 → 目录形态，确立端分类与读取分层）与 `20260926-唐启云-规范载体v2与入口壳`（v1 → v2：稳定 ID `C-<n>`、`history.md` 独立、入口壳），本次把载体由 v2 升到 **v3 三分区**，并补齐 Windows 以外平台的兼容性缺口。

## 背景

用户真实诉求：**减少任务开始时「常驻读取」的 token 与上下文占用**。当前 v2 载体的痛点是「规范已作废，AI 每次开工仍读到废弃条目」——既有索引行（状态置 `已废弃` 但**不删行**），又有分册内条文（`common.md` 恒叠加、作废条目不删），双重占用。

经对四个接入方仓库实测（读面行数 80–573，本仓 111），确认 v2 的四个缺陷：

- **D1**：`common.md` 恒叠加，巨型 common 项目（某接入方仓库 428 行）token 收益被淹没——三分区只缩 `index.md` 对该项目仅约 4.5%；
- **D2**：作废行滞留常驻面（某接入方仓库 C-3 实证）；
- **D3**：无「生效范围」的结构化加载维度（只能按端）；
- **D4**：`scope` 多值语法分裂（`+` 与 `/` 混用）；
- **D7**：`conventions-spec.md` §8 明文「作废不删分册条目」与实践冲突（某接入方仓库实测作废条目的分册小节**确已删除**）。

## 目标

1. 载体升 **v3 三分区**，把「废弃即迁出」落为机制，使常驻与按需读面**只含活跃条文**；
2. 补 **Z2 按需裁剪**维度（分类标签分册），让 `common.md` 巨型项目能按标签下沉、按 `scope` 命中片加载；
3. 收敛载体纪律（`scope` 多值统一 `+`、`history` ID 统一 `C-n`、来源列格式归一）；
4. 补 Windows 以外平台兼容性缺口（macOS CI job、路径归一口径统一、`.gitattributes`）。

## 实施方案

### T1 治理本体（v3 三分区）

**分区模型**

- **Z1 常驻**（`index.md`）：列改为 `ID | 规则 | 当前语义 | 归属 | 单一事实源`——删「状态」「确立来源任务」两列（状态恒为活跃故无信息量；来源任务交 git 与 Z3 承载）；
- **Z2 按需**（`common.md` / `<端名>.md` / `<分类标签>.md`）：恒叠加 common + 按 `scope` 命中；分类标签若存在同名分册则加载，否则静默跳过；
- **Z3 归档**（`history.md` + 新增 `retired.md`）：`retired.md` 承载已退休条目，列 `ID | 规则 | 退休时语义（冻结） | 归属 | 后继 | 退休来源任务 | 条文去向`。

**7 条不变量**：I1 同一条目不得同时在 Z1/Z2 与 Z3；I2 Z1 只含活跃；I3 Z2 只含活跃条文；I4 条文只存一处；I5 ID 永不回收复用；I6 Z1 当前语义是活的、Z3 冻结语义是死的；I7 凡会被读到的位置不含废弃正文。

**三层清理**（作废即执行）：① 索引层——行迁入 `retired.md`；② 载体分册层——物理删除分册内该条小节；③ 外部单一事实源层——删 / 改 AGENTS / docs / skills 中该条条文。

**元原则**：载体新增的任何字段、文件、表格，必须证明它不进常驻面，才允许引入。

**落地清单**

1. `skills/fxri-plan-to-task/references/conventions-spec.md`：§1 目录结构补 `retired.md`；§2.0 标记升 v3；§2.2 索引表改 5 列 + 新增 `retired.md` 结构与字段定义；§4 端名规则补分类标签分册；§5 读取判定改「分类标签命中同名分册则加载」+ 显式「retired/history 不进常驻读面」；§6 写作判定同步；§8 内容修订改「作废即迁出 Z1 + 三层清理」；§10 补 v2→v3 升级；§12 自查清单同步。
