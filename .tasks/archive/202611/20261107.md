# 补充 Trae Hook 的启用前置条件

## 背景

`docs/usage/agents.md` 的支持矩阵把 Trae 标为「已验证」，正文只写了「安装 Hook」与「开启采集」两步，读者会误以为 `usage hooks install` 之后即生效。实测与官方文档均表明还有一道前置：Trae 必须在 **设置 > Hooks** 里为全局 Hook 点「创建」并在安全警示中「启用」，否则即便 `~/.trae-cn/hooks.json` 存在也不会派发；且启用后需重启 Trae 或开新会话才重新加载。

本机现象可作为证据：Hook 已安装、采集已开启、命令手工执行可正常落盘，但数据目录始终未创建，`hooks status` 一直显示「已配置但尚未执行过」，直到在 Trae 面板启用并重启。

## 实施方案

1. `docs/usage/agents.md` 支持矩阵的 Trae 行：状态列补充「需在 Trae 设置 > Hooks 启用」。
2. 同页「安装与启用是两步」节补第三步（Trae 面板启用）与两条注意：运行方式须为「本地自动运行」（沙箱可能拦截写数据目录）；启用后需重启 Trae 或开新会话，历史会话不补录。

## 影响范围

- `docs/usage/agents.md`：矩阵状态与前置条件说明。
- 文档触达核对：`docs/cli/usage.md` 只描述命令行为、不承载各 Agent 的 IDE 侧前置，无触达；`docs/rules/usage.md` 与 skills 无触达；`docs/changelog.md` 为生成物不受影响。
- 属文档对其行为的结构性描述变更，按仓库质量门建 patch 变更集。

## 验证方式

- `pnpm verify`（构建、单测、文档一致性校验）。
- `toolkit tasks check` error / warn 均为 0。

## 完成情况

- `docs/usage/agents.md`：矩阵 Trae 行状态改为「已验证（需在 IDE 内启用）」；「安装与启用是两步」节新增「Trae：还需在 IDE 内启用」四条步骤与验证方式。
- `.changeset/usage-trae-hook-prereq.md`：patch 变更集。
