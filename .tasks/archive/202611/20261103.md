# skills --from 支持远程技能来源

## 背景

`--from` 目前只接受本地目录（`src/skills/source.ts` 的 `resolveLocalSource`），用户从远程技能内容仓安装必须先手工 clone，增加心智负担。目标是本地路径与远程地址同一条命令、同一套语义，不为远程单独造一套流程。

## 实施方案

1. 来源解析统一入口：本地路径沿用现有 `resolveLocalSource`；远程地址先落到本地缓存，再复用同一解析函数，保证三种来源形态（根 `SKILL.md`、`skills/*/SKILL.md`、`skills.json`）行为一致。
2. 支持的远程形态：
   - `https://`、`http://`、`ssh://`、`git@` 开头的 Git 地址；
   - `github:owner/repo` 简写，展开为对应 HTTPS 地址；
   - 可选 `#<ref>` 后缀指定分支、标签或提交，缺省用远端默认分支；
   - 同一地址的不同书写（结尾 `.git`、末尾斜杠、域名大小写、`github:` 简写与完整 HTTPS）规范化为同一来源标识，避免缓存两份、选择集出现两个来源；
   - 同一地址不同 ref 视为不同来源标识；不同地址解析出相同来源名时按重名冲突处理，提示用 `--save` 指定不同来源名。
3. 缓存与刷新：
   - 缓存目录 `~/.agents/.toolkit-sources/<来源标识>`，来源标识由规范化地址 + ref 派生；
   - 首次浅克隆，后续按需 `fetch` + 检出指定 ref；ref 为分支或标签时用 `clone --depth 1 --branch`，为提交 SHA 时改用 `init + fetch --depth 1 <sha>`（clone 不认任意 SHA）；
   - 缓存命中不重复下载；显式刷新由 `skills install` 的常规重跑触发，失败保留旧缓存并告警；
   - 来源名优先取来源内 `skills.json` 的 `name`，其次取仓库名；本地目录改名或 URL 写法变化不改变来源名，保证选择集按来源名保存时不漂移；
   - `sources remove` 只删登记与已装产物，不自动删缓存，避免误删同一地址其他 ref 的共享缓存；缓存不自动清理，文档给出缓存目录位置与手工清理方式；
   - 缓存写盘走临时目录 + 原子 rename，避免并发安装留下半成品；
   - 克隆 / 刷新在技能操作锁之外完成，只在写产物阶段持锁，避免网络耗时占锁导致锁被超时接管；
   - `--dry-run` 不写持久缓存；无缓存时用临时目录完成预演并在结束后清理，不为预演留下缓存副作用。
4. 登记与状态：
   - `--save` 永久来源记录远程地址与 ref，而非缓存绝对路径；零选择时仍登记来源，但不写选择集；
   - `sources` 配置兼容旧 `{ root }` 与新 `{ url, ref }`，旧配置继续可用；
   - `skills sources` 展示来源地址、ref、缓存状态；`--format json` 同步输出 `url` / `ref`，不输出缓存绝对路径；
   - 状态结构新增可选 `url` / `ref` 字段（不升 `schemaVersion`，旧状态无该字段仍合法）；远程来源在项目面写 `root: ""` + `url` / `ref`，不把本机缓存路径写入仓库内状态；
   - 临时 `--from` 来源不写 selection 与 sources 配置，避免配置里残留下次不生效的来源键；
   - 项目面 `status` 在本机无缓存时降级为只核对产物自身版本，不把「缓存缺失」报成解析失败。
5. 降级与安全：
   - 认证沿用本机 git 凭据，不读取、不存储令牌；
   - `http://` 明文传输允许但 stderr 告警，优先推荐 HTTPS / SSH；
   - 缓存目录权限跨平台处理：POSIX 下 `chmod 0700`；Windows 依赖用户目录默认 ACL，不强行 `chmod`；权限设置失败只告警不阻断；
   - 只读取 `SKILL.md`、`references/` 与 `skills.json`，不执行来源内脚本；
   - 文档明确提示只安装可信来源：技能正文会被 agent 读取，来源内容等同可执行指令面；
   - 克隆失败、ref 不存在、来源内未找到技能时按「降级不静默」告警或报错退出；
   - 远程来源与包内或其他来源存在同名技能时，沿用「同名冲突」判定，错误信息点明可用来源名限定，不自动裁决。
6. 文档同步：`docs/cli.md`、`docs/config.md`、`docs/guide.md`、`docs/faq.md`、`README.md`、`skills/README.md` 补远程来源用法与缓存说明，明确生产环境建议用 tag 锁定版本；`--from` 的 help 文案由 `<path>` 改为 `<path|url>`。

# changelog 文档镜像内置到 CLI

## 背景

镜像「根 `CHANGELOG.md` → 文档站更新页」的脚本目前由各项目自建。扫描工作区内 6 个仓库，每个都有一份 `scripts/sync-changelog-doc.mjs`，哈希各不相同、行数在 23–67 之间，已经出现实现漂移；还有仓库只有其中一侧文件。剥离 H1、拼页头、校验版本块属于通用能力，不应由每个使用者重复承担。

## 实施方案

1. 新增 `src/changelog/doc.ts`：
   - `buildDocPage(changelog, options)`：归一换行、剥离根文件 H1、拼页头（frontmatter + H1 + 来源说明）、校验至少一个 `## x.y.z` 版本块；
   - `syncDoc(options)`：写目标文件；`checkDoc(options)`：只比对，不一致时输出差异位置并以非 0 退出。
2. CLI 新增 `toolkit changelog doc` 子命令，在透传 changesets 之前拦截，避免被当作操作数。
3. 选项：`--check`、`--from <path>`、`--to <path>`、`--title <text>`、`--outline <n,n>`、`--no-frontmatter`；默认 `CHANGELOG.md` → `docs/changelog.md`。
4. 配置：新增 `changelogDoc` 段（`source` / `target` / `title` / `outline` / `frontmatter`），按项目层与全局层合并；非法值告警后回落默认。
5. 发版链路：`changelog version` 成功后自动同步镜像（根文件与目标目录存在时幂等执行），`--no-sync-doc` 关闭；无根 `CHANGELOG.md`、目标目录不存在或写入失败时只告警、不阻断发版。
6. 本仓迁移：删除 `scripts/sync-changelog-doc.mjs`，`package.json` 的 `sync:changelog-doc` 改为 `toolkit changelog doc`；`scripts/verify.mjs` 增加 `node dist/cli.js changelog doc --check` 步骤，放在「构建」之后（依赖 `dist/cli.js`）；`AGENTS.md` 发版链路与相关文档改用内置命令。

8. 错误口径：`changelog doc` 子命令不存在时（旧版 CLI）明确提示升级到 1.14.1+，与「镜像内容不一致」区分开，避免误报。
9. 默认页头与现有项目一致（`outline: [2, 2]` + `# 更新日志` + 来源说明），来源命令与文案可配置；生成物统一 LF；`--lang` 指定语言时按语言后缀定位源与目标文件，默认中文。
