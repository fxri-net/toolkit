# 技能安装支持纯包管理器模式

## 背景

当前 `core` 技能恒装且不可取消，用户无法把本工具只当技能包管理器使用。需要新增显式模式，让「一个技能都不预置」成为合法且可持久化的使用方式，同时保持默认模式行为不变。

## 实施方案

1. 模式定义：
   - `skills`（默认）：沿用现状，`core` 默认选中且不可取消；
   - `package`：纯包管理器，所有技能（含 core）均为普通可选项，允许零选择并持久化。
2. CLI：
   - `--mode skills|package`：先切换模式并持久化，再按新模式配置本次技能；切模式不以旧模式的保存选择作基线（`package` 基线为空、`skills` 基线为 core），想保留选择须在同一条命令显式传 `--skills`；
   - `--no-skills`：仅本次不安装任何技能，不改模式、不改保存选择；
   - `--no-skills` 与 `--skills` / `--all` / `--no-optional` / `--mode` 互斥，同时传入报错退出 1（`--mode package` 本身已表达本次零装）；
   - `--mode package` 与 `--all` 同时传时装全部技能，`--all` 优先于模式默认基线；
   - `--skills ""` 维持现状报错，并提示改用 `--no-skills`；
   - `--mode` 的写入层跟随 `--scope`：`global` 写全局层、`project` 写项目层、`all` 写两层；未传 `--scope` 时按现场判定；
   - `--yes` 或非 TTY 下 `package` 模式零选择时打印「纯包管理器模式：本次未安装任何技能」，退出码 0。
3. 配置：`skillsInstall.mode` 与 `projectSkills.mode` 写入全局层 / 项目层，非法值告警并按 `skills` 处理。
4. 选择算法：
   - `planSkillSelection` 接收模式，`package` 下不再强制并入 `core`，零选择合法；
   - TTY 交互在 `package` 下默认全不选且 core 可取消，`skills` 下保持 core 不可取消；
   - 全链路区分「已保存为空数组」与「未保存」：`cli.ts`、`config.ts`、`status.ts` 中所有 `selection.length > 0` 判断改为 `!== undefined`；
   - 传入 `--mode` 时 `resolveSkillSelection` 忽略旧 saved，显式按新模式基线解析。
5. 安装与状态：
   - 零选择时仍执行 `--prune` 清理旧产物，再写状态；输出「未选择任何技能」；
   - `installSkills` / `installProjectSkills` 新增 `saveSelection` 开关：`--no-skills` 传 `false`，跳过现有的无条件 `saveGlobalSelection` / `saveProjectSelection`，避免一次性空装被写成持久配置；
   - 从 `skills` 切到 `package` 不自动删除旧产物，`status` 将其报为「未选择但已安装」并提示 `--prune`；
   - `status` / `install` 报告增加模式字段与「纯包管理器」人读文案；两者的 `--format json` 同步增加模式字段，零选择时 `selection` 为空数组，文档与测试一并更新；
   - `init` 生成的规范入口壳与技能选择无关，`package` 模式下仍照常生成；技能入口薄壳由 `install --scope project` 生成，零选择时不生成、不写 `.toolkit/state.json`；
   - `prepare` 钩子在 `package` 模式触发零选择安装时退出码 0，只提示，不阻断 `pnpm install`。
6. 文档同步：`docs/cli.md`、`docs/config.md`、`docs/guide.md`、`docs/handbook.md`、`docs/faq.md`、`docs/getting-started.md`、`README.md`、`skills/README.md`。

## 20261103-唐启云-skills远程来源支持

# skills --from 支持远程技能来源

## 背景

`--from` 目前只接受本地目录（`src/skills/source.ts` 的 `resolveLocalSource`），用户从远程技能内容仓安装必须先手工 clone，增加心智负担。目标是本地路径与远程地址同一条命令、同一套语义，不为远程单独造一套流程。

## 实施方案

1. 来源解析统一入口：本地路径沿用现有 `resolveLocalSource`；远程地址先落到本地缓存，再复用同一解析函数，保证三种来源形态（根 `SKILL.md`、`skills/*/SKILL.md`、`skills.json`）行为一致。
2. 支持的远程形态：
   - `https://`、`http://`、`ssh://`、`git@` 开头的 Git 地址；
   - `github:owner/repo` 简写，展开为对应 HTTPS 地址；
   - 可选 `#<ref>` 后缀指定分支、标签或提交，缺省用远端默认分支；
   - 同一地址的不同书写（结尾 `.git`、末尾斜杠、域名大小写、`github:` 简写与完整 HTTPS）规范化为同一来源标识，避免缓存两份、选择集出现两个来源；
   - 同一地址不同 ref 视为不同来源标识；不同地址解析出相同来源名时按重名冲突处理，提示用 `--save` 指定不同来源名。
3. 缓存与刷新：
   - 缓存目录 `~/.agents/.toolkit-sources/<来源标识>`，来源标识由规范化地址 + ref 派生；
   - 首次浅克隆，后续按需 `fetch` + 检出指定 ref；ref 为分支或标签时用 `clone --depth 1 --branch`，为提交 SHA 时改用 `init + fetch --depth 1 <sha>`（clone 不认任意 SHA）；
   - 缓存命中不重复下载；显式刷新由 `skills install` 的常规重跑触发，失败保留旧缓存并告警；
   - 来源名优先取来源内 `skills.json` 的 `name`，其次取仓库名；本地目录改名或 URL 写法变化不改变来源名，保证选择集按来源名保存时不漂移；
   - `sources remove` 只删登记与已装产物，不自动删缓存，避免误删同一地址其他 ref 的共享缓存；缓存不自动清理，文档给出缓存目录位置与手工清理方式；
   - 缓存写盘走临时目录 + 原子 rename，避免并发安装留下半成品；
   - 克隆 / 刷新在技能操作锁之外完成，只在写产物阶段持锁，避免网络耗时占锁导致锁被超时接管；
   - `--dry-run` 不写持久缓存；无缓存时用临时目录完成预演并在结束后清理，不为预演留下缓存副作用。
4. 登记与状态：
   - `--save` 永久来源记录远程地址与 ref，而非缓存绝对路径；零选择时仍登记来源，但不写选择集；
   - `sources` 配置兼容旧 `{ root }` 与新 `{ url, ref }`，旧配置继续可用；
   - `skills sources` 展示来源地址、ref、缓存状态；`--format json` 同步输出 `url` / `ref`，不输出缓存绝对路径；
   - 状态结构新增可选 `url` / `ref` 字段（不升 `schemaVersion`，旧状态无该字段仍合法）；远程来源在项目面写 `root: ""` + `url` / `ref`，不把本机缓存路径写入仓库内状态；
   - 临时 `--from` 来源不写 selection 与 sources 配置，避免配置里残留下次不生效的来源键；
   - 项目面 `status` 在本机无缓存时降级为只核对产物自身版本，不把「缓存缺失」报成解析失败。
5. 降级与安全：
   - 认证沿用本机 git 凭据，不读取、不存储令牌；
   - `http://` 明文传输允许但 stderr 告警，优先推荐 HTTPS / SSH；
   - 缓存目录权限跨平台处理：POSIX 下 `chmod 0700`；Windows 依赖用户目录默认 ACL，不强行 `chmod`；权限设置失败只告警不阻断；
   - 只读取 `SKILL.md`、`references/` 与 `skills.json`，不执行来源内脚本；
   - 文档明确提示只安装可信来源：技能正文会被 agent 读取，来源内容等同可执行指令面；
   - 克隆失败、ref 不存在、来源内未找到技能时按「降级不静默」告警或报错退出；
   - 远程来源与包内或其他来源存在同名技能时，沿用「同名冲突」判定，错误信息点明可用来源名限定，不自动裁决。
6. 文档同步：`docs/cli.md`、`docs/config.md`、`docs/guide.md`、`docs/faq.md`、`README.md`、`skills/README.md` 补远程来源用法与缓存说明，明确生产环境建议用 tag 锁定版本；`--from` 的 help 文案由 `<path>` 改为 `<path|url>`。

## 影响范围

`src/skills/source.ts`、`src/skills/types.ts`、`src/skills/install.ts`、`src/skills/config.ts`、`src/skills/state.ts`、`src/skills/status.ts`、`src/cli.ts`、`src/__tests__/skills-remote.test.ts`（新建）、`docs/cli.md`、`docs/config.md`、`docs/guide.md`、`.changeset/`。

## 验证方式

- `pnpm verify` 全绿；
- 手工矩阵：本地目录回归、HTTPS 来源、`github:` 简写、`#ref` 指定、缓存命中、刷新失败保留旧缓存、来源不可达报错、`--save` 后 `sources` 展示地址；
- 切换 `#ref` 后旧产物不被 `--prune` 误删（内容已与新真源不一致），`status` 如实报漂移或「未选择但已安装」，文档给出 `remove --source` 清理路径；
- 明确验证不把缓存绝对路径写入项目面状态文件。
