前两轮清理把「该怎么执行」也写死成技能自己的规定：删掉「按仓库发版链路发布」、把归档指定为唯一命令、禁止复核技能写入任务档。方向错了——技能只应规定**必须达成的结果**，执行方式让位于**仓库既有约定与用户确认**；只有「必须依赖另一技能安装才能继续」才算硬依赖，需内联兜底。

## 实施方案

1. `skills/fxri-writing-docs/SKILL.md` 第 5 步：恢复为「记录 patch 变更集，按仓库发版链路发布（写法与 bump 判定见 `fxri-release-changelog`）」。
2. `skills/fxri-release-changelog/SKILL.md` 前置检查：「先执行 `toolkit task archive`」改为「发版前任务必须已归档，归档方式以仓库约定为准，无约定时用 `toolkit task archive`」；覆盖核对同口径。
3. `skills/fxri-plan-review/SKILL.md`：`直接落档` 恢复可直接写入——边界改为「不改用户已确认的目标与范围」，允许修正实施方案 / 拆分 / 验收 / 计划表，写入方式按仓库既有落档流程（`fxri-plan-task` 的 task 命令可直接用）；L68 改为「用户明确接受后只应用 `直接落档` 项」；L71 恢复「写入前后列出所改文件与摘要，禁止静默改用户内容」；L86 改为「不在用户未确认时改任务文件，也不代替建档」。
4. `references` 同步：`review-checklist.md` 第四节的「交给落档流程 / 本技能不写任务文件」与 `trigger-examples.md` 的同类表述改为与 SKILL 一致。
5. 三个技能 patch 升版（`fxri-plan-review`、`fxri-release-changelog`、`fxri-writing-docs`），`skill bump --sync-tables` 同步两张技能表。
6. 变更集不新建：按净变更改写 `.changeset/skill-no-cross-deps.md`。
