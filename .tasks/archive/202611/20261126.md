## 实施方案

### 1. 数据模型与目录

- 项目回收站：`<项目根>/.toolkit/trash/<时间戳>-<随机后缀>/`
- 全局回收站：`~/.toolkit/trash/<时间戳>-<随机后缀>/`
- 每个条目目录包含：
  - `manifest.json`：`schemaVersion: 1`、`id`、`createdAt`、`command`、`scope`、`root`、`entries[]`、`status`
  - `entries[]`：`path`（相对 `root`）、`kind`（file / dir / link）、`size`、`sha256`（文件）、`linkTarget`（链接）
  - `items/`：实际移动进来的文件 / 目录；链接只记录目标，不复制内容
- `id` 用 `YYYYMMDD-HHmmss-<6 位随机>`，字典序即时间序，`restore latest` 取最新一条。

### 2. 移动与恢复语义

- 移动前先做路径校验（复用安全删除基础设施的根约束），拒绝根目录、home、`AppData`、`Windows`、`Program Files` 本身。
- 普通文件 / 目录：优先 `rename` 到 `items/`（同卷原子）；跨卷时复制到回收站、校验大小与哈希后再删源，任一步失败都保留源并回滚半截副本。
- 符号链接 / junction：只 `unlink` 链接本身，记录 `linkTarget`，不复制目标内容；避免把真实目标搬走。
- 恢复：按 `manifest` 逆序还原到 `root + path`；目标已存在时默认跳过，`--overwrite` 才覆盖；覆盖前先把现有目标再收进回收站，避免二次误删。
- 部分恢复失败时保留条目与剩余文件，`status` 标记 `partial`，不静默丢弃。
- 全部恢复成功后删除该条目目录；`trash prune` 负责彻底清理剩余条目。

### 3. CLI 契约

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `toolkit trash` / `toolkit trash list` | `--scope project / global / all`（缺省 all）、`--command <name>`、`--older-than <days>`、`--format json` | 列出条目：id / 时间 / 来源命令 / 条目数 / 占用；按时间倒序；多个过滤条件取交集 |
| `toolkit trash restore [id]` | `--scope`、`--to <dir>`、`--overwrite`、`--dry-run`、`--format json` | 省略 id 取 `latest`；`--to` 把目标根替换为指定目录，路径仍按 `entry.path` 保留结构 |
| `toolkit trash prune` | `--scope`、`--keep <n>` / `--older-than <days>` / `--all` 三选一、`--dry-run`、`--yes`、`--format json` | 未指定选择器时报用法错误；非 TTY 执行需 `--yes`；`--dry-run` 只预览 |
| `toolkit trash stats` | `--scope`、`--format json` | 只读统计：条数、占用、最旧 / 最新时间、按来源命令分布 |

- `prune` 的 `--scope` 缺省：项目内只清项目、home 下只清全局；`--scope all` 才跨面，和 `upgrade --prune-backups` 的缺省口径一致。
- `--keep` 只作用于每个回收站根，保留最近 n 条；`--older-than` 按自然日计算；两者同时出现按参数冲突退出 1。
- `list --command <name>` 精确匹配 `manifest.command`（如 `skill uninstall`）；`list --older-than <days>` 与 `prune --older-than` 语义一致；多个过滤条件取交集。
- `stats` 只读，退出码恒 0；`--format json` 的 `data` 含 `entries / bytes / oldest / newest / byCommand`。
- `restore --to <dir>` 把目标根替换为 `<dir>`，仍按 `manifest.entries[].path` 保留结构；目标根须通过安全删除的路径校验，拒绝根目录、home、`AppData`、`Windows`、`Program Files` 本身；`--to` 与 `--overwrite` 可组合。
- `--no-trash` 只出现在用户可见的删除命令上：`skill uninstall`、`skill install --prune`、`upgrade --prune-backups`、`upgrade --restore`。

# 新增安全删除基础设施

第 1 个（共 5 个执行任务）；前置：无；后继：加固破坏性操作约束、新增项目内回收站

## 背景

本轮环境排查发现：仓库内多处递归删除直接使用 `rmSync(..., { recursive: true })`，删除目标来自可被仓库文件或用户配置影响的数据——技能状态账本（`.toolkit/state.json`、`~/.agents/.toolkit-skills.json`）与迁移备份清单（`manifest.json`）。这些路径未做根目录约束与单段名校验，存在越界删除风险；一旦状态或清单被篡改 / 损坏，可能删除仓库或家目录之外的文件。

本次尚未发现代码路径能解释本机 `.ssh`、浏览器配置与 WSL 磁盘的丢失，但该风险必须收敛，避免「删除用户文件」级别的事故。

## 实施方案

1. 新增 `src/safe-remove.ts`：
   - `assertWithinRoot(target, root, label)`：`resolve` 后必须位于 `root` 内；同时拒绝文件系统根、家目录、`AppData`、`Windows`、`Program Files` 作为删除目标；
   - `safeRemoveArtifact` / `safeRemoveEmptyDir` / `safeRemoveFile`：统一入口，越界或失败时告警并返回 `false`，不静默；
   - 递归删除增加两项硬约束：目标不得等于允许根本身；路径不得经 `..` 逃逸。
2. 技能状态校验（`src/skills/state.ts`）：
   - 项目态 `target.dir` 必须位于项目根内；全局态允许 `--dir` 自定义目标，但必须是绝对路径，且不得是根 / home / `AppData` / `Windows` / `Program Files` 本身；
   - `entry.name` 必须是单段名（非空、不含 `/`、`\`、`.`、`..`），确保 `join(target.dir, entry.name)` 不会逃出目标目录；

3. 新增 `toolkit upgrade --drop-legacy`：新段已存在时删除旧段（旧段本就不生效），`--dry-run` / `--diff` 可预览；仅显式传参时生效，不替用户取舍。`detect`、`planConfigContent` 与 diff 共用同一开关。

# 修复项目作用域误判与配置越层写入

> 计划位置：第 1 个（共 3 个）；前置：无；后继：20261126-唐启云-修复迁移残留死循环并支持旧段一键处置

## 背景

用户在 Linux 家目录（`/home/<user>`）执行 `toolkit setup` 与 `toolkit upgrade` 后，每次命令都重复告警旧段名，`toolkit upgrade` 反复列出同一批「可自动处理」项却迁不动。根因之一是家目录被当成项目根：

- `detectSkillScope` 按向上找到的 `package.json` 与全局包目录包含关系判定，家目录存在 `package.json` 即判项目面；
- 项目面安装以 `cwd` 为 root，在家目录写出 `.agents/skills`、`.codebuddy/skills`、`.toolkit/state.json`，其中 `.agents/skills` 与全局面 canonical 目录同址；
- `writeProjectSkillsConfig` 在项目层未命中时回落到 `cwd/.toolkitrc.json`，把 `projectSkill` 写进全局层文件 `~/.toolkitrc.json`，下次读取即告警「仅支持项目层」；
- `upgrade` 在家目录同时产出 `config:global` 与 `config:project` 两条指向同一文件的迁移项，`checkVersionGate` 只看 cwd 的 `package.json`，只迁全局层也会被版本门禁拦下；
- 项目面只读与清理同样以 home 为项目根：日志中 `skill:project` 从 `/home/<user>/.toolkit/state.json` 清理旧技能，`skill status --scope project` / `uninstall --scope project` 也会读、清 home 下的项目产物。

## 实施方案

1. 新增家目录边界判定（`src/scope/paths.ts`，复用 `src/config.ts` 既有 stopAtHome 口径）：以「cwd 到 home（不含 home）」之间是否存在项目标志（`.git` / `.tasks` / `package.json`）为项目判据；home 自身及其上不作为项目标志。保留「cwd 位于 toolkit 包内 → 全局」的既有特例。
2. `src/skills/source/targets.ts`：`detectSkillScope` 改用上述判定，无项目标志返回 `global`；保持「全局 CLI 在项目目录内 → project」的现有语义。
3. `src/skills/install/project.ts`：项目面安装前校验 root 不得为 home（取磁盘真实形态比较），否则报错并以非 0 退出，提示「进入仓库后重试，或改用 `--scope global`」；不静默降级。
4. `src/skills/config.ts`：`writeProjectSkillsConfig` 的目标文件等于全局配置文件时抛错（含路径与改用 `--scope global` 的提示），由调用方告警；`src/commands/config.ts` 的 project / local 写入同口径拒绝，只读定位不受影响。
5. `src/upgrade/detect.ts`：非项目环境下不生成 project / local 面迁移项；`config:global` 与 `config:project` 指向同一文件时只保留一条。`src/upgrade/index.ts`：`checkVersionGate` 仅当计划含项目层项时生效。
6. 项目面只读与清理同口径：`skill status --scope project`、`skill uninstall --scope project` 与 `upgrade` 的 `skill:project` 检测在 home 边界按非项目处理，不读取、不清理 home 下的 `.toolkit/state.json` 与技能产物；判定收敛到步骤 1 的同一函数，状态展示注明「家目录不作为项目根」。
7. 触达面与变更集：以 `scripts/touch-surface.mjs` 输出为单源逐篇核对「自动判定 / 项目面 / 全局层」措辞并标注结论；skills 逐篇确认（预计无触达）；`.tasks/conventions/index.md` 对应行核对无语义变更；变更集按发版技能判定（预计 patch，类型「修复」）。
