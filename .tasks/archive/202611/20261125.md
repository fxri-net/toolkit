> 计划位置：第 1 个（共 2 个）；前置：无；后继：20261125-唐启云-技能补bump判定例子

## 背景

查 GitHub 官方 runner 参考页确认：`macos-latest` 现映射到 arm64（3 核 M1）镜像，Intel 标签只剩 `macos-15-intel` / `macos-26-intel`，`macos-13` 已下线。arm64 容量紧张时 job 会一直排队直到超时。

1. macos job 的 `runs-on` 由 `macos-latest` 改为 `macos-15-intel`，注释说明原因与「大小写不敏感文件系统回归在 Intel 同样成立」。
2. artifact 两动作升级到最小的 Node 24 版本：`upload-artifact@v6`、`download-artifact@v7`；用法（`name` / `path` / `retention-days`、按 name 下载）不变，不引入 v7 / v8 的行为变更。
3. 不改其余 job、不改 `pnpm verify` 步骤清单。

## 验证方式

# bump自动归一历史块

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

每次发版后 `docs/changelog/1.x.md` 都会出现 7 处空行，随后又要跑 `release changelog --history` 回退，形成固定抖动。

隔离实验（临时 worktree，验完删除）确认根因：`@changesets/cli` 写入 CHANGELOG 时会重排整个文件，把「父条目 + 缩进子项」序列化成松散列表（条目之间插空行）；本仓默认格式化不动历史块（幂等，无缺陷），`--history` 能把空行精确删回。问题在 `release bump` 的工序顺序：先镜像、后归一，中间态被写进归档页。

技能把成因写成「人工润色留空行」，与实际不符。

## 实施方案

1. `src/commands/release.ts` 的 `runChangelogBump` 改为以 `history=true` 格式化，历史上在镜像前完成归一；`bump --history` 保留为兼容参数（help 注明已默认归一）。
2. `AGENTS.md` 发版链路第 1 步改写：bump 自动归一后再镜像；润色改动条目间距时再补 `--history` + 镜像。
3. `docs/cli/release.md` 同步 bump 说明、示例与 `--history` 选项表。
4. `skills/fxri-release-changelog`（1.4.0 → 1.4.1）修正空行成因、失败模式与 `references/changelog-format.md` 的不动点说明；同步 `skills/README.md` 与 `docs/guide.md` 的版本列。
5. 补 patch 变更集，随本次发版一起消费。
