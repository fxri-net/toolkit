用户在 `.gitignore` 里用 `!` 显式取消忽略某个本工具守护的文件（如 `!.toolkitrc.local.json`）时，`task init` 仍会把该行写回片段。因片段位于否定行之前，否定最终生效、功能无影响，但每次重跑都会保留一行无效规则，属噪声。

## 实施方案

1. `src/git-ignore.ts` 增 `lastIgnoreRule(lines, relPath)`：返回最后命中该路径的规则行（含 `!` 前缀），无命中返回 `null`；`isIgnoredByRules` 改为复用它。
2. `src/tasks/init.ts`：
   - 目标被用户显式否定（片段之外最后命中的规则以 `!` 开头）时视为「用户不要忽略」；
   - 整组目标都被否定时，该组既不补写、也不从片段内保留，重建时直接省略；
   - 片段内原有该组行时同样触发重建（把它删掉），否则走保持分支。

> 计划位置：第 1 个（共 2 个）；前置：无；后继：20261125-唐启云-技能补bump判定例子

## 背景

GitHub Actions 连续两轮失败/卡死均只发生在 macos job：CI #130（`5836f5b`）报 `The job was not acquired by Runner of type hosted even after multiple attempts`，CI #131（`702ea79`）的 macos 一直 `Waiting for a runner to pick up this job`，其余 job 全过。

查 GitHub 官方 runner 参考页确认：`macos-latest` 现映射到 arm64（3 核 M1）镜像，Intel 标签只剩 `macos-15-intel` / `macos-26-intel`，`macos-13` 已下线。arm64 容量紧张时 job 会一直排队直到超时。

2. artifact 两动作升级到最小的 Node 24 版本：`upload-artifact@v6`、`download-artifact@v7`；用法（`name` / `path` / `retention-days`、按 name 下载）不变，不引入 v7 / v8 的行为变更。
3. 不改其余 job、不改 `pnpm verify` 步骤清单。

- 文档：无触达（`docs/` 不描述 CI 内部步骤；`AGENTS.md` 只要求不另写步骤枚举，本次遵守）。
- 变更集：无（CI 配置不随包分发）。

## 验证方式

1. 推送后看新一轮 CI：macos job 应在数分钟内被 `macos-15-intel` 接管并完成，其余 job 保持通过。
2. 本地无需额外验证（workflow 语法由 GitHub 解析）。
