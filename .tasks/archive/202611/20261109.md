## 背景

跨项目建档时出现「任务文件名整串英文 slug、归档块标题随文件名固化」的问题，复盘出三层根因：

1. 规范只约束「任务简述 = 不含空格的短语」，任何语种的 slug 都合规；`SPEC.md` §2.1 的「建议团队统一语言」是不可判定的建议，无法进门禁。
2. 唯一键 `{YYYYMMDD}-{用户名}-{任务简述}` 的三段只有日期与 `created` 有比对（`src/tasks/validate.ts` L260-L265），用户名段未比对 `owner`、简述段未比对正文 H1，机器看不见「英文 slug」「归属人写错」这两类问题。
3. `src/tasks/archive.ts` 直接以文件名作归档块标题，错误在归档时被固化为冻结记录，事后改名要连带改 `depends_on`、档间引用与归档块。

工具自身已有正确实现（`src/tasks/import.ts` L185-L190 的 `slugTitle` 从标题派生名字），但只在导入路径生效，人工/AI 建档是自由命名，两条路径口径不一。本次把「派生规则」提升为单一真源并落到校验。

## 实施方案

1. 新建 `src/tasks/name.ts`：导出 `taskBrief(title)` 与 `briefMatchesTitle(brief, title)`。
   - `taskBrief`：NFC 归一 → 去掉跨平台非法字符（`\ / : * ? " < > |`）与控制字符 → 空白折叠为 `-` → 截断 24 字符 → 去首尾点与空格。
   - `briefMatchesTitle`：两侧归一（NFC、小写折叠、去空白/连字符/标点）后判定简述是否为标题子串（截断即前缀）；不满足时按字符覆盖率兜底。
2. `src/tasks/import.ts` 的 `slugTitle` 改为调用 `taskBrief`，消除双实现。
3. `src/tasks/validate.ts` 新增软告警（均为 warn，不阻断）：
   - 文件名简述与正文 H1 不同源；文件名含跨平台非法字符 / Windows 保留设备名 / 超长 / 未 NFC 归一；
   - 文件名用户名段与 frontmatter `owner` 不一致。
4. `src/tasks/archive.ts` 固化前提示：命中不同源判据时追加 warn（说明归档块标题将随文件名固化），不阻断归档。
5. 规范与文案改写：

定稿口径（第 5、6 步照此措辞落地）：

> 任务简述由正文 `# 标题` 派生：NFC 归一、替换跨平台非法字符、空白折叠为 `-`、截断至 24 字符；不翻译、不音译、不缩写。校验判据为「归一后简述是标题的子串（截断场景即前缀）」，不绑定语种。文件名三段各对真源负责：日期↔`created`、用户名↔`owner`、简述↔标题。校验发生在归档前，归档块标题随文件名固化后不再改。

不做的事：不新增命令、不自动改名（改名牵连 `depends_on`、档间引用与归档块标题，属人工决策），与「只报不改、`normalize --fix` 只管归档块」的既有边界一致。
