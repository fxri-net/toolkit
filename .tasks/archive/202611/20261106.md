# 遥测初始化与 Hook 接入

- 计划位置：toolkit 3 / 5；前置：遥测内核与本地统计

## 背景

遥测内核提供配置、事件、存储与统计能力后，需要让用户用一条命令完成启用，并把 Agent 的工具调用事件接进来。Hook 必须是事件驱动的短进程，默认不安装、不启用，安装与采集分离授权。

## 实施方案

1. 适配器接口与首批实现
   - `src/telemetry/adapters/types.ts`：`AgentAdapter` 接口（`detect` / `installHooks` / `uninstallHooks` / `parseHookEvent`）。
   - `trae`：读写 `%USERPROFILE%/.trae-cn/hooks.json`（或 `~/.trae/hooks.json`），注册 `PostToolUse` 与 `UserPromptSubmit` 命令。
   - `claude`：读写 `~/.claude/settings.json` 的 `hooks` 段，注册 `PostToolUse` 与 `UserPromptSubmit`。
   - Hook 命令写入当前 CLI 的绝对路径（`node <cli> telemetry ingest --agent <id>`），避免依赖 PATH。
2. Hook 安装器
   - `install` 前备份原配置，写前展示 diff；`--dry-run` 只预览。
   - 配置无法解析时不覆盖，报错退出。
   - `status` 展示已安装命令、配置路径与最近触发时间；`uninstall` 从备份恢复或精确移除本包命令。
3. 初始化向导
   - `toolkit telemetry init`：检测 Agent 与技能 → 预设（默认保持关闭 / 推荐 / 一方+第三方 / 自定义 / 高级）→ 选择 Agent → 范围与字段 → 存储 → 预览 diff → 应用。
   - 任意步骤取消不落盘；所有写操作先备份、原子写入。
   - `toolkit telemetry` 无参数进入交互菜单：状态、统计、开关、Hook、上传、导出清理、退出。
   - 非 TTY 且未给参数时打印用法并以退出码 2 结束，不悬挂等待输入。
4. Hook 事件入口
   - `toolkit telemetry ingest --agent <id>`：从 stdin 读取 Hook 载荷，解析后写入本地事件存储；未启用时直接退出、不写文件。
   - Prompt 缓存：`UserPromptSubmit` 写入 `state/sessions/<hash>.json`，`PostToolUse` 读取并作为触发词来源。
5. 全局规则
   - `src/telemetry/rule.ts` 输出固定文案；`docs/telemetry/global-rule.md` 提供可复制代码块；`toolkit telemetry rule print` 打印同一份文本。
   - 不自动修改用户全局规则文件。

# 遥测内核与本地统计

- 计划位置：toolkit 2 / 5；前置：变更集净变更规则（按计划顺序）

## 背景

需要回答「某个技能用了多少次、在哪个会话、由哪句话触发」，人工统计不可靠。内核负责配置、事件模型、过滤、本地存储、去重与统计；默认全部关闭，数据只留在本机。

## 实施方案

1. 配置（`src/telemetry/config.ts`）
   - `telemetry` 段只读全局层 `~/.toolkitrc.json`；项目层 / 本地层误写只告警、不生效。
   - 默认值：`enabled=false`；`agents` 全空；三来源开关全 `false`；`skills.mode=none`；`capture` 三项全 `false`；`storage.rotation=monthly`、`retentionDays=180`；`upload.enabled=false`。
   - 数据目录覆盖顺序：`--dir` > `TOOLKIT_TELEMETRY_DIR` > `storage.dir` > `~/.toolkit/telemetry`。
   - 配置写入提供 `updateTelemetryConfig`：只改全局层、保留其它段、原子写、非法 JSON 不覆盖。
2. 事件模型（`src/telemetry/event.ts`）
   - `schemaVersion=1`；字段：`eventId / occurredAt / agent / sessionId / toolUseId / project / skill / skillVersion / skillSource / managedBy / triggerPrompt / skillArgs / outcome / durationMs / originAdapter / toolkitVersion`。
   - `eventId` 由 `agent + sessionId + toolUseId` 计算；缺少 `toolUseId` 时用 `sessionId + skill + 2 秒窗口`。
   - 技能识别：`Skill` 工具取 `name`；`Read` 读取 `skills/<name>/SKILL.md` 时反推；其余返回空。
   - 技能元数据：包内 `listPackageSkills()` 判一方；技能状态登记的非 toolkit 来源判第三方；其余为未托管 / 未知。
3. 过滤链（`src/telemetry/filter.ts`）
   - 顺序：总开关 → Agent 开关 → 来源开关 → 技能模式 → 字段开关；任一步不通过即不落盘。
   - 技能模式：`none / all / include / exclude`；`include` 空列表等同 `none`。
4. 存储与去重（`src/telemetry/store.ts`、`src/telemetry/index-store.ts`）
   - JSONL 追加写：`events/YYYY-MM.jsonl`（按月）、`events.jsonl`（不轮转）、`YYYY-MM.N.jsonl`（按大小）。
   - `index.json` 保存已写入 `eventId` 与会话摘要；写入前查重，命中即丢弃。
   - 单行小于 4KB；目录自动创建；轮转、保留期、`purge` 可配置。
   - 索引是可重建读模型，损坏时 `doctor` 提示重建。
5. 统计与导出（`src/telemetry/stats.ts`）
   - `stats`：按技能 / Agent / 来源汇总，支持 `--since`、`--agent`、`--source`、`--skill`、`--json`、`--unused`。
   - `top`、`sessions`、`triggers`、`export --format csv|json|jsonl`。
6. CLI（`src/telemetry/commands.ts` + `src/cli.ts`）
   - 命令：`status / enable / disable / sources / skills / capture / storage / stats / top / sessions / triggers / export / import / log / dedupe / purge / doctor / rule print`。
   - 只读命令支持 `--json`；所有告警走 stderr。
7. 文档
   - 新增 `docs/telemetry/index.md`、`docs/telemetry/configuration.md`、`docs/cli/telemetry.md`，更新 `docs/cli.md`、`docs/config.md`、`docs/.vitepress/config.mts`。
8. 测试
   - 默认关闭、开关组合、技能模式、事件 ID 去重、JSONL 轮转与保留、统计聚合、导出往返。

# 变更集净变更规则

- 计划位置：toolkit 1 / 5；前置：无

## 背景

CHANGELOG 面向从上一已发布版本升级的用户。同一发布内的来回改动（新增某能力后又在同版本内修改、修复或回退）对读者不可见，逐条保留会让更新日志混入过程记录。当前 `fxri-release-changelog` 只做语义归类，并明确「归类只搬移、不删内容」，没有「同版本内后改动覆盖先改动」的编辑规则。

## 实施方案

1. `skills/fxri-release-changelog/SKILL.md`
   - 在「消费发版」之前插入「合并同版本变更集」步骤：按净用户可见结果收敛同一版本块的条目。
   - 判定标准：
     - 仅限同一包、同一版本块、本次发布内；不跨版本、不改历史块、不合并依赖变更。
     - 上一已发布版本中不存在的新能力，本次内的 `新增 → 修改 → 修复` 折叠为一条最终状态。
     - 上一已发布版本中已存在的行为，其 `修改` / `修复` 必须体现在最终条目中，不得整条丢弃。
     - 本版本内完全回退且从未发布的能力，整条删除。
     - 类型归并：`新增 + 修改/修复` 归新增，`修改 + 修复` 归修改，纯修复保留，重大变更不降级。
     - 无法确认同源时保留，不猜。
     - 输出折叠清单：保留哪条、哪条并入哪条、删除哪条及原因；过程记录留在变更集、提交与任务档。
   - 失败模式新增一行：同版本内过程性条目未收敛时，按净变更规则合并而不是继续堆叠。
   - 版本双写位同步升到 `1.3.0`。
2. `skills/fxri-release-changelog/references/changelog-format.md`
   - 新增「净变更合并」小节，给出判定表与正反例。
   - 把「归类只搬移、不删内容」限定为 CLI 格式化命令的行为，不约束人工净变更编辑。
3. `docs/guide.md`
   - 技能表版本更新为 `1.3.0`。
4. `.changeset/`
   - 新增 patch 变更集，描述净变更规则。
