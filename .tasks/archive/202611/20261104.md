# 技能版本提示与来源

批次：第 2 个（前置：任务「工具版本提示器与私有 registry」）

## 背景

工具本体的提示解决后，技能侧还有两类来源没有覆盖：

- 本包内置技能随 CLI 同批分发，但项目面副本可能落后；
- 第三方来源技能各自独立发版，需要单独的提示开关与频率，不能和本包技能共用一套。

本任务把技能版本可见性统一收敛到 `skills status` 与 `skills sources`，**不在各 SKILL.md 内增加单独的自检步骤**——所有技能已声明版本，统一入口是 CLI 的 `versionStatus`，避免只改个别技能造成口径不一致。

版本口径：本次能力量级为 minor，包版本 1.15.0。

## 配置模型

在上一任务基础上扩展：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `updateCheck.channels.builtinSkills.notify` | `inherit` | 本包内置技能；`inherit` 表示 CLI 已落后时由 CLI 提示覆盖、不重复提示，CLI 最新但磁盘副本落后时才单独提示 |
| `updateCheck.channels.externalSkills.notify` | 继承全局 | 第三方来源技能的默认提示 |
| `updateCheck.sources.<name>.notify` | 继承 externalSkills | 单个第三方来源独立覆盖 |

规则：

- 优先级：`sources.<name>` > `channels.externalSkills` > 全局默认；`channels.builtinSkills` > 全局默认。
- 通道关闭不是总闸：`channels.externalSkills=off` 时，显式写了 `sources.<name>.notify` 的来源仍按来源值提示；要让全部外部来源静默，用 `updateCheck.enabled=false`，或删除各来源覆盖。
- `notify: off` 即该来源的提示开关关闭，不再另设 boolean。
- 临时来源（`--from` 不带 `--save`）不写独立配置，统一继承 `channels.externalSkills`。
- 配置中写了未注册的来源名时，`skills status` 归入「未知来源配置」提示，不阻断命令。
- 非法值 stderr 告警并回落到上一级默认。

# 工具版本提示器与私有 registry

批次：第 1 个（前置：无）

## 背景

1.9.3 用户反馈「AI 没有提示我升级」。现状是升级提示只走 stderr、且只在部分命令路径出现；`toolkit --version` 只输出版本号，不提供可升级信息；CLI 最新版本查询地址写死公网 registry，内网 / 镜像 / 私有仓库用户请求失败后静默。本任务先把工具本体的版本检查收敛为一个统一提示器。

设计参考 `update-notifier`、`gh`、`pip` 的共同约束：缓存、不阻塞、可关闭、CI 与脚本上下文静默、只提示不自动升级；同时补一项它们没有的能力——结构化字段供 AI 消费。

版本口径：本次能力量级为 minor，包版本 1.15.0。

## 配置模型

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `updateCheck.enabled` | `true` | 总开关；`false` 不联网、不提示 |
| `updateCheck.notify` | `always` | 默认展示频率：`always` / `daily` / `weekly` / `off` |
| `updateCheck.channels.cli.notify` | 继承全局 | CLI 本体更新提示 |
| `updateCheck.registry` | 有效值按「配置 > `npm_config_registry` > 项目 `.npmrc` > 家目录 `.npmrc` > `https://registry.npmjs.org`」解析；空值或非法值回落下一级 | 配置未写时不落盘 |

## 实施方案

1. `src/update-check.ts`：
   - 缓存结构改为 `latest` + `lastCheckedAt` + `lastFailedAt` + `notifiedAt`；`notifiedAt` 为「键 → 时间戳」映射，任务 1 用 `cli`，任务 2 再扩展 `builtin` 与 `source:<name>`。兼容读取旧版 `{ ts, ok, latest }` 并静默迁移。
   - 检查频率沿用成功 24 小时 / 失败 1 小时；过期不删除上次成功版本，按 stale-while-revalidate 继续用旧值提示并在后台刷新；失败只记录 `lastFailedAt`，保留上次成功版本。
   - `readCachedLatest()`：先判关闭开关，再读缓存（含过期但成功的历史值），零网络。
   - `shouldShowUpdateHint(channel)`：统一闸门——关闭、真实 CI、`npm_lifecycle_event`、该通道频率未到任一命中即不提示。新增 `isCiEnv()`：`CI` 取 `0` / `false` / `off` / `no` 视为非 CI，并同步用于 `skills.autoLink` 的 CI 判定。
   - `buildRegistryUrl(registry)` 与 `fetchLatestVersion(registry)`：仅接受 http / https，1 秒超时、失败静默、负缓存；非法地址告警并回落默认。
   - 认证：读取 `NPM_TOKEN` 与 `.npmrc` 中与 registry host 匹配的 `_authToken`，同 host 时 `NPM_TOKEN` 优先；`.npmrc` 查找顺序为项目 `.npmrc` > 家目录 `.npmrc`；命中时发送 Bearer，token 不写入日志、报告或缓存。401/403 按失败静默并记负缓存。
   - registry URL 含 userinfo（`https://user:pass@host`）时告警并剥离账号密码后再使用；剥离失败则回落默认地址，凭据不进报告与缓存。
   - 代理：Node fetch 不自动读 `HTTP(S)_PROXY`，本次文档写明限制；失败不阻塞命令，需要时用 `updateCheck.enabled=false` 关闭检查。
   - `formatUpdateHint()`：固定一句话，不输出 JSON；`emitVersionHint()` 按通道选择——TTY 走 stderr，非 TTY 走 stdout 结尾。仅在命令成功（`exitCode === 0`、未抛异常）时输出；解析错误、Ctrl+C、非 0 退出不提示。
2. `src/cli.ts`：
   - `main()` 收口调用 `emitVersionHint()`，所有业务命令共用一处，不再逐命令追加。
   - `--version`：stdout 保持原样（版本号），提示只写 stderr，避免破坏脚本解析与测试快照。
   - `--help`、`help` 子命令与裸 `toolkit`：完全不提示——帮助不是升级检查场景，也避免帮助快照与文档站构建受干扰。
   - `skills path`：stdout 与 stderr 都不提示——该命令专供上游安装器消费，任何额外输出都可能被当成异常。
   - `--check` 类命令（如 `changelog doc --check`）与 `tasks --export`：stdout 保持原样，提示只写 stderr，避免校验结果或导出回执被额外行污染。
   - `changelog` 透传子命令与 `--format json`：不输出文本提示；JSON 由 `skills status` 的 `versionStatus` 承载。透传判定按 commander 解析后的命令路径，不用 argv 字符串启发。
   - `skills status` 增加最小「版本检查」块：CLI 当前 / 最新、registry 有效值与来源（配置 / `npm_config_registry` / 项目 `.npmrc` / 家目录 `.npmrc` / 默认）、`channels.cli` 的生效频率；`enabled=false` 时明确显示「版本检查已关闭」并保留本地版本。`--format json` 顶层增加 `versionStatus`，结构为 `cliVersion`、`latestVersion`、`updateAvailable`、`registry: { value, source }`（`source` 取 `config` / `npm_config_registry` / `npmrc-project` / `npmrc-home` / `default`）、`channels: { cli: { notify } }`，任务 1 只含 `channels.cli`，后续任务按只增不改扩展。`versionStatus` 放顶层承载 CLI / registry / 通道策略；`global` 与 `project` 两个报告各自保留 `skillVersions` 并新增 `skillsOutdated`，避免 `--scope all` 时顶层字段含义含糊。`schemaVersion: 1` 由现有 `printJson` / `toJsonText` 统一前置，本任务不重复实现，只确保新增字段走同一出口。该命令跳过结尾提示，避免同屏重复。文本模式对 registry 只显示来源与折叠后的主机，避免内网地址进入共享截图；JSON 保留完整值供脚本使用。
3. 单测：配置优先级与非法回落、频率四态、闸门三态（含 `CI=0` 不静默）、registry 优先级（配置 / 环境变量 / `.npmrc` / 默认）与 URL 构造（含路径前缀与 scoped 包名编码）、`NPM_TOKEN` 与 `.npmrc` `_authToken` 认证头、401 静默、通道选择、JSON 不输出文本、`--version` stdout 不含提示、`--help` 完全不提示、`skills path` stdout / stderr 均不含提示、`--check` / `--export` 的 stdout 不被污染、registry 文本模式主机折叠、旧缓存结构迁移、过期缓存仍可提示、失败保留上次成功版本。
4. `scripts/verify.mjs`：CLI 冒烟与任务区体检步骤统一注入 `FX_NO_UPDATE_CHECK=1`，保证门禁输出确定；单测 setup 同样关闭提示。
5. 文档：`docs/cli.md`（提示行为与例外、版本检查块、脚本请用 `--format json` 或 `FX_NO_UPDATE_CHECK=1` 的边界）、`docs/config.md`（基础字段表、registry 优先级、`NPM_TOKEN` / `.npmrc` 认证、代理限制，以及 `skills.autoLink` 的 `CI=0/false/off/no` 视为非 CI 口径）、`docs/guide.md` 与 `docs/handbook.md` 补使用说明；默认频率写明 `always`，`daily` / `weekly` / `off` 仅作可选项，不要求用户先配置。`.changeset/` 建 minor 变更集，条目逐条 `- 新增：...`。
