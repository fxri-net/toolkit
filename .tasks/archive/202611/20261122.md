## 设计底座

### 事实分四类，手段分四级（只可向下退）

| 类别 | 例子 | 允许的处理 |
| --- | --- | --- |
| A 代码事实 | 退出码、状态集合、阈值、目录清单、前缀 | 运行期派生；派生不了才生成 |
| B 契约事实 | JSON 信封、配置键、命令元数据 | 代码为源 + 文档生成或指针 |
| C 叙述事实 | 开工词、判定表、流程措辞 | 一处散文 owner，其余指针 |
| D 外部约束 | `package.json` engines、CI 配置 | 一致性校验兜底 |

手段阶梯：**派生 → 指针 → 生成 + `--check` → 一致性校验**。同一事实不得同时存在生成器与校验器两份实现。

### 落地规范（防「统一了又长回来」）

- **事实 ID**：`F-<n>` 稳定编号，不复用；owner 变更须同批改注册表并写 `history.md`
- **生成块标记**：统一 `<!-- toolkit:<fact-id>:start -->` / `:end`，缺标记即 `--check` 失败并给出修复命令
- **守卫载体优先级**：单测 → 现有 `check-*.mjs` → 新脚本；新增脚本须带 `--self-test`（C-44）
