## 20261113-唐启云-修复日志遍历越界改写第三方包日志

> 负责人：唐启云　状态：已完成　范围：toolkit　完成时间：2026-11-13 12:01

# 修复日志格式化越界改写第三方包日志

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

在 PHP 项目发版时执行 `toolkit changelog version`，命令把 `vendor/` 下 8 个第三方包的 `CHANGELOG.md` 一并改写：这些包的版本块格式为 `## 3.2.0 (2024-05-24)`，没有独立日期行，格式化逻辑据此判定「缺发布日期」，给每个版本块补了一行当日日期，写入虚假发布日期。

根因是收集器只按硬编码目录名排除：

```
const exclude = new Set(["node_modules", ".git", "dist", "coverage"])
```

`vendor`、`.venv`、`target` 等依赖与产物目录都不在名单内，凡不在名单里的目录都会被当作本仓内容改写。补名字等于逐个补洞，换生态仍会漏。

## 实施方案

收集器的判据改为「目录内容是否属于本仓自己的包」，三条并行且都不依赖 git 跟踪状态：

1. 语义排除（主判据）：依赖安装目录（`vendor`、`node_modules`、`bower_components`、`jspm_packages`、`.venv`、`venv`、`site-packages`、`__pypackages__`、`vendor-prefixed`）与构建产物目录（`dist`、`build`、`out`、`target`、`coverage`、`.cache`、`.next`、`.nuxt`、`.output`、`.svelte-kit`），任意层级按目录名命中即跳过；composer 的 `config.vendor-dir` 自定义目录名一并跟随。
2. gitignore 兜底（辅助判据）：以 `git ls-files --others --ignored --exclude-standard --directory` 一次取回被忽略的子树，遍历时整棵跳过；覆盖项目自造目录名。
3. 可配置覆盖：`--exclude` 追加跳过、`--include` 强制放行，`include` 优先于内置名单与 gitignore 判定。

不采用「按 git 跟踪状态过滤」：把 `vendor` 提交进版本库的项目（PHP 常见做法）会让第三方日志重新进入改写范围，判据必须与跟踪状态解耦。

## 影响范围

- `src/changelog/collect.ts`：重写收集逻辑，新增 `CollectOptions`。
- `src/git-ignore.ts`：新增 `gitIgnoredDirs`，复用既有 `runGit` 出口。
- `src/changelog/format.ts`：`formatChangelogs` / `countUntypedEntries` 增加可选收集选项，向后兼容。
- `src/commands/changelog.ts`：`version` / `format` 增加 `--exclude` / `--include`。
- `src/index.ts`：导出 `CollectOptions` 类型。
- `docs/cli/changelog.md`：选项表与 `version` 行为说明补范围口径。
- 下游仓：无需改文件，升级工具即生效；此前被改写的第三方日志需重装依赖恢复。

## 验证方式
