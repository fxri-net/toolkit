### 只报告，不自动提议

- 变更集缺类型前缀 / 裸行、规范载体异常形态、索引语义警告、历史 ID 补录；

- 文档 / 技能里的本机路径、无法自动改的 `.gitignore` 覆盖、`git rm --cached` 等。

### 统一交互

- 在 `task check` / `status` 这两个本来就会跑的步骤收集告警；
- 按**修复命令**分组：同一命令覆盖多个告警只征得一次确认，不同命令分别征得确认；每次给出「告警摘要 + 将执行的命令 + 影响」，用户确认或拒绝均可（表达不限）；
- 是 → 执行该命令；否 → 记录并继续任务，不阻断；
- 非 TTY / CI 不询问，只报告；
- Tier 2 不并入自动提议，单独给命令与影响；只报告项不发提示。

# 统一批量入口、修复数据迁移边界与版本口径

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

前序任务「统一升级入口并迁移本机契约数据」已归档。本次复核发现 1 个数据迁移逻辑漏洞与若干口径风险，用户已确认处理方向：

1. playbook 的版本级别文案与 toolkit 共享口径冲突，改为「指针 + patch 兜底」，不整段删除。
2. `toolkit status` 的区块 id 保持 `upgrade`，接受破坏性变更。
3. `--all` / `--yes` 按同类命令统一，取消自定义的「5 项阈值」。
4. 变更集仍按本会话约定用 patch，但破坏性条目必须标 `重大：`。

复核确认后追加：`usage data purge --all` 纳入本次统一；`--all` 与 `--only` / `--skip` 按 `skill uninstall` 的「互斥并报错」处理；playbook 同步技能正文与任务档；修正待发布变更集里的「5 项」条目；补备份不可恢复披露与交互态 `--yes` 告警。

本任务只做修复与口径收敛，不新增命令入口。

## 结论与已确认决定

1. **数据迁移边界**：同一数据项内出现无法解析文件时，整项判人工并列出文件，不把 unknown 文件带进重写清单；事件文件同时含 legacy 与 unknown 行时，unknown 行列入人工提示；缺失版本显示「缺失」而不是 `undefined`。
2. **`upgrade` 批量入口统一**：`--all` 表示全选，`--yes` 表示非交互确认；裸 TTY 一律交互多选且默认不全选；非 TTY 全量执行必须 `--all --yes`，只给 `--yes` 报错并给用法；交互态 `--yes` 缺 `--all` 按 `skill uninstall` 的既有模式告警并忽略；`--all` 与 `--only` / `--skip` 互斥，同时出现时报错；`--only` 与 `--skip` 同时出现时沿用既有过滤顺序（先 only 后 skip），不新增报错；删除 `BATCH_THRESHOLD` 与文档中的「5 项」。`--check` / `--dry-run` 只读，不受 `--yes` 约束。
3. **`usage data purge --all` 一并统一**：非 TTY 执行 `--all`（非 `--dry-run`）必须加 `--yes`；交互态确认；`--dry-run` 只读不要求 `--yes`；与 `trash prune --all` 的口径一致。
4. **`status` 区块**：代码保持 `id: "upgrade"`，不改回 `migrate`；文档写明脚本迁移。
5. **变更集**：保持 patch，新增 `重大：` 条目登记 `upgrade --yes` 语义变化、`usage data purge --all` 确认变化与 `status` 区块 id 改名；同时修正待发布变更集中「超过 5 项」的旧表述。
6. **备份清理**：`--prune-backups` 清理到含数据迁移的备份时给出提示，或保留最近一次含数据项的备份；文档写明被清理的备份不可恢复、数据回滚点随之消失。
7. **playbook 版本口径**：删除「小修 +patch，新增能力 +minor」，改为「bump 级别以 `@fxri/toolkit` 的 `fxri-release-changelog` 技能为准；未加载时按 patch 兜底，minor 须举证既有用法失效且无迁移；属人工裁决，无自动门禁」；同步 `fxri-code-profile-core` 正文（去掉「条目较多时」，版本 0.1.1 → 0.1.2）、生成物与变更集，并在 playbook 任务区补档。
8. **不纳入本次**：使用数据目录不跟随 `--cwd`、`status` 不检测全局数据、事件检测性能，只补文档说明；不新增 `--usage-dir` 等开关。

## 背景

## 结论：不新增 `toolkit migrate`，并入 `toolkit upgrade`

`toolkit upgrade` 已具备本机数据迁移所需的全部骨架：`--layers global/project/local`、`--check` / `--dry-run` / `--diff`、`--yes`、备份与 `--restore` / `--prune-backups`、统一 JSON 信封。新增一个平行命令只会让用户多学一个概念，违背 C-55「同一能力只留一条入口」。

**唯一用户入口**：`toolkit upgrade`
- 裸命令 = 预览（工程侧 + 本机契约数据，含事件文件）→ TTY 一次确认 → 全部执行；非 TTY 需 `--yes`。
- 只读：`--check` / `--dry-run` / `--diff` / `--format json`。
- 默认全部可迁移项都做，不要求用户选参数；需要取舍时走交互或高级 `--only` / `--skip`，并保留 `--skip-events` 作为唯一的事件跳过开关。
- `--restore` 扩展为同时恢复本机数据项：升级前把状态/台账/事件的备份登记进同一备份会话，恢复时一并还原。
- 不新增必填参数；`--layers` 语义扩展为同时覆盖数据契约所在层。

`toolkit status` 的 `migrate` 区块：**显示名与机器 id 都改为 `upgrade`**（用户已确认），提示统一指向 `toolkit upgrade --check`。
`toolkit convention upgrade` 保留为底层恢复命令，文档标注「通常由 `toolkit upgrade` 自动完成，无需手动执行」，不删入口以免破坏既有脚本。

## 交互与安全

1. 版本判定：只迁移「同 MAJOR 且落后」或历史整数；更高 MAJOR 报错「请先升级 toolkit」，不降级写。

## 背景

用户发现 `%TEMP%\fxts-tk-skills-kYCvT3` 长期堆积，追问同类残留的成因、是否该自动清理、成熟做法与本仓缺口。

实测证据（2026-11-27）：

- 全量 `pnpm test`（147 文件 / 1915 用例全绿）后 `os.tmpdir()` 新增 9 个 `fxts-tk-*`，全部来自 `src/__tests__/changelog-doc.test.ts`。

- 泄漏点两处：`changelog-doc.test.ts` 的 `buildDocPages` / `syncDoc` 两个 describe 内 7 处 `tempDir("fxts-tk-doc-")` 无任何清理钩子；`resolveDocOptions` describe 的 `writeConfig` 每次重新赋值 `home` / `project`，同一用例调两次即永久孤儿化第一组，每轮再漏 2 个。

## 背景

GitHub Actions 的 macos job 唯一失败用例 `collectSkillVersionUpdates > 项目态内置技能落后同样计入 builtin`，

根因：macOS 的 `/tmp` 是 `/private/tmp` 的软链，`process.chdir` 后 `process.cwd()` 返回物理路径，
而项目态账里的 `target.dir` 是逻辑路径。`src/skills/state.ts` 的 `isSafeTargetDir` 走
`isInside(resolve(root, dir), root)`，`src/skills/source/paths.ts` 的 `isInside` 只做文本前缀比较、
不解析软链，两种写法前缀失配 → 合法目标整条丢弃 → `builtin` 为空。

该缺陷对真实用户同样成立：项目位于软链路径（macOS `/tmp`、`/var`，或家目录被软链）时，项目态技能账会被整条丢弃。

现有守卫 `temp-prefix.test.ts` 只匹配 `mkdtempSync(join(tmpdir(), …))` 与包装函数字面量，手工拼路径形态漏检。

## 实施方案

1. `src/skills/state.ts`：`isSafeTargetDir` 项目态分支改为
   `isInside(realPath(resolve(options.root, dir)), realPath(options.root))`，比较前统一真实路径；
   `realPath` 解析失败自动回落 `resolve`，不改变全局态判定与状态文件格式。
2. `src/__tests__/version-status.test.ts`：新增回归用例——别名目录写进账、真实目录作 root，
   断言项目态内置技能仍计入 `builtin`（Windows 用 junction，其它平台用 dir 软链）；
   同时把沙箱前缀 `tk-version-status-` 改为 `fxts-tk-version-status-`。

   `tk-golden-sandbox-`、`tk-envfx-sandbox-`、`tk-matrix-sandbox-`、`tk-check-sandbox-`、`tk-upd-sandbox-`。

   断言手工拼路径前缀同样以 `fxts-tk-` 开头，违规按「文件:行 前缀」全量列出。

## 背景

安全审计发现三处高 / 中危边界缺口：

- 外部技能 `name` 未做单段校验，`join(target.dir, name)` 可被 `../../` 穿越（`src/skills/install/global.ts L142`、
  `src/skills/install/project.ts`；名称来自 `src/skills/source/metadata.ts`）。
- 远程技能 git `ref` 未校验、未加 `--`，可被以 `-` 开头的值做选项注入（`src/skills/source/remote.ts`）。
- 任务 `owner` 未净化，`task add --owner` 与 CSV/XLSX 导入可写出任务目录（`src/tasks/edit.ts L104-108`、`src/tasks/import.ts L272`）。

   涉及写入 / 删除时先预览并披露不可逆部分。
5. 执行完运行项目自己的门禁；失败则按步骤回滚。
