> 批次：第 1 批（共 2 批）；计划位置：第 6 个（共 6 个）；前置：无；后继：无

## 背景

- 协作中出现一次理解偏差：用户连续表达「按推荐方案落档」，助手把上一轮建议的「开始执行」当成授权；实际用户本意仍是继续任务档维护与重新评估。

# 统一命令指路与组合缓存语义

> 批次：第 1 批（共 2 批）；计划位置：第 5 个（共 6 个）；前置：无；后继：无

## 背景

- 误敲 `toolkit conventions check` 时只回「期望 0 个参数，实际收到 1 个」，不提示正确命令是 `conventions status`；同类命令（如 `usage hooks status`）会显式给出下一步命令。
- `rules compose` 在显式传 `--preset` / `--module` 时默认写缓存，即使同时带 `--out` 或 `--copy`；因此一次性导出会顺带改掉「以后裸跑 `rules compose` 的默认组合」。文档示例正使用该形态且未带 `--no-cache`。

## 实施方案

1. `src/cli.ts`：为 `conventions status` 增加别名 `check`（commander `.alias("check")`），使 `toolkit conventions check` 等价于只读体检。
2. `src/cli.ts`：为 `tasks` 增加别名 `list`，使 `toolkit tasks list` 等价于裸 `tasks` 看板（与 `conventions check` 同类：命令名与直觉不一致）。
3. `src/cli.ts`：`rules compose` 在带 `--out` 或 `--copy` 时默认不写缓存（等同隐式 `--no-cache`），跳过写缓存时向 stderr 输出一行说明（stdout 保持机器可读）；仅输出到 stdout 时保持现行为。
4. `docs/cli/conventions.md` 子命令表补 `check` 别名；`docs/cli/rules.md` 补「`--out` / `--copy` 不写缓存，需要记住组合时单独跑一次」；`docs/cli/tasks.md` 补 `tasks list` 别名说明。
5. 测试：`conventions check` 与 `conventions status` 输出一致、退出码相同；`tasks list` 与裸 `tasks` 输出一致；help 输出含别名且 `setupHelp` 递归替换后不重复列条；`check --format json` 等参数能原样透传给 `status`；`rules compose` 三态用例——仅 stdout 写缓存、带 `--out` 不写、显式 `--no-cache` 不写。
6. 新增 `.changeset/` 条目（patch）：`- 新增：conventions check 作为 status 的别名`；`- 新增：tasks list 作为任务看板别名`；`- 修改：rules compose 在 --out / --copy 时不再改写组合缓存`。
7. 提交粒度：别名（conventions / tasks 可同一次）与缓存语义两类改动分两次提交，不混批。

# 强化技能使用规则可执行性

> 延续「改为全局规则上报技能使用」（见 archive/202611/20261107.md）；本次只改规则文本与提示位置，不改采集链路。
> 计划位置：第 1 个（共 6 个）；前置：无；后继：20261108-唐启云-会话收尾补报技能使用

## 背景

现场取证：

- `~/.trae-cn/user_rules/rule-1793951733673.md` 存在，且与 `toolkit usage rule` 当前输出一致。
- `toolkit usage info`：已开启、通道 `rule`、队列 0、Hook 未安装。
- `~/.trae-cn/hooks.json` 为 `{"version":1,"hooks":{}}`；历史 6 条事件的 `originAdapter` 为 `trae-hooks`，说明 Hook 曾可用，切规则通道后被移除。
- 手动补执行一次 `toolkit usage record` 后事件 7 → 8，说明采集链路正常。

规则未生效的四层原因：

1. **与既有纪律冲突**：AI 规则要求「只读型请求默认只读」「方案确认不等于执行授权」，`usage record` 会写本机数据，模型容易按「只读 / 待授权」跳过；现有规则未声明豁免。
2. **触发模糊**：「每批工具调用全部返回后」难以判定，容易拖到会话结束或直接遗忘。
3. **位置靠后**：三个 user_rules 文件按文件名顺序拼接，usage 规则在最后，长上下文中容易被忽略。
4. **无机械兜底**：Hook 被移除后完全依赖模型自觉，规则文本无法强制。

## 实施方案

1. 改写 `docs/rules/usage.md` 的规则全文（复制块内）：
   - 标题改为 `## 技能使用情况（必做）`。
   - 触发改为「每次调用 Skill 工具（加载并遵循某个技能）后立即执行 `toolkit usage record --skill <技能名>`；同一技能调用几次就重复传几次，未调用 Skill 工具则不执行」。
   - 增加「同一轮连续调用多个技能时，可在本轮最后一次调用后合并为一条命令；不得拖到下一轮或会话结束」。
   - 增加「给出最终回复前自检：本轮调用过 Skill 却尚未上报的，先补报；命令无法执行时在回复中说明原因，不静默跳过」。
   - 增加豁免条款：「`usage record` 只把技能名写入本机 usage 队列，不改仓库、不改远端、不上传，因此不受『只读型请求默认只读』『方案确认不等于执行授权』限制，也无需逐次确认」。
   - 保留「只传技能名 / 明细反查 / 配置决定范围 / 数据只留本机 / `stats` 与 `doctor` / 不自行改数据」。
   - 按变更时刻更新复制块首行锚点；「注意」段同步为「立即上报、按次计数」口径。

   `- **技能上报（仅当启用技能使用统计时）**：每次调用 Skill 工具后立即按《技能使用情况规则》执行上报；该命令只写本机队列，不改仓库 / 远端，不受只读与授权纪律限制。`
   同步更新该页锚点。理由：usage 规则文件在 Trae 中排最后，容易在长上下文中被忽略；AI 规则文件最先加载，放一行条件提醒提高命中率。
