## 背景

用户确认把散落缓存统一到 `~/.toolkit/cache/` 并迁移存量。现状盘点：

- 升级检查缓存 `{tmpdir}/.toolkit-update-check.json`：`/tmp` 在多用户系统共享，文件名可预测，存在碰撞与符号链接风险，也污染临时目录。
- 远程技能来源缓存 `~/.agents/.toolkit-sources/<hash>`：派生数据，与技能账本同根但性质不同，混放不利于统一清理。
- 技能状态账本 `~/.agents/.toolkit-skills.json`、项目 `<repo>/.toolkit/state.json`：状态不是缓存，不迁。
- 使用事件 `~/.toolkit/usage/**`：用户数据不是缓存，不迁。
- 锁文件 `~/.agents/.toolkit-skills.lock`、`<repo>/.toolkit/skills.lock`：运行时状态，不迁。

## 实施方案

1. 新增 `src/cache.ts`：

   - `resolveCacheEntry(nextRel, legacyAbs, kind: "file" | "dir")`：新路径存在则用新路径；否则旧路径存在时惰性迁移（优先 `renameSync`，失败回退 `cpSync` / `copyFileSync` 后删除旧路径；再失败则返回旧路径继续可用，不丢数据）；两者都不存在返回新路径。迁移只在被访问时发生，不启动扫描、幂等。
2. `src/update-check.ts`：缓存文件改为 `~/.toolkit/cache/update-check.json`，旧 `{tmpdir}/.toolkit-update-check.json` 惰性迁移；写入前 `mkdirSync(dirname(file), { recursive: true })`；读取仍剥 BOM 并兼容旧结构。
3. `src/skills/source.ts`：`remoteCacheDir()` 改为 `~/.toolkit/cache/skill-sources/<hash>`，旧 `~/.agents/.toolkit-sources/<hash>` 惰性迁移；克隆、刷新、失败回落逻辑不变。
4. 文档：
   - 新增 `docs/config/cache.md`：目录布局、可安全删除、惰性迁移行为，以及「哪些不在此目录」（状态账本、使用数据、锁文件）。
   - `docs/config/update.md`：缓存路径改为 `~/.toolkit/cache/update-check.json`。
   - `docs/config/skills.md`、`docs/cli/skills.md`：来源缓存路径补新位置。
   - `docs/.vitepress/config.mts`：配置参考侧栏加入「缓存目录」。
