## 背景

工具定位是「以方案为主、一方案一归档、不攒一大坨改动一次提交」。据此，「任务收尾的 git 提交自动执行」应从作者私用偏好升为官方推荐，同时保留单独取消的余地。当前规则层与这一定位不符：

- `personal` 模块被描述为「作者自用的规则层偏好」，`recommended` 预设不含它，官方推荐事实上缺失。
- 预设 `complete`（自用全篇）与 `recommended` 内容重叠，且「极简」原设计为 `[core]`，与「搭配技能使用的工作流规则」的目标错位。
- `env` 模块删掉安装命令后只剩一条安装授权纪律，独立成模块性价比低。

## 实施方案

### 一、模块合并：`personal` + `env` → 「推荐做法」

```markdown
> 规则更新时间 2026-11-24 10:47

## 推荐做法

- 以下条目优先于同类默认约定。
- 任务收尾的 git 提交自动执行。
- **不自行安装**：任何安装动作（全局包、项目依赖、系统工具）都须用户在方案或计划里明确授权；未授权时只给命令与排查建议。
```

- 首条保留覆写声明，保证与 workflow 的提交纪律形成「默认 → 约定覆写」单向链。
- 「不自行安装」条目吸收 `env` 原纪律并放宽为「任何安装动作」，删除全局安装命令（安装方式只在文档与技能里出现）。
