不能简单把覆盖率全交给 CI：发布门禁也在本地 `pnpm verify`，若本地不采集且代码未推送，「功能写了、测试忘加」的代码可能直接发布。
所以本地要保留**改动行覆盖率信号**，只是把采集范围收窄到本次改动的文件——测试仍全量跑，信号不丢，开销下降。

## 采集率口径（本次不改判定公式，只改采集范围）

- 指标是**新增语句的命中比例**，不是文件数、不是全仓百分比：
  `改动行覆盖率 = 被测试执行到的新增语句数 / 新增语句总数`。
- 「新增语句」由 `git diff -U0` 的 `+` 行确定；语句起始行落在这些行里的才计入。
- 门槛：新增语句 ≥ 5 条时要求 ≥ 80%，不足 5 条直接放行。

  - 0/6 才失败——含义是「新代码一行都没跑过」，不是「测试文件不够多」。
- 覆盖率收窄只改变「报告里包含哪些文件」，因为全部测试照跑，改动文件的语句命中数依然准确。
- **补测不按任务新建文件**：门槛只要求「新增语句被执行到」，优先在既有同主题测试文件里追加用例；仅当被测模块没有对应测试文件时才新建（文件生命周期约定见后继任务）。

## 背景

典型传播路径是「某个员工自己用着好 → 想在公司内推广 → 不知道怎么简洁清晰地介绍给别人和领导」。
现有文档全部面向使用者（怎么装、怎么用），没有任何一页面向推广者与决策者：没有可直接复制的一段介绍、没有试点方案、没有对「安全 / 成本 / 与现有工具冲突」的回答。
这类角色是开源工具在组织内落地的关键节点，缺这一页，传播会停在「口头推荐」并迅速流失。

参考成熟设计：1Password / Linear / Vanta 等产品的「Rollout guide」都包含：一句话价值、给不同听众的讲稿、试点范围与指标、决策者 FAQ、推进清单。

## 实施方案

1. 新增 `docs/adoption.md`，H1 与 frontmatter title 均为「内网推广（adoption）」，约 110 行，面向「推广者 + 决策者」，不写命令细节。
2. 内容结构：
   - **一句话介绍**（≤60 字，可直接复制到群公告 / 邮件）：把对话里的方案与交付变成仓库里可校验、可分发、可迁移的资产。

   - **试点方案**：选 1 个仓库、2 周、3 个指标（任务留档率、返工与重复沟通次数、沉淀出的规范条数）；给出成功与止损判据。
   - **决策者问答**：数据存在哪（默认全本机，统计默认关闭）、要不要全员装（可只在试点仓库用 devDependency）、
     与 Jira / Confluence 是否冲突（管的是 AI 会话里的方案与交付，不替代工单与文档站）、许可与成本（MIT）、
     安全与脱敏（`redact` 默认开、`privacy` 扫描本机路径）、试点失败怎么退（仓库内文件删掉即还原）。

   - **常见阻力**：「我们已经有 Jira」「AI 写的东西能信吗」「会不会把代码传到外面」——每条给一句事实回答并链到对应页。

# 提交规则显式同步

> 计划位置：第 4 个（共 6 个）；前置：20261124-唐启云-变更集重大前缀进规则；后继：无

## 背景

每个项目都要配一份 `.trae/rules/git-commit-message.md`，与 `templates/rules/commit.md` 逐字一致，目前只能人工复制，多项目时维护麻烦。

规则改动是极低频事件，不适合自动化：薄壳会让 agent 读不到内容、未装 toolkit 的成员失效、离线不可用。因此保留项目内自包含快照，改为**显式同步**。

## 实施方案

- 新增 `toolkit rule sync`：
  - 无参时先显示「项目内文件与当前版本的差异」，确认后写入；`--yes` 免确认，`--dry-run` 只显示差异。
- 目标文件固定为 `.trae/rules/git-commit-message.md`（当前只有 Trae IDE 需要项目内提交规则；其它 agent 走全局规则，不生成项目文件）。文件不存在时创建，存在时整段覆盖。
  - 写入内容首部加一行「由 toolkit 生成，更新请跑 toolkit rule sync」，与规则正文分隔，不进可复制块。
- **不挂自动化**：不进 `prepare` 钩子、不进 `init` 默认流程；`init` 只在目标文件不存在时创建一次。
- `toolkit status` 增加被动提示：项目内文件与当前版本不一致时提示「跑 `toolkit rule sync` 更新」，只提示不改文件。
- 文档与测试：`docs/cli/rule.md` 补命令说明；差异计算复用现有文本比对工具；新增单测覆盖「无差异 / 有差异 / dry-run / 不存在时创建」。

### 产物示例

`.trae/rules/git-commit-message.md`：

```markdown

alwaysApply: true
scene: git_message
generated_by: "@fxri/toolkit 2.0.5"

<!-- 由 toolkit 生成，更新请跑 toolkit rule sync；勿手改本文件 -->

## 提交信息规则

（以下正文与 templates/rules/commit.md 逐字一致，不含首行更新时间锚点）
```

只记版本、不记生成时间：版本能判断是否落后，且同一版本重复同步零改动（幂等）。注释行提示勿手改；正文逐字镜像，现有逐字一致性测试在比对时剔除该注释行。

### 交互（不替用户做选择）

- 无差异：只输出「已是最新（版本 X）」，不提问、不写盘。
- 有差异：先打印目标路径、当前版本、最新版本与差异摘要（+N −M），再让用户选择「写入最新版本 / 保留当前文件 / 查看完整内容」，不默认写入。
- 文件不存在：询问「是否创建」，同意才写。
- 文件被手改（与上次生成内容不同）：提示「与上次生成内容不一致」，默认停在「查看」，不默认覆盖。
- `--dry-run` 只显示差异；`--yes` 是显式选择才直接写入；非 TTY 且无 `--yes` 按无交互退出码结束。

## 20261124-唐启云-新增init接入向导

> 负责人：唐启云　状态：已完成　范围：toolkit　完成时间：2026-11-24 11:40

# 新增 init 接入向导

> 计划位置：第 3 个（共 3 个）；前置：20261124-唐启云-init命令迁移至task域；后继：无

## 背景

当前上手要按文档跑 4~5 条命令（`skill install` → `rule compose` → `task init` → `usage setup` → `scope`），分散在多个域，用户心智负担高。

目标是把「新机器 / 新环境的全局接入」收敛为一条 `toolkit init`：默认路径零参数，已就绪的步骤自动跳过，结束给出明确下一步。

本命令只碰全局层，在任意目录可执行，不初始化任务区：任务区是项目内的事，由技能在项目里按需调用 `toolkit task init`（fxri-plan-task 工作流第 1 步），用户的执行目录不一定是项目目录。

## 实施方案

### 一、向导流程

```
toolkit 接入配置
├─ 1. 检查环境（只读，不提问）
│     Node 版本 / 是否 TTY
│     已就绪项只作状态展示：全局技能已装、规则组合已缓存、作用域已显式配置、使用统计已开
├─ 2. 要配置哪些内容？（四项勾选）
│     [✓] 安装 AI 技能   [✓] 配置全局规则   [✓] 设置生效范围   [ ] 开启使用统计
├─ 3. 开始配置（串行执行，复用现有命令实现，逐步打印）
│     安装 AI 技能 → 配置全局规则 → 设置生效范围 → 开启使用统计（如选）
└─ 4. 配置完成
      逐项：已完成 / 已存在跳过 / 失败 + 单条重试命令
      规则一步：自动复制到剪贴板，并打印各 Agent 的具体粘贴位置
```

- **已就绪只影响「无选择步骤」的默认勾选**（安装技能、生成规则可标为已完成）；**有交互选择的步骤一旦勾选就必进交互**，不因当前状态替用户跳过。
- 「设置生效范围」选中后进入 `toolkit scope` 的状态优先向导（非 TTY 下为 `scope wizard`），由用户在菜单里自行抉择，末项「退出」按成功返回并继续下一步；向导不替用户写任何范围决定。
- 单步失败写 stderr 并继续后续（各步互相独立），末尾汇总未完成项；全部失败才非 0 退出。
- 规则一步的真实边界：`rule compose` 只生成文本、不写任何 Agent 配置，向导只做「生成 + 复制剪贴板 + 打印粘贴位置」，文案须写明，避免用户误以为全自动。
- 用户可见文案统一用上表名称；「一次多选」「步骤适配」等只作内部设计用语，不出现于 CLI 输出与文档。

### 二、命令与架构

- 新建 `src/init/index.ts`（编排）与 `src/init/steps.ts`（步骤适配）；每步调用现有命令实现，不复制其内部逻辑。
- 新建 `src/commands/init.ts` 作为向导注册（前置任务已删除旧文件）：无参且 TTY 进向导；非 TTY 且无参数时按无交互退出码结束并提示 `--yes`。
- 默认勾选口径：**无选择的步骤**若已就绪则默认不勾（可手动勾上强制重跑）；**有交互的步骤**（设置生效范围）默认勾选，勾选后必进交互。
- Ctrl+C 语义：在范围菜单里按 Ctrl+C 结束整个命令（取消退出码），与单跑 `toolkit scope` 一致，向导不吞该信号、也不回退到下一步。
- 参数：`--yes`（全默认零交互，透传给 `skill install --yes` 与 `usage setup`）、`--dry-run`（只打印将执行的动作）、`--rules <preset>`、`--skills <scope>`、`--no-scope`、`--no-usage`。
- 显式参数即视为勾选：传了 `--rules` / `--skills` 时对应步骤自动勾选并执行，不因未进交互而漏做；`--no-scope` / `--no-usage` 只是取消对应勾选。
- `--dry-run` 下「设置生效范围」只打印「将进入范围设置」而不进入菜单，其余步骤同样只打印动作、不写盘。

# 消除全局规则模块间悬空指代

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

延续 规则收尾校正与变更集降级（见 `archive/202611/20261120.md`）。

全局规则按模块组合后供用户单独复制，`docs/rules/personal.md` 与 `docs/rules/commit.md` 的页首都宣称「相互独立，可只取其一」。
但 `templates/rules/workflow.md` 里仍有两处指向未选中的模块：

- `L15`「提交默认需你确认，**个人偏好可覆写**」——`recommended` 预设为 `core + output + workflow`（`templates/rules/ruleset.json L49`），不含 `personal`，按推荐集复制的用户读到的是不存在的模块。
- `L16`「细节**见《技能使用情况规则》**」——`recommended` 与 `complete` 预设都不含 `usage`，同样悬空。

同类悬空另有两处：`templates/rules/usage.md L8` 引用 workflow 的两个纪律名，`templates/rules/personal.md L5` 的「本套规则」指向打包内的其余模块。

同一问题此前修过两次均未解决：`archive/202611/20261120.md L1592` 把「个人偏好**模块**可覆写」改为「个人偏好可覆写」，`L1675` 把「覆写《工作流》的默认行为」泛化为「覆写**本套规则**的默认行为」——两次都只换措辞、保留了指代关系。本次改为语义自述，并删除 workflow 中不承载独立内容的转发条。

## 实施方案

### 一、源文案（`templates/rules/`）

1. `workflow.md L15`：`提交默认需你确认，个人偏好可覆写。` → `提交默认需你确认，除非规则另有约定。`
2. `workflow.md L16`：删除整条「技能上报（若启用统计）：调用 Skill 后立即上报，细节见《技能使用情况规则》。」
   - 理由：`usage.md L5-L7` 已完整承载上报要求，本条无独立内容；统计未启用时用户不需要它。
3. `usage.md L8`：`不受「只读型请求默认只读」「方案确认不等于执行授权」限制` → `不受只读请求与方案授权限制`
4. `personal.md L5`：`以下条目覆写本套规则的默认行为，两者冲突时以本章为准。` → `以下条目优先于同类默认约定。`
5. `ruleset.json L25`：personal summary `可裁剪的个人偏好：覆写工作流默认行为` → `可裁剪的个人偏好：优先于同类默认约定`

保留不动的相邻项：`workflow.md L18`「任务管理细节以已加载的 fxri-* 技能为准」属规则与技能的边界元声明，删除会让规则开始复述技能细节；
`workflow.md L17` 的 `toolkit scope status` 是独立判据且必须在规则承载（技能被作用域判为不生效时正文加载不到）。

### 二、锚点（C-15）

`workflow.md` / `usage.md` / `personal.md` 首行取同批同一时间（2026-11-24 09:57）。
`docs/rules/ai.md` 取所含模块最大值（含 workflow，即该时间）；`docs/rules/personal.md`、`docs/rules/usage.md` 各取自身模块时间；`commit.md` 不动。
