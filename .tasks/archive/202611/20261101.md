# 规范载体稳定 ID 校验收紧为去补零

## 背景

规范要求稳定 ID 去补零（`C-<n>`），但校验用的 `ID_RE` 是 `/^C-\d+$/`，`C-001` 这类补零写法一路通过：`conventions status` 的 ID 形态检查与 `tasks check` 的演进记录首列检查都判定为合法，错误写法没有任何反馈。下游多个仓库的载体已出现补零 ID，属该漏洞的直接后果。

## 实施方案

> 批次：单批　计划位置：1　前置：无

1. `src/conventions/format.ts`：`ID_RE` 收紧为 `/^C-[1-9]\d*$/`，新增补零识别与规范写法推导，供告警复用。
2. `src/conventions/status.ts`：索引 ID 形态检查与演进记录首列检查各补一条补零定向告警，给出「应写作 `C-1`」的明确指引。
3. `src/tasks/validate.ts`：演进记录首列检查同样区分补零与非法形态，避免把补零混入「用了规则名」的告警。
4. `src/conventions/upgrade.ts`：升级复核报告同样区分补零行。
5. 单测补补零用例：`src/__tests__/conventions-status.test.ts`、`src/__tests__/validate-conventions.test.ts`。
6. 变更集按 patch 记录。
