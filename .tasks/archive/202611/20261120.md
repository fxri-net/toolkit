# 技能内容级闸门

> 计划位置：第 3 个（共 3 个）；前置：20261120-唐启云-全局作用域解析与只读命令；后继：无

## 背景

全局安装的技能对所有项目可见，`description` 命中后整篇流程会进入上下文。用户要求默认保持现状（全文安装、全域生效），
由用户主动开启「内容闸门」后，才把全局技能改为入口壳，正文由 CLI 按目录判定后下发；可随时用 `--embed` 改回全文。

这是介于「一句约束」与「项目面安装」之间的措施：未激活项目拿不到流程正文，但技能壳仍可见。

## 方案

### 1. 入口壳与正文下发

- 全局安装默认仍写全文（与今天一致），不改变任何现有产物
- 用户通过 `toolkit scope` 向导或 `toolkit skills install --gate` 开启闸门后，全局技能改写为入口壳：
  frontmatter 保留 `name` / `description`（保证可被发现），正文只保留「先运行 `toolkit scope guard <skill>`；未激活即停止」
- `toolkit scope guard <skill>`：校验技能名属于包内清单；当前目录激活时输出真实 SKILL.md 正文，未激活时输出原因并以
  **退出码 3** 结束；只读，不写缓存
- `guard` 走独立快速路径：仅在 argv 形如 `scope guard <技能名>` 且无其它参数时直接处理，跳过 commander 解析、其余命令模块、
  `autoLinkSkills` 与升级检查，只加载作用域解析与包内正文读取；其余情况回落常规 CLI，保证 `--help` 与参数错误提示可用
- 快速路径同样复用 `ensureUtf8`，避免 Windows 中文正文乱码
- 输出契约：stdout 只放正文（未激活时为空），原因与诊断一律走 stderr
- 入口壳不携带版本号：`skills status` 与升级提示从包内真源读取版本，避免误报“已装版本缺失”
- `toolkit skills install --embed` 把入口壳改回全文；`toolkit skills status` 显示形态（全文 / 入口壳）

### 2. 与现有机制的隔离

- 入口壳使用独立标记（与项目面薄壳标记不同），`skills status` 与自愈逻辑据此区分，互不覆盖
- 开启闸门后，`link` / `copy` 两种安装形态都改为写入入口壳文件；由 `skills install` 幂等刷新，CLI 升级后需重跑一次刷新壳
- `autoLinkSkills` 启动自愈需识别入口壳：只修复指向包内的链接，不把入口壳改回全文、也不把全文改成壳
- 状态文件新增形态值（如 `gate`），与 `link` / `copy` / `shell` 并列

### 3. 接入范围

- 首批只接 core 三个技能（`fxri-plan-to-task`、`fxri-session-recap`、`fxri-plan-review`），验证无误后再推广
- 每个接入技能需同步递增 `metadata.version` 与正文首部版本号，并更新 `skills/README.md`、`docs/guide.md` 版本表
- 未接入技能保持全文，不因闸门开启而受影响

### 4. 文档

- `docs/cli/exit-codes.md` 新增退出码 `3`（技能未在当前目录激活）
- `docs/cli/skills.md` 补 `--gate` / `--embed` 与形态展示
- `docs/cli/scope.md` 补 `guard` 契约与 AI 调用约定
- 文档明确：入口壳只降低“正文被读取”的概率，不是物理隔离；需要绝对干净用项目面安装

### 5. 性能约束

- `guard` 是每次技能使用都会执行的命令，成本必须可控：快速路径只读一次配置与包内正文，不扫描目录、不启动 git（未配置时）
- 目标：含 Node 启动在内 < 200ms（本机基线：空进程约 140ms、完整 CLI 启动约 400ms）；实现后用计时命令复核
- `--gate` / `--embed` 切换按目标目录逐个写入，保持幂等；不做全盘递归扫描

# 交互式作用域管理与批量挂载

> 计划位置：第 2 个（共 3 个）；前置：20261120-唐启云-全局作用域解析与只读命令；后继：无

## 背景

作用域是给人用的能力，必须可交互、可预览、低心智负担。默认路径只写全局配置，不侵入项目；批量「项目面安装」作为
可选的强隔离手段保留，但必须由用户明确选择，并在执行前说明「会在所选仓库里写文件」。

## 方案

### 1. 无参交互入口

`toolkit scope` 进入菜单：

- 查看当前状态（复用任务 1 的 `status`）
- 选择生效模式：全部生效（默认）/ 只在我选的目录 / 除了我选的目录
- 管理目录：添加 / 移除（多选，最近目录候选 + 手动输入；不要求用户手写 glob）
- 预览：展示“以下 N 个目录将生效、以下 M 个被排除”
- 批量挂载（默认不选中，见下）

### 2. `scope add` / `scope remove`

- 写前预览，写后打印摘要；只改全局 `~/.toolkitrc.json`
- 写配置走「读 → 合并 → 原子写」：复用 `writeFileAtomic`，只覆盖 `activation` 段，保留用户其它配置；并发写不产生半截文件
- 用户取消不落盘；配置损坏时告警并给修复指引（降级不静默）
- 不改、不建任何项目内文件

### 3. 批量挂载（显式选择）

- 扫描用户指定的父目录，**只下探一层**识别仓库：判定顺序 `.git` → `package.json` → 已有 `.tasks`；
  跳过 `node_modules` / `dist` / `.git` 内部，条目超过 500 个时提示并停止扫描
- 多选目标仓库，先 `--dry-run` 预览，再对所选仓库执行 `toolkit skills install --scope project`
- 批量挂载在**同一进程内逐个执行**安装逻辑，不为每个仓库 spawn 一次 CLI；进度与错误走 stderr，stdout 只放结果摘要
- 明确提示「本操作会在所选仓库写入技能真源 / 入口薄壳 / 状态账，可能含项目规则文件」；
  默认不选中、不自动执行
- 逐仓库报告成功 / 跳过 / 失败；失败不中断其余仓库
- 可选生成项目规则文件，同样需显式勾选

### 4. 性能约束

- 交互与预览不做安装动作；只有确认后才写盘
- 目录扫描只一层、有上限；单仓安装成本沿用现有 `skills install`，批量时逐仓输出进度，避免长时间无反馈
- 不读取 git 历史、不递归整棵树

### 5. 不变式

- 除用户明确选择「批量挂载」外，本任务不产生任何项目内写入
- 交互计划抽为纯函数（模式 / 目录选择 / 挂载计划），便于单测

# 全局作用域解析与只读命令

> 计划位置：第 1 个（共 3 个）；前置：无；后继：20261120-唐启云-交互式作用域管理

## 背景

全局安装 toolkit 与技能后，默认对所有项目生效。用户希望按项目 / 父目录 / 排除项 / marker / git 远端等条件决定生效范围，
但要求：**默认行为与今天完全一致**；只有写了「特定配置」才出现局部生效；工具**不主动往用户项目里写配置**；
用户自己愿意在项目里写配置时，该配置应正常参与（沿用现有就近查找语义）。

本任务只做「解析 + 只读命令」，不写任何配置文件，是后两个任务的基础。

## 方案

### 1. 配置模型（`activation` 段）

```json
{
  "activation": {
    "mode": "allowlist",
    "include": ["~/work/**"],
    "exclude": ["~/work/legacy/**"],
    "markers": { "include": [".toolkit-scope"], "exclude": [".toolkit-off"] },
    "gitRemotes": ["github.com/acme/**"]
  }
}
```

- `mode`：`all`（默认，等同今天）/ `allowlist` / `denylist`
- 覆盖变体：指定项目、父目录（多仓库）、排除项目 / 目录、marker 文件、git 远端
- 查找沿用现有三层：全局层 → 项目层（自 cwd 向上最近）→ 本地层；就近者整体覆盖上级，数组整体替换
- 工具**不创建、不修改**任何项目内配置或 marker；项目层若由用户自行写入，正常参与解析
- 路径判定：`~` 展开、glob、Windows 分隔符归一、**按 realpath 判定**（防符号链接绕过）；判定顺序固定并可解释
- 不新增运行时依赖：glob 只实现最小子集（`**` / `*` / `?` / `~`），其余字符按字面匹配，并配表驱动单测
- 查找与判定是纯字符串操作，不做目录遍历；`gitRemotes` 未配置时**不启动 git 进程**；marker 只检查 cwd 与 git 根两处
- `scope status --format json` 固定字段：`active` / `mode` / `sourceFile` / `matchedRule` / `reason`（字段增删视为契约变更）
- `config status` 的展示键保持现有四项不变（固定契约不扩），作用域判定统一由 `scope status` 呈现
- 单技能作用域不在本次范围；若后续确有需求再单独评估

### 2. 只读命令

- `toolkit scope status [--format json]`：当前目录是否激活、命中的配置文件与具体规则；JSON 供 AI 与脚本消费
- `toolkit scope list`：规则清单、来源与优先级
- 两命令均只读，不改配置、不写缓存

### 3. 边界

- 不改变 `skills` / `rules` 的现有行为；未配置时 `status` 恒为 active
- 不新增退出码；判定结果通过 stdout 与 JSON 字段表达
- 解析逻辑抽为纯函数，供后续 `scope` 向导与 `guard` 复用

### 4. 性能约束

- 每次判定最多读三层配置各一次，不做递归扫描、不遍历目录树
- 未配置 `gitRemotes` 时零子进程；配置时 git 调用超时 1s，失败按未命中处理并告警

# 运行时兼容 Node 18

> 计划位置：第 1 个（共 2 个）；前置：无；后继：20261120-唐启云-统一快速开始的官方推荐路径

## 背景

用户在 Node 18.20.8 下执行 `toolkit skills install` 报
`The requested module 'node:util' does not provide an export named 'styleText'`，退出码 1，且提示里没有任何版本线索。

根因：运行时依赖 `@inquirer/prompts@8.7.5` 的 `@inquirer/select` / `@inquirer/core` 在模块顶层写
`import { styleText } from 'node:util'`，而 `util.styleText` 自 Node 20.12 才存在；Node 18 的 ESM 链接器在加载阶段直接抛错，
toolkit 的六处惰性动态导入（`src/skills/prompt.ts L183/L204/L223`、`src/usage/wizard.ts L208/L398/L449`、`src/usage/upload.ts L256`）
只要走到交互路径就命中，`src/commands/skills.ts L911` 把英文原文当作安装失败原因打印。

同族问题：`@changesets/cli@2.31.1` 经 `@changesets/write@0.4.0` 依赖 ESM-only 的 `human-id@4.x`，Node 18 下 `changelog` 透传子命令报
`ERR_REQUIRE_ESM`；`commander@14` 声明 engines `>=20`。仓库当前 `engines.node` 为 `>=20.19.0`，但 engines 只是安装期警告，
用户仍会落到「能装、跑到一半崩」的状态；CI 四作业全部使用 `.node-version`（20.20.2），声明的门槛从未被执行过。

目标：CLI 运行时（全部命令，含 TTY 交互与 `changelog` 透传）兼容 Node 18.17+；开发环境保持 `.node-version` 的 Node 20.20.2 不变。
Node 18 已于 2025-04 EOL，只保证可运行，不含安全补丁，文档需标注。

## 方案

### 1. 依赖与构建

- `package.json`：`@inquirer/prompts` `^8.7.5` → `^7.10.1`（engines `>=18`，接口不变）
- `package.json`：`@changesets/cli` `^2.31.1` → `^2.27.12`（`@changesets/write@0.3.2` → `human-id@1.x` CJS）
- `package.json`：`commander` `^14.0.3` → `^13.1.0`（engines `>=18`）
- `package.json`：`engines.node` `>=20.19.0` → `>=18.17.0`（下限由 `mute-stream@2` 的 `^18.17.0` 决定）
- `tsup.config.ts` / `tsup.dev.config.ts`：`target: "node20"` → `"node18"`
- `tsconfig.json`：`target: "ESNext"` → `"ES2022"` 并显式 `lib: ["ES2022"]`（`tsconfig.typecheck.json` 继承同一取值），
  把 Node 18 不可用的 ES2023+ API 挡在类型层；若触发存量类型错误，逐个改为 Node 18 可用的等价写法，不放宽 `lib`。
  注意显式 `lib` 会移除默认注入的 DOM，以 `pnpm typecheck` 结果为准：若存量依赖 DOM 类型则补 `DOM` 或改为 Node 原生写法
- `pnpm install` 重建 lockfile
- `@types/node` 决策规则：先降为 `^18.19`（18 线最新），让类型层拦住 Node 20-only API；若 `pnpm verify` 出现无法收敛的类型冲突，保留 `^20`，

## 20261120-唐启云-补充阻塞节形态与导入归档告警

> 负责人：唐启云　状态：已完成　范围：toolkit　完成时间：2026-11-20 15:25

# 补充阻塞节形态与导入归档告警

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无
> 延续「补充已放弃任务的放弃理由校验」（见 `.tasks/archive/202611/20261120.md`）

## 背景

三个使用方项目的历史归档里已有 5 处阻塞节，形态各不相同：标题有 `## 阻塞与解除记录`、`## 阻塞说明`、`## 阻塞记录（日期）`、`## 阻塞记录` + `## 解除阻塞记录`、
`## 阻塞结论（日期）` 五种；结构有「时间线叙述 / 单段 / bullet」三种；日期有标题带、正文带、不写三种。
其中一个 active 档在转 `搁置` 后仍残留 `## 阻塞结论`，说明「阻塞转其它状态时该节如何处理」也从未定义。
这与搁置档当初的漂移同源，Rule of Three 已触发，需要定形态并加软告警。

另一处静默口：`tasks import --target archive` 按表格行直接生成归档块，不经过 `check` 也不经过 `archive` 命令，
已放弃记录可以不带放弃原因直接写进归档（上一任务只覆盖了 `archive` 命令入口）。

## 方案

### 一、`## 阻塞` 节形态

1. **位置**：当前状态的节须是正文第一个二级标题，历史状态节紧接其后、背景等其它 `##` 之前（不让注记漂到文末）；
   阻塞转搁置时 `## 搁置` 在前、`## 阻塞` 紧随其后。历史节的位置是规范约定，`check` 只校验「当前状态的节是第一个二级标题」，
   不对历史节做位置告警（避免正文结构差异造成误报）。
2. **标题**：固定 `## 阻塞`，不带日期（日期只写进「阻塞日期」一行，避免双真源）。
3. **三行固定**：阻塞原因 / 解除条件 / 阻塞日期（`YYYY-MM-DD`），须位于节首、顺序固定，全角冒号、句末不加句号；
   三行之后允许补充叙述行。
4. **解除后保留**：转 `进行中` / `已完成` / `搁置` 时保留该节，并在三行之后追加一行 `- 解除记录：YYYY-MM-DD …`
   （以日期开头才计入解除记录；「解除方向：…」这类描述行不算，避免误判）。历史样本里解除决策（如「用户裁决采用口径 1」）是主要价值，
   删除会让它只剩 git 可查。
5. **进入阻塞**：由 `进行中` / `待办` 转入时新增该节并填三行；由 `搁置` 转入时删除 `## 搁置` 节、改按本节记原因
   （两侧不对称是刻意的：搁置节是「何时恢复」的前向指针，过时即误导，故唤醒删节；阻塞记录是「为何卡住、怎么解除」的后向证据，故解除保留）。
6. **与放弃并存**：阻塞后放弃时保留阻塞节，另按 §2.4 写 `> 放弃原因：…`。
7. **重复进入阻塞**：同一档只保留一个 `## 阻塞` 节；再次进入时把三行覆盖为本次内容，解除记录按时间追加在下方
   （历史细节留 git 与既有解除记录），不新建第二个同名节——`check` 只认第一个节，建第二个会静默失效。

### 二、`tasks check` 软告警（warn，不阻断）

- `status: 阻塞`：缺 `## 阻塞` 节、三行缺项 / 顺序错 / 半角冒号、阻塞日期非 `YYYY-MM-DD` 或日期不存在 / 晚于今天（留 1 天容差）；
- `status: 阻塞` 且存在**日期晚于「阻塞日期」**的 `- 解除记录：` → warn（解除后未把状态转回）；
  按日期比较而非“存在即告警”，否则重复进入阻塞后保留的旧解除记录会误报；
- 非阻塞状态：允许保留该节（历史注记），**不做残留告警**，也**不校验其形态**（三行残缺同样不报）——历史注记的价值在内容而非格式，
  对非当前状态加形态约束只会制造噪音；也不校验位置；

## 20261120-唐启云-统一搁置档规范并增加校验

> 负责人：唐启云　状态：已完成　范围：toolkit　完成时间：2026-11-20 14:48

# 统一搁置档规范并增加校验

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无
> 延续「新增搁置任务状态」（见 `.tasks/archive/202611/20261118.md`）

## 背景

`搁置` 状态引入后只规定了「四行必写」，没有规定这四行放在正文哪个位置、节标题长什么样、项名与标点如何书写，
`tasks check` 也只校验状态枚举合法、完全不读正文。规范留白 + 机器不校验，导致多个使用本工具的项目各自长成不同形态：
节位置有开头与末尾两种（`docs/guide.md` 只说「正文记四行」）、标题有带日期与不带日期两种（带日期的与「搁置日期」一行形成双真源）、
句末标点有带与不带两种。同一份技能规范在不同项目里产出不同形态的任务档，恢复会话时也无法只读固定位置就取到摘要。

本任务只补规范与校验（本仓能力）；各项目存量搁置档的一次性归一属外部仓改动，按「跨仓库改动各自归档」由各仓另行建档，不在本任务范围。

## 方案

### 一、搁置节形态定稿

1. **位置**：`# 标题` → `> 计划位置行`（缺该行时紧跟标题）→ `## 搁置` → 背景等后续正文。摘要前置，
   与「恢复时只读 frontmatter + 四行」的读取路径一致，避免读完全文才能判定能否跳过。
2. **节标题**：固定 `## 搁置`，不带日期。日期只写四行里的「搁置日期」，避免标题与正文双真源。
3. **四行固定顺序与项名**：搁置原因 / 重启条件 / 进度锚点 / 搁置日期，全角冒号，句末不加句号（列表项体例）。
4. **搁置日期格式**：`YYYY-MM-DD`（与 `completed` 的 `YYYY-MM-DD HH:mm` 区分，盘点按日差计算）。
5. **重启条件须可判定**：写可观测事件（契约提供 / 窗口确定 / 决策落定），不写「以后再说」「视情况」。
6. **唤醒与离开搁置**：转回 `待办` 时删除整个 `## 搁置` 节，不留「曾搁置」段；且唤醒前须复核方案与重启条件是否仍成立，
   不成立先修订方案再转 `待办`。转 `阻塞` 同样删节，改按阻塞口径在正文记原因；转 `已放弃` 时**保留**该节并随任务归入归档块——
   否则归档后只剩方案，丢失「为何放弃」。
7. **搁置日期口径**：搁置日期 = 本次进入搁置的日期，不因 90 天盘点的「继续搁置」刷新（刷新会让超期提醒永远不触发，与超期可见性冲突）；
   先唤醒再重新搁置视为新一次搁置，日期才刷新。盘点选「继续搁置」不改档、不碰 `updated`。
8. **计划位置快照**：搁置期间冻结「计划位置」行原值，同批其他档唤醒 / 放弃导致序号失真时不回写；唤醒时按当时的 active 集合重排再转 `待办`。

### 二、`tasks check` 增加软告警（warn，不阻断）

`status: 搁置` 的档：

- 正文缺少 `## 搁置` 节（按 `^## 搁置\s*$` 精确匹配，避免误命中「## 搁置方案」类标题）；
- 四行缺任一项、顺序与规定不一致、冒号用了半角；
- 「搁置日期」不是 `YYYY-MM-DD` 或日期不合法、晚于当前系统时间。

`status` 非搁置的档：

- 正文残留 `## 搁置` 节（唤醒未删节的直接症状）；`已放弃` 例外——该节保留在归档块内作为「为何放弃」的终结理由。

另校验**节位置**：`## 搁置` 须是正文第一个二级标题（位于标题与计划位置行之后、任何其它 `##` 之前），否则 warn——
位置是本次统一的起因，不校验位置等于只统一了一半。节内四行之后允许补充叙述行（如依赖的任务键），不视为违规。

实现落在 `src/tasks/validate-file.ts` 的单文件校验内（与 frontmatter 同类问题一并输出），复用既有的 warn 级别与 `--no-warn` 开关，
不改任何既有 error 判定。

### 三、搁置超期可见性

「90 天 / 1 年盘点」原来只有条文、没有触发点，靠人记得主动盘点。在 `tasks` 总览（含 `--status 搁置`）中把时长显性化：

- 搁置行追加「搁置 N 天」，超过 90 天加 `⚠️` 标记、超过 1 年加「建议终结」提示；

`20261119-唐启云-收敛全局规则为薄壳`（`archive/202611/20261119.md`）按「稳定纪律 / 可变细节归技能」两类清洗 `workflow` 模块，把「任务收尾的 git 提交自动执行（作者个人收紧，可参考可裁剪）」一并删掉。

该条无法归入任何一类：它是**用户个性化偏好**——每个用户不同，技能随包分发不能编码它。技能侧也明确把决定权交回规则层（`skills/fxri-plan-to-task/references/task-spec.md`「是否执行取决于用户的全局 / 个人 / 项目规则」），于是形成「规则 → 技能 → 规则」的循环，而规则端已被清空，行为退化为默认不自动提交，且用户无从发现该开关曾存在。

## 背景

可复制规则块会整段进入 AI 上下文，但 **AI 同样按读者对待**——不能因为「这句话是给人读的」就删掉。收录判据按价值三分：

| 类别 | 判断 | 示例 | 处置 |
| --- | --- | --- | --- |
| 对业务有用 | 指导动作、判定条件、单一事实源指引 | 「提交默认需你确认」「任务管理细节以已加载的 fxri-* 技能为准」「正文示例（可选）」 | 留在块内 |
| 解释性 | 说明为什么这么写、模块归属、升级与分发入口 | 规则模块准入标准、「本模块暂无对应技能」、见文档站快速开始 | **移出块内，但页面保留可见** |
| 对业务与人都无用 | 重复复述、过程记录、已失效的旧路径 | 实施中发现的重复句 | 清理，并在完成情况列明 |

本任务的移出项（不删，全部在页面落位）：

| 条目 | 现位置 | 页面落点 |
| --- | --- | --- |
| 规则模块准入标准（「本模块只放稳定纪律…」） | `templates/rules/workflow.md` 第 5 行 | `docs/rules/ai.md` 说明区 |
| 「本模块暂无对应技能，上报流程细节直接由本模块承载」 | `templates/rules/usage.md` 第 5 行 | `docs/rules/usage.md` 页首说明 |
| 「安装、升级与技能分发细节见文档站「快速开始」」 | `templates/rules/env.md` 第 5-6 行 | `docs/rules/ai.md`「配套安装」节 |

块内保留但改写一处：`templates/rules/workflow.md` 末条去掉文档自指的「本规则不复述」，保留业务指引「任务管理细节以已加载的 fxri-* 技能为准」。

2. `templates/rules/usage.md`：第 5 行移出（页面落位见第 5 步）；其余条目不动。
3. `templates/rules/env.md`：去掉页面导航句，只留安装命令与「不自行执行全局安装」；导航信息移入页面。

# 规则锚点只保留时间戳

> 计划位置：第 1 个（共 3 个）；前置：无；后继：20261120-唐启云-规则块内读者说明移到页面

## 背景

组合输出的首行由 `src/rules/core.ts` 的 `ruleAnchorLine` 生成，现为
`> 规则更新时间 YYYY-MM-DD HH:mm。本规则内容变更时以变更时刻更新此值；快照与本规则当前值不一致即说明已失同步，重新复制本规则即可。`

后半句是写给「正在读规则页的人」的同步说明，却随规则一起被复制进用户的规则文件。用户裁定：复制块首行只保留时间戳，同步说明移到页面正文（围栏外），页面仍是用户复制的入口，说明照旧可见。

关联：本条属 `20261119-唐启云-收敛全局规则为薄壳` 的后续清理（见 `archive/202611/20261119.md`）——收敛时未区分「AI 面向」与「读者面向」文本。

## 实施方案

1. `src/rules/core.ts`：`ruleAnchorLine` 只返回 `> 规则更新时间 ${time}`；函数注释改为「块内只留时间戳，同步说明在规则页正文」。
2. `src/__tests__/docs-consistency.test.ts`：
   - 围栏首行正则（现 `L263`）去掉时间后的「。」；
   - 原「组合输出锚点使用「本规则」措辞」用例（现 `L286-290`）改为反向断言：组合首行须逐字匹配 `^> 规则更新时间 \d{4}-\d{2}-\d{2} \d{2}:\d{2}$`，且组合正文不含「重新复制本规则即可」。
3. 用 `node dist/cli.js rules compose` 按各页模块组合回填围栏块（ai / commit / usage），不手改块内正文。
4. `docs/rules/ai.md`、`docs/rules/commit.md`、`docs/rules/usage.md` 围栏外各补或校一句「首行时间与本页当前值不一致，即说明快照落后，重新复制即可」（ai.md 已有，校措辞即可）。
5. 重新生成 `rules.generated.ts`（`pnpm sync:docs-rules`）与 `cli-golden` 快照。
6. `.changeset/` 一条 patch：修改——规则快照首行只保留更新时间，同步说明移至规则页正文。
