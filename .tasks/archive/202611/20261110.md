# 修正link模式技能版本误报

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

全局 CLI 升到 1.16.8 后，`toolkit usage stats` 仍提示「fxri-plan-to-task 1.10.7 → 1.10.8 可更新」，但目标目录软链指向的 `SKILL.md` 实际已是 1.10.8，`toolkit skills status` 也显示 1.10.8 且 8 项正常。

根因在 `src/skills/version-status.ts` 的 `accumulate`：`installed` 只取状态文件 `~/.agents/.toolkit-skills.json` 的 `entries[].version`，该值仅在 `skills install` 时写入。软链模式下内容随包升级，但状态记录不刷新，于是「记录版本 1.10.7 vs 包内真源 1.10.8」必然误报一次，直到下次 `skills install` 重写记录。

同类排查结论：

- `src/skills/status.ts` 的 `stateVersions` 只在来源根不可解析时兜底展示，属「读不到真源」的合理回落，不改。
- `toolkit skills sources` 展示的是**来源级**版本，与技能自身版本独立编号，不是同一问题，不改。
- `hasGlobalSkillsInstalled()` 只读状态登记：人工删除目标目录后会误判为「已安装」，影响 `init` 的提示口径（低危，本次不改，列为后续候选）。
- `update-check` 的 `dismissed` 按「技能 + 最新版本」记，来源版本变化会自动恢复，CLI 升级后旧记录整体失效，机制本身无缺陷。

## 实施方案

1. `src/skills/version-status.ts`：累积结构改为保存每条登记的目标目录与 `mode`；`link` 模式解析目标目录下 `SKILL.md` 的实际版本（读不到时回退记录值），`copy` / `shell` 模式仍用状态记录——副本与薄壳不会随包升级。多目标仍取最低已装版本，保持「任一目标落后即提示」。
2. 调整 `src/__tests__/version-status.test.ts`：既有用例按新口径造现场（link 写实际文件、copy 仅写记录）；新增两条用例——link 记录落后但实际文件已新则不提示、copy 记录落后则仍提示。
3. 文档 `docs/config/update.md` 的「版本比较口径」补一条：已装版本按落点形态取证（link 读目标文件、copy / shell 读状态登记）。
4. 建 `patch` 级变更集。

不做的事：不改 `skills status` 与 `skills sources` 的版本来源；不在 `skills install` 之外自动改写状态文件（保留显式动作）。
