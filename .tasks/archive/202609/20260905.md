# .toolkitrc.json 全局配置支持

## 背景与目标

当前配置仅支持项目级：从 `process.cwd()` 向上查找最近的 `.toolkitrc.json`。个人偏好类配置（关升级提示、个人脱敏规则、自定义语言表）写进项目会共享给全团队，环境变量只对单次会话生效——需要全局配置层。已经用户确认立项，并定性为「原设计缺失的配套修补」，按 patch 归档变更集。

## 方案设计

- 全局文件位置：`~/.toolkitrc.json`（`os.homedir()`，Windows 即 `C:\Users\<用户>\.toolkitrc.json`），与 `.gitconfig`/`.npmrc` 惯例一致
- 查找与合并：
  1. 向上查找最近的 `.toolkitrc.json`（现状不变）

- 覆盖链不变：CLI `--flag` > 环境变量 > 项目配置 > 全局配置 > 默认值

## 变更范围

- 代码：`src/config.ts`（约 +20 行）；`src/__tests__/config.test.ts` 补全局层用例（合并/覆盖/非法文件/缓存失效）

现有 README/SPEC 无法支撑新用户自助上手。按需求拆分为双形态内容（GitHub 直读 + VitePress 站点同源），能力前置、链接跳详情、去重收敛。

## 实施方案

docs/ 下新建八篇：

1. `index.md` 站点首页：是什么/解决什么痛点/能力矩阵/文档索引
2. `getting-started.md` 新手指南：30 秒上手、零基础术语、安装三方式对比（项目 devDep / 全局 / 独立 pnpm，含 nvm/corepack 切版本陷阱）、能力前置链接
3. `guide.md` 完整攻略：方案落盘（任务如何产生）、会话归档、Git 纳管范围（.tasks 整体入库、.toolkitrc.json 建议提交、.archive.lock 忽略）、项目级强制激活模板、三平台部署发布、多语言 CHANGELOG
4. `cli.md` CLI 参考：tasks/changelog/init 全命令、参数、默认值、退出码、help footer 说明
5. `api.md` Node API 参考：按 src/index.ts 实际导出编写，纯 CLI 则并入 cli.md（执行时确认）
6. `config.md` .toolkitrc.json 参考：字段枚举、脱敏规则、scope 校验
7. `faq.md` FAQ：工具与 skills 的区别、.tasks 入库范围、node 切版本全局包丢失、只在公司项目激活、会话归档边界等（匿名化，不留真实人名）
8. `ai-rules.md` 推荐全局规则：源自作者自用全局规则三层转化（通用 AI 协作规则原样 / toolkit 专属工作流视角转换 / 安装升级校验命令直接可用），去标识处理；升级后开新会话 ⚠️ 强调

补充（用户确认，防止遗漏）：

- **工具与 skills 的关系结论必须显式成章**：skills 独立可用（零依赖纯 Markdown，装了即可跑通工作流）；工具是可选加速（自动建档/校验/归档）；推荐都装但不强制。落在 getting-started.md（入门视角）与 faq.md（答疑视角）两处
- **零基础术语科普（不懂 AI 的用户也看得懂）**：真实用户反馈「skills 是啥我都还没怎么研究过」——getting-started.md 增设「几个术语，先说人话」小节（AI 编程助手/agent/skills/MCP/CLI 用类比解释，不堆缩写）；faq.md 增设「skills 是什么？和插件/脚本有什么区别？」「我不用 AI，这个工具对我有用吗？」条目；全文避免未解释的缩写首次出现即使用
- **文档美化**：八篇统一页面结构模板（标题 → 一句话定位 → 「解决什么问题」→ 正文 → 「相关页面」互链）；index.md 用 hero 首屏布局；表格/代码块/⚠️ 注意事项风格统一；README 入口页与 SPEC.md 同批美化

同步：SPEC.md 瘦身为规范摘要+站点链接；各能力页开头统一「解决什么问题」小节。
