1. **条目无稳定身份**：索引表首列是序号（1..23），插入或重排即漂移；载体内部对条号的引用（`index.md` 用法说明的「如第 23 条」、`common.md` 的「与索引第 17 条配套」）是活指针，条号一变即失准。演进记录与索引表同文件，把「写」（每次语义变更追加）与「读」（每次建档 / 恢复常驻读）两类不同频次的访问混在一起。
2. **无触发面**：载体只在 AI 建档 / 归档时被主动读取，用户不主动问「本项目有哪些规范」就接触不到；而 Agent Skills 标准已把「项目态 + 随 git 提交 + 团队共享」的项目级技能目录做成熟（Trae `.trae/skills/`、Cursor / Claude 的 `.agents/skills/` 等，`.agents/skills/` 是规范约定的中立共识目录），载体结构与其三层渐进披露几乎一比一映射，缺的只是一个入口壳。

## 实施方案

### 一、载体 v2 规格

`index.md` 由「四节」改「三节」，首行为形态标记，索引表首列改稳定 ID：

```markdown
<!-- toolkit-conventions: v2 -->
# 项目协作规范索引

> 唯一入口与唯一权威：端清单在此声明、每条规范在此留一行指针；分册（`common.md` / `<端名>.md`）按需创建。
> 端名与任务 frontmatter 的 `scope` 取值共用同一套词表、逐字一致；保留字 `index` / `common` 不得作端名。
> 演进记录见 `history.md`；超长条目升级见分册。

## 一、端清单
## 二、索引          ← 首列改 ID
## 三、用法说明
```

- **标记**：`<!-- toolkit-conventions: v2 -->` 置首行，首 token 即版本标识、留扩展位；仅**破坏性结构变更**递增（+1），措辞修正不递增；无标记即「引入机制前的形态」（代号 v1）。标记不写包版本号——写包版本会让「发版即全员过时」。
- **ID**：`C-<n>`（`C` 表 conventions），去补零、不带端前缀、只追加不重排不回收；容量不是问题（3 位 vs 无补零均可），去补零取的是可读性。引用一律行内代码包裹（`` `C-17` ``），便于机械匹配 `C-\d+(?!\d)`。
- **`history.md`**：演进记录独立成文件（`# 规范演进记录` + 三列表 `规则 ID / 名称 | 修订内容 | 修订来源任务`），**仅追加、不改旧行**；表语义边界写死——载体结构升级、入口壳生成 / 删除均**不入表**（表只记规范语义变更）。
- **形态识别（结构为主、标记为辅）**：有 `history.md` 且索引表首列表头为 `ID` → v2；首列为 `#` 且无 `history.md` → v1；有 `history.md` 但首列仍是 `#` → **形态异常，拒绝自动处理，提示人工确认**。
- **载体内部活引用**：`upgrade` 只改写**裸「第 N 条」且 N ≤ 索引表最大序号**的引用（形如 `` `C-23` ``）；带限定词前缀的引用（如 `AGENTS.md` 质量门第 5 条、`SPEC.md` 协作模型第 3 条、`task-spec.md` 第 6 节）一律不动。改写清单进报告。

### 二、`toolkit conventions` 命令域（独立域）

- `conventions upgrade`：v1 → v2 结构升级（纯机械：发 ID / 切 `history.md` / 改内部引用为 ID / 首行补标记 / 标题归一 / 节号重编 / 分册小节标题序号归一），幂等；`--dir`、`--dry-run`（报告样式照抄 `skills install` 的 `[预演] ` 前缀 + 固定尾行）；**先判后写**，遇形态异常拒绝执行并给非 0 退出码（异常态不写任何文件）。
- `conventions status`：只读体检报告（形态 / 索引体检 / 入口层生态三块），`--format json`，**退出码恒 0**，不给 `--fix`；未初始化项目输出单条明确结论（如「未找到 `<dir>/conventions/`，先执行 toolkit init」）而非一堆异常项。
- ID 映射**不落盘**：映射由 `upgrade` 输出（实跑与 `--dry-run` 均打印）；真值可由 git 历史复现（迁移提交的父提交即 v1 原件），故不落盘的代价近零。

### 三、`check` 形态告警（保持「不读内容」）

`validateConventions` 由二态升三态，只读首行标记与文件存在性，不读表内容：

- v1（有 `index.md`、无 `history.md`、无标记）**合法存量形态，不告警**
- 有 v2 标记但缺 `history.md` → 告警（提示跑 `conventions upgrade` 或补齐）
- 无标记但有 `history.md` → 告警（形态异常，提示人工确认）
- 入口层：壳存在但被 gitignore 覆盖、壳 marker 与载体标记不匹配时告警

### 四、`init` v2

- `CONVENTIONS_INDEX` 骨架换 v2（三节 + 首行标记 + 首列 ID + 标题归一 `# 项目协作规范索引`）
- 新增技能壳生成：写入检测命中的项目级技能目录（优先 `.agents/skills/`，其次 `.trae/skills/` / `.cursor/skills/` / `.claude/skills/`），目录名与 `name` 同名 `toolkit-conventions`，幂等不覆盖
- 新增 `AGENTS.md` 指针块：**仅当文件已存在**时幂等追加标记块，不存在不新建
- `initWorkspace` 由 `void` 改返回 `InitReport`，`init` 逐项打印**实际动作**（新建 / 保持 / 追加 / 跳过及原因），取代现在只讲「会做什么」的固定三行；遇到「保持」的 v1 载体时提示可跑 `conventions upgrade`
- `init` 的 `--help` description 与 `docs/cli.md` 同步补两项产物

壳正文（不写死 `.tasks/`——任务区可外置，路径由 AI 按配置解析）：

```markdown
<!-- toolkit-conventions-entry: v2 -->
<!-- 由 toolkit init 生成，可安全删除；需要时重跑 toolkit init 即可补齐 -->
本技能只是入口，不承载条文：读本项目任务区（默认 `.tasks`，已配置 `tasks.dir` 时按配置声明）下的 `conventions/index.md`，按其「用法说明」节执行；条文以各文件的单一事实源为准。
```

### 五、自举迁移本仓库载体

作为 `upgrade` 的首个验证场：23 条发 `C-1`..`C-23`、13 条演进记录切 `history.md`、内部引用 `index.md`（「如第 23 条」「仅第 23 条需再翻 `common.md`」）改 `C-23`、`common.md` 的「与索引第 17 条配套」改 `C-17`、标题归一、首行补标记；`index.md` 第 4 行的告警口径段补 v2 形态描述。

⚠️ 本仓库自举**不生成自己的入口壳**（源仓库靠 `fxri-*` 技能自举，壳只对使用者项目有意义）：壳生成走内部开关，自举验证时关闭，**不给用户暴露新参数**。

## 验证与回滚

- 验证：`pnpm verify`（含类型检查、冷缓存静态检查、单测、覆盖率、构建、文档站构建、CLI 冒烟、任务区体检）；另手工跑 `node dist/cli.js conventions status` 与 `upgrade --dry-run` 核对本仓库载体判为 v2、报告无异常项；`node dist/cli.js init` 在临时目录实跑两次核对幂等与动作报告
- 发版前门禁前置：涉及对外行为（新命令、新告警口径、init 产物变化），归档前完成三方一致复核（代码 / 测试 / help 与文档、skills 版本双写）并建变更集
- 回滚：改动集中在单一提交，回滚即 `git revert`；自举迁移的 v1 原件保留在迁移提交的父提交中，可随时对照恢复
- 上线次序：先落结构层（规格 + 命令 + check + init 骨架）→ 自举升本仓库载体 → 再落入口层（壳生成 + gitignore 探测 + AGENTS.md 指针），避免首次 `status` 满屏「需升级」噪声
