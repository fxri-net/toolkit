## 20260912-唐启云-skills包内分发与全局安装

> 负责人：唐启云　状态：已完成　范围：toolkit　完成时间：2026-09-12 15:02

# skills 包内分发与全局安装能力

## 背景

现状装/升级需两条**互不相关**的命令：`pnpm add -g @fxri/toolkit`（CLI，走 npm registry）+ `pnpm dlx skills add fxri-net/toolkit --global`（skills，走上游 vercel-labs/skills 从 GitHub 拉取）。两条供应链版本无关联，易漂移，心智负担高。

上游另有两条未修缺陷直接落在本场景：

- issue #537（open）：全局安装时 canonical 副本写入成功，但 agent 专属目录（`~/.cursor/skills` 等）**不被创建**，`skills list -a <agent> -g` 显示 `Agents: not linked`，需用户手动 mkdir 或重装；
- issue #693（open）：Claude Code 全局不读 canonical，只读 `~/.claude/skills`。

本任务把 skills 改为**从包内 `skills/` 目录分发**（`package.json` 的 `files` 已含 `skills`），新增 `toolkit skills` 命令域，使**升级阶段一条命令**即可，并正面绕开上述两条缺陷。

已核验事实（来源可查）：

- Agent Skills 规范只定义技能目录结构与 frontmatter 字段，**不规定安装位置**（agentskills.io/specification）；
- `~/.agents/skills/` 是上游安装器**自设的 canonical store**，非标准；上游表中 7 家 agent 共读该目录；
- 上游维护 75+ agent 的全局/项目路径表且持续新增 → 内置表必然过期，需 `--dir` 兜底；
- 上游支持**本地路径源**安装（`npx skills add ./path`），可作为表外 agent 的委托路径；
- pnpm v10 起**默认禁止依赖执行 postinstall** → 依赖 postinstall 自动装 skills 不可靠；
- Windows 上 `fs.symlink(target, link, 'junction')` 创建 junction **免管理员、免开发者模式**，POSIX 忽略 `type`；实测 junction **可跨本地卷**（本机 `C:\Users\<user>\__jtest_cross__` → `D:\...\skills\fxri-plan-to-task` 创建成功且可读，`isLink=true`），失败场景落在网络路径（UNC）、非 NTFS 卷、权限不足等，而非跨盘。

## 实施方案

**命令面**（新增 `skills` 域，仿 `init` 的 commander 写法）：

- `toolkit skills install [--copy] [--dir <path>]... [--dry-run] [--force]`
- `toolkit skills status`
- `toolkit skills remove [--dry-run]`
- `toolkit skills path [--json]`

**真源与目标**：真源 = 包内 `<包根>/skills/<name>/`（含 `SKILL.md` 才计为技能）。所有目标目录**一律链接到真源**——与上游「canonical 存真身」的做法不同，本方案真源唯一、无链中链、`pnpm add -g` 升级后所有链接自动跟随。

目标分三层：

1. 主目标 `~/.agents/skills/`（上游 canonical，7 家 agent 共读）；
2. 附加目标 = 内置快照表中**已安装**的各 agent 全局技能目录（判据：技能目录的父目录即该 agent 配置目录存在；不存在则只报告不创建，避免在用户机器上凭空造目录）；
3. `--dir <path>`（可多次）任意目标，兜底表外新 agent，无需等 toolkit 升级。

**链接与降级**：默认软链（POSIX `symlink`、Windows `symlink(..., 'junction')`）；**链接创建失败时自动降级 copy**（实测 junction 可跨本地卷，故触发条件落在网络路径 / 非 NTFS 卷 / 权限不足等异常，不预设「跨卷」），并打印 ⚠️ 警告（原因 / 影响 / 修复命令），不静默；`--copy` 强制副本。幂等：已存在且指向正确 → 跳过并计入报告；指向错误或**悬空** → 重建。

⚠️ 升级跟随的诚实边界：Node 解析主模块时会对软链取 realpath，pnpm 全局安装下包路径含版本段（`.pnpm/@fxri+toolkit@x.y.z/...`），升级后旧链接可能**悬空**。因此软链并非「一定自动跟随」，而是由 `autoLink`（默认 true）在下次运行任意 `toolkit` 命令时自动**修链**；`skills status` 也会把悬空/指向错误显式报告出来。

**状态文件** `~/.agents/.toolkit-skills.json`（与上游 `.skill-lock.json` **分开命名**，避免冲突）：记录本包写入的产物、各目标模式（link/copy）、写入时间。双重用途——`status` 据此报告副本漂移并提示重跑 install；`remove` 据此**精确识别本包产物**，落实「只删本包写入，绝不碰用户自装技能」。

**配置** `skills.autoLink`（默认 `true`）：作用边界为**补链 + 修链**——仅对已存在目录补链、CI 环境跳过、失败静默降级并留一行日志；**不含**首次自动安装、**不含**自动升级（软链模式下版本同步由链接天然保证，只有 copy 副本漂移，仅提示不自动覆盖）。

**包根定位**：用 CLI 自身模块位置（`import.meta.url`）解析，不依赖 `pnpm root -g` 之类猜路径 → npm / pnpm / yarn / bun 装的都通用。

**不做项**：postinstall 自动安装（pnpm 10 拦截 + 用户已否决）、Go 二进制化（收益极低且需改造 changesets 调用链）、全局规则强制安装（与 ai-rules「AI 不得自行执行全局安装/升级」冲突，降级为检测 → 给命令 → 用户确认后执行）、项目级安装（本版只做全局）、内置 `--via` 委托上游（改由 `skills path` + 用户手工 `pnpm dlx skills add "$(toolkit skills path)" -g` 覆盖表外 agent）。

**安装/升级链路**（诚实边界，不夸大）：

| 阶段 | 命令 | 条数 |
| --- | --- | --- |
| 首次 | `pnpm add -g @fxri/toolkit && toolkit skills install` | 一行两条 |
| 升级 | `pnpm add -g @fxri/toolkit` | 一条（软链自动跟随） |
| 升级（含 copy 目标） | 上述 + `toolkit skills install` | 两条 |

首次仍需两步，不做 postinstall 的前提下无解；本方案消除的是**每次升级**的那条，即痛点所在。
