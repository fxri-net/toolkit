### 设计取舍与复核结论

- **检测入口落 cli 层而非 tasks 域**：避免 tasks 域依赖 changelog 域；避免既有「只传临时目录、`cwd` 默认仓库根」的单测受仓库自身 `.changeset/` 状态影响；与 cli 既有 `warnUntypedEntries` / `hasPendingChangeset` 同域；`validateTasks` 公有签名不变。四条理由详见批次 B。
- **保留 changelog 侧 `warnUntypedEntries`**：覆盖「跳过 `tasks check` 直接发版」的兜底；两条路径不在同一命令内触发，无重复告警。
- **`SPEC.md` 判定无触达的依据**：其「其他语言实现要点」第 7 条是语言无关的任务文件规范实现要点，枚举本就未含 conventions 载体、入口壳、文件卫生等 toolkit 专有校验项，变更集域更不属任务文件规范。
- **`docs/ai-rules.md` 不更新的依据**：本批改动全在「可变流程细节」层，薄壳只承载稳定纪律与对 fxri-* skill 的引用（`C-6` / `C-8`）；锚点按「未变更不刷新」（`C-15`）。
- **rules 有、门禁没跟上（本任务的起点与本轮最值得沉淀的结论）**：已由 `C-28` 收口——新增可检出的规则要求时须同批落地检测入口，且入口置于不可逆动作之前。
