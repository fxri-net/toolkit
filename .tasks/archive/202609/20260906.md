# 会话收尾沉淀能力升级

## 背景

作者自用工作流要求「把完整会话聊天记录按规则建档归档、以会话真实时间沉淀」，与现行 fxri-session-recap / fxri-plan-to-task / fxri-release-changelog 能力存在差距：时间口径冲突、沉淀依赖收尾时刻系统时间、切会话漏档无解、历史归档时间无法修正、已归档任务不在恢复范围、规范无承载文件、触发词需字面匹配。

## 目标

1. 完整会话的全部任务可精确建档归档，以会话真实时间沉淀（非收尾系统时间）
2. 解决切会话漏建档/漏归档痛点
3. 历史归档时间可修正（含 CLI normalize 迁移能力）
4. 恢复覆盖全部任务（含已归档），近窗精读 + 全量索引
5. 规则沉淀自动跟随四场景（任务归档/会话沉淀/会话恢复/批量修正）
6. 触发词语义化（近义即触发，不要求字面一致），不带个人口头禅进通用触发词
7. 能力终点从「归档」升级为「沉淀」：任务终结 → 归档 → 规范沉淀 → 提交/发版/推送（可选，需确认）
8. 全量文档与规则文件同步更新，工具/能力/文档三方一致

## 核心设计

### 四级时间源（贯穿所有沉淀场景）

| 级 | 时间源 | 取证 | 适用 |
| --- | --- | --- | --- |
| 0 | 任务完成当场打点 | 当场执行命令取时间 | 会话内即时归档（首选） |
| 1 | 聊天记录准确时间戳 | 用户贴日志/口述时刻 | 收尾补档有可信上下文 |
| 2 | 任务改动 git 提交时间 | `git log --format="%h %ci"` | 任务有对应提交 |
| 3 | 系统当前时间兜底 | 当场取时 + 正文标注「收尾补记」 | 前三者皆不可得 |

### 统一收尾链路（能力终点 = 沉淀）

```
任务终结 → 归档 → 规范沉淀（硬终点） → 提交/发版/推送（可选，需用户确认）
```

提交/发版/推送不强制；沉淀时机固定：归档后、任何 git 操作前，同批落盘。

### 规范沉淀两级模型（同一落点 `.tasks/conventions.md`）

- 唯一落点 conventions.md；每条规范带来源任务与日期，可审计
- 任务级：单任务归档后，AI 判断有可升格规范才追加，无则静默
- 会话级：收尾聚合全会话候选，与已有规范合并去重（跨任务重复模式在此补）
- 写前用户确认；一次性决策留任务正文不进规范

### 恢复模式三层 + 近窗边界

| 层 | 范围 | 动作 |
| --- | --- | --- |
| L0 索引 | active 全部 + archived 全部历史 | 一行一条 + 周期统计 |
| L1 工作层 | active 任务 | 全文精读 |
| L2 深度层 | 近窗 archived（月份 ≤6 或块 ≤200） | 精读近况 |
| 统计降级 | 超近窗阈值 | 只出按月/负责人统计 + 近期明细 |
| 按需 | 更早历史 | `--owner/--date` 检索；用户说「全部恢复」才全量列出 |

### 触发词语义化

- description 写行为意图画像，声明近义即触发、不要求字面一致
- 反例排除区防误触发（「开始/开工」仅在方案已确认进 plan-to-task；「收个尾」vs「总结某段代码」区分）
- 不带作者个人口头禅（如「开始」）进通用触发词
