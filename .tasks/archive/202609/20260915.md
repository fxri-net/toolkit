# CHANGELOG 分组明细剥离类型前缀

延续 20260915-CHANGELOG历史块追溯能力（见 archive/202609/20260915.md）：语义分组归类落地后，分组标题已表达类型，条目仍原样带出 `类型：` 前缀（如 `### ✨ 新增功能` 下每条都是 `- 新增：…`），属冗余。

## 背景

- 现状取证：`src/changelog/format.ts` 的 `regroupBlock` 用前缀判定槽位，但条目整行原样入桶（`bucket.push(item)`），`renderItems` 只做拼接 → 前缀被原样带出。
- 本仓库历史块（1.0.0–1.7.0 共 58 条）本就无前缀形态，剥离是回归原生风格而非背离。
- 前缀的真实职责是「归类信号」，归类完成后使命已尽，留在产物里属中间态残留。

## 实施方案

1. 抽出公共前缀匹配 `matchSlotPrefix(head, extra)`（返回 `[槽位, 前缀文本] | null`），`explicitSlot` 与新增的 `stripSlotPrefix(item, extra)` 共用，避免两处匹配逻辑漂移。
2. `regroupBlock` 入桶前剥离：`bucket.push(stripSlotPrefix(item, extra))`。
3. 同步跑一次 `changelog --history format`，把 1.9.0–1.9.3 既有块的条目前缀一并剥离，使 CHANGELOG 全文形态一致。
   ⚠️ 命令写法：`changelog` 域开了选项透传（`src/cli.ts:588` `.passThroughOptions(true)`），自有选项须置于子命令**之前**——`changelog --history format` 生效，`changelog format --history` 会被 changesets 静默忽略（输出「无 CHANGELOG 需要更新」）。仓库内 `docs/cli.md` 示例、`skills/fxri-release-changelog/SKILL.md` 可选加速节、本档原文三处旧写法一并更正。
   ⚠️ 连带发现：上一任务（archive/202609/20260915.md）「`changelog format --history` 对现行 CHANGELOG 零改动」的验证结论系该静默失效所致，不构成追溯能力已生效的证据；本次以 `changelog --history format` 实测确认能力正常。

### 边界（写死）

| 情形 | 处置 |
| --- | --- |
| `SLOT_PREFIXES` ∪ 语言自有 `group.prefixes` 命中 | 剥离 |
| `- Updated dependencies`（changesets 依赖源条目，续行承载包版本） | 不剥离（非「类型：」前缀） |
| `kept`（标题无法识别）与含正文 prose 的分组 | 整块原样，不剥离 |
| 剥离后文本为空 | 保持原样（防御） |
| 默认模式 | 只作用于 changesets 新写入块，历史块不动 |
| `--history` 模式 | 历史块一并剥离 |

### 幂等性

- 默认模式：剥离后块内已无英文源组标题 → 二次运行走 `source.length === 0` 短路原样返回。
- `--history` 模式：按当前语言 canonical 组标题反查槽位，条目已无前缀则不再变。
- 两模式均保持幂等。

# CHANGELOG 历史块追溯能力

延续 20260914-唐启云-CHANGELOG语义分组扩展（见 archive/202609/20260914.md）：上一任务确立了语义分组归类口径，但历史版本块按设计豁免（不追溯改写）。本任务把该豁免改为「默认保留、用户可主动开启追溯」，并修复镜像脚本在 Windows 检出下的换行误判。

## 背景

两件事同批处理：

1. **镜像脚本换行缺陷**：`scripts/sync-changelog-doc.mjs` 读入 `CHANGELOG.md` 后未归一换行。Windows 检出（`core.autocrlf=true`）下源文件为 CRLF，剥离首行 H1 后 `body` 以 `\r\n## x.y.z` 开头，而版本块校验正则 `/^##\s+\d+\.\d+\.\d+/` 无 `m` 标志，只匹配串首，于是必然误报「未发现「## x.y.z」版本块，镜像已中止」并以 exit 1 退出。实测：`CHANGELOG.md` 含 CRLF 为真，`docs/changelog.md` 为 LF。
2. **追溯能力缺失**：`regroupBlock` 中 `if (source.length === 0) return block.lines` 使历史版本块（不含英文源组）原样输出。上一任务用户需修正历史块时必须临时改源码自举，说明默认豁免合理、但缺少用户主动触发的正式入口。

## 实施方案

### A. 镜像脚本（`scripts/sync-changelog-doc.mjs`）

1. 读取后即 `replace(/\r\n/g, "\n")` 归一换行（与下游校验、写回产出的 LF 一致）。
2. 小幅重构：把页头拼接与校验抽成可导入的 `buildPage(text)`，主流程加 `main` 守卫（仅在直接执行时运行），便于单元测试直接调用而不落盘。

### B. 追溯能力（`--history` opt-in）

1. `src/changelog/languages/index.ts`
   - `SLOT_PREFIXES` 补全：`improved` 增 `技能：`、`skills：`；`deps` 增 `依赖：`。
   - 新增 `LEGACY_TITLE_SLOTS`：历史组标题 → 槽位（首批 `### 🐛 补丁修复` → `fixed`）。
   - 修正 `zh.replacements` 过时映射：`"### 补丁修复"` → `"### 🐛 问题修复"`（原映射指向已被更名的 `### 🐛 补丁修复`）。
2. `src/changelog/format.ts`
   - `formatChangelog` / `formatChangelogs` 增第 5 参 `history = false`。
   - `regroupBlock(block, groups, history)`：`history=false` 保持现状（历史块原样输出）；`history=true` 取消短路，块内**所有**分组参与归类——英文源组标题查 `SOURCE_GROUP_SLOTS`；历史组标题先按当前语言 `groups[].title` 反查槽位、再查 `LEGACY_TITLE_SLOTS`，命中则无前缀条目落该槽位并以当前语言 canonical 标题输出；未识别的分组原样附后（不臆造前缀）。
   - 依据「按现有组标题 + 前缀」，**不回溯 git 记录**。
3. `src/cli.ts`：`changelog` 命令增 `.option("--history", "追溯改写历史版本块")`，在 `version` 与 `format` 两个分支透传给 `formatChangelogs`。

### C. 测试

1. 新增镜像脚本回归测试：CRLF 输入正常产出 LF 页、首行非 H1 与无版本块两种失败分支。
2. `src/__tests__/changelog.test.ts` 增补：默认路径下历史块逐字不动；`--history` 下按组标题归位、带前缀条目按前缀移组、未识别分组原样保留；`--history` 二次运行零 churn；本仓库现有 `CHANGELOG.md` 在 `--history` 下零改动（自举一致性）。
