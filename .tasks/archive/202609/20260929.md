# 路径形态归一修复（Windows 8.3 短名导致归属判定失配）

## 背景与目标

推送 v1.11.2 后，GitHub Actions `windows` job 的 `pnpm verify --skip-coverage --skip-docs` 失败：`Test Files 2 failed | 33 passed (35)`、`Tests 5 failed | 486 passed (491)`，失败用例全部落在 git 路径归属判定（`git-ignore.test.ts` 4 例 + `validate-conventions.test.ts` 1 例），断言清一色 `expected { state: 'outside-repo' } to deeply equal { state: 'ignored'/'not-ignored'/'tracked' }`。本地同一命令全绿。

根因（已取证）：CI Windows runner 的 `os.tmpdir()` 返回 **8.3 短名**形态（`C:\Users\RUNNER~1\AppData\Local\Temp`，见失败日志内该串），而 `git rev-parse --show-toplevel` / `git` 侧返回的是**长名**形态（`C:\Users\runneradmin\...`）。`normalizePathForCompare` 只做分隔符 / 尾斜杠 / 大小写折叠，不做短名→长名归一，于是 `isInsideWorktree` 的前缀比对失配、把仓库内文件误判为 `outside-repo`。本地用户名 `tqy` 不产生 8.3 短名，两侧同形故全绿——这是**环境形态差异**导致的漏网，不是清单缺步骤。

非测试假阳性：生产路径 `toolkit tasks check` → `inspectLocalConfigIgnore` 同源，凡用户 Windows 机器名/用户名被 8.3 截断（或 TEMP 指向短名目录）就会**静默漏掉**「本地配置未被 gitignore 覆盖」告警，违反 C-26（降级不静默）。

目标：让路径归属判定对 Windows 8.3 短名 / 长名（及软链等路径形态差异）免疫；同批修复 `config.ts` 中同类潜在失配（本地层 `stopAtHome` 边界）。

2. `isInsideWorktree`：两侧先过 `canonicalPath` 再进 `normalizePathForCompare`，使 `os.tmpdir()` 短名与 git 返回的长名可比。

## 背景与目标

个人在团队项目里的偏好（关升级提示、个人脱敏补充规则、自定义语言表）当前只能落两层：项目 `.toolkitrc.json`（会共享给全团队）或全局 `~/.toolkitrc.json`（跨项目全局，无法按项目区分）。缺的是**项目作用域内、仅本人可见、默认不入库**的中间层。目标：新增本地配置层 `.toolkitrc.local.json`，并让它默认被 git 忽略。

## 方案设计（决策与补充建议均已确认）

1. **文件与查找**：文件名为 `.toolkitrc.local.json`，与项目配置文件**各自独立**从 `process.cwd()` 向上逐级查找最近一份。
   理由：若采用「严格同目录才生效」（dotenv / Compose 语义），monorepo 子目录只放本地配置文件时会吞掉上层团队配置；独立向上查找与现有 `loadToolkitConfig` 同构，语义一致且无此缺陷。
2. **合并粒度**：
   - 全局层 → 项目层：维持**段级整体覆盖**（现状不变，保护既有测试与文档语义）；
   - 本地层 → 合并结果：**段内字段级浅合并**（数组整体替换），即本地层只覆盖显式写出的子字段，未写的子字段保留团队值。
   理由：本地层走段级覆盖会让个人写一条 `redact` 规则就静默抹掉团队整段脱敏配置，属安全风险。
   ⚠️ **两处边界须定案**：①**段值为非对象**——本地层写 `"redact": "off"` 或 `"tasks": 123`（段级非对象）时，是整段替换（顶掉团队对象）还是告警降级？定案**按 `getConfigSection` 既有口径告警 + 整段按未写处理**（不顶掉团队对象，安全侧优先，与 `C-26` 一致）；②**合并深度严格一层**（段 → 字段）——字段值本身是对象时**整体替换**、不递归合并，`docs/config.md` 的「合并粒度对照表」须注明「仅一层浅合并，更深的嵌套对象整体替换」，避免用户以为嵌套子键也会被保留。
3. **覆盖链**：CLI `--flag` > 环境变量 > 本地配置文件（`.toolkitrc.local.json`）> 项目配置文件（`.toolkitrc.json`）> 全局配置文件（`~/.toolkitrc.json`）> 默认值。

8. **忽略行写入位置定案**：写入**团队 `.gitignore`**（`toolkit init` 幂等追加），不改向 `.git/info/exclude`——理由：`.gitignore` 让每个新人 clone 后自动被忽略、`init` 幂等可控；代价是团队可见一个 diff，可接受。`docs/config.md` 另以一句话注明「不想改团队 `.gitignore` 者可自行把该行写进 `.git/info/exclude`」（本地排除、不进版本控制，同样被 `git check-ignore` 识别）作为个人替代。
9. **`null` 语义定案**：本地层字段级浅合并**不支持「删除 / 清空团队键」**——写 `null` 与未写等价（按未写处理，团队值保留），文档须明示（与 Compose override 需 `!reset` 才能清空键的差异，属本次有意不做）；若将来确需清空能力，再以独立提案引入显式哨兵（如 `"$reset"`），不在本次范围。

- `pnpm verify`——单一步骤清单真源（`scripts/verify.mjs`：类型检查 → 冷缓存静态检查 → 单测 → 覆盖率 → 构建 → 文档站构建 → CLI 冒烟 → 任务区体检）；任一步失败即修复。
- 手工实测：三层优先级生效（本地层覆盖项目层、项目层覆盖全局层）；本地层段内字段级覆盖（未写子字段回落团队值，数组字段如 `redact` 为整段替换而非追加）；`init` 幂等三态（含「已被既有规则覆盖则跳过追加」）；`tasks check` 告警触发与不触发；`config status` 文本输出（home 折叠）与 JSON（绝对路径）双形态均与文档一致。
- 回滚：`git revert` 本提交即可（本地层为可选层，缺省行为不变）。

## 边界与注意

- 本地层是**段内字段级浅合并（数组整体替换）**，与全局层→项目层的**段级整体覆盖**语义不同，文档须分别写明，避免读者混用。
- 本地配置文件是本机个人属性，默认不入库、不随 git 分发，换机器需手动迁移。
- `tasks.dir` 可被本地层覆盖 → 同一仓库不同人任务区可能不同；属合理能力（个人本地任务区），文档须点明该语义。
- 本地配置文件沿用既有 `readConfigFile` 解析口径（BOM 剥离、顶层非对象告警、非法 JSON 降级为未配置），不引入 jsonc；文件名须带 `.json` 扩展名。
- 降级不静默：本地配置文件非法 JSON / 顶层非对象同样按既有口径告警后视为未配置。
- ⚠️ `redact` 等**数组字段**的本地层覆盖是**整段替换、非追加**：个人想「补一条」脱敏规则，实际会顶掉团队整组规则——属安全相关语义，`docs/config.md` 须单独警示，不能只写「数组整体替换」一句。
- ⚠️ 存量项目升级后不会自动获得忽略行（`GITIGNORE_SNIPPET` 只在 `init` 时写入），本地配置文件会裸露于 `git status`、仅靠 `tasks check` 软告警兜底；变更集与 `docs/config.md` 须明示「重跑 `toolkit init` 补写（幂等）」。
- ⚠️ **本地层有版本下限**：旧版本 toolkit 不识别 `.toolkitrc.local.json`、静默忽略（不报错），团队版本不一时呈「我本地生效、同事机器不生效」；变更集与 `docs/config.md` 须写明「读取该文件需 toolkit ≥ 本次版本」，避免用户误判为配置写错。
- ⚠️ `appendGitignore` 的幂等判定**必须逐行独立**（「注释 + 有序行列表」逐行 diff、只补缺失项）：现实现以 `raw.includes(".archive.lock")` 单串判定，片段插入第二行后若沿用，用户手删 `.toolkitrc.local.json` 行而保留 `.archive.lock` 时重跑 `init` 永不补写、反之缺 `.archive.lock` 时整体误报「已追加」；测试须含「手删单行后重跑只补该行」一态锁住。
- 测试注入点（home 目录 / 本地层目录）不进公共 API，核实 dist 类型产物无泄漏。
- ⚠️ 已跟踪态的本地配置文件跑完 `toolkit init` 后告警**仍不消失**（`git check-ignore` 对已跟踪文件恒返回「未忽略」），须 `git rm --cached .toolkitrc.local.json` 才清；告警文案与文档须点明该出路，避免用户反复重跑 `init` 而无效。
- ⚠️ 单文件忽略判定**不可复用 `gitIgnoredSet(cwd, rels)` 的签名**——它以 `cwd` + 相对路径表达、调用点全在 `cwd` 子树内，而本地配置文件按 A 案可能命中仓库根之上、相对路径无法表达；须在 `src/git-ignore.ts` 新增面向绝对路径的判定（`git -C <文件所在目录> check-ignore --quiet -- <绝对路径>`），不改造原函数签名去兼收绝对路径。
- 向上查找止于 home、不设仓库根边界（A 案）：项目位于非仓库父链时父目录散落的本地配置文件也会被命中（与项目层同语义，不算回退），`config status` 的绝对路径即排查入口。
- ⚠️ 非 git 仓库（未 `git init` 的项目）下「未纳入忽略」的判定**不适用**（`gitIgnoredSet` 对非仓库返回空集），故告警须先判 `git rev-parse --is-inside-work-tree`，非仓库时跳过、不发告警；`config status` 的对应列标「非 git 仓库（不适用）」，不可与「未忽略」混同（用户无从处置的告警等于噪声）。
- ⚠️ **「位于仓库工作树之外」是第四态**（A 案不设仓库根边界，本地配置文件可能命中在仓库根之上的父链散落处）：该文件本就不属本仓库跟踪范围、`.gitignore` 亦无从作用，但现判据在文件目录不属任何工作树时返回「未忽略」→ 告警**恒触发且用户无从处置**（与上一条「无从处置的告警等于噪声」同一道理）。判定须前置 `git rev-parse --show-toplevel`（以运行 `cwd` 为锚取仓库根），文件不在根之下则态为「位于仓库外（忽略判定不适用）」、**不告警**；`config status` 对应列同标。与「非 git 仓库」态的区别：本态是**有仓库但文件在仓库外**，那态是**根本无仓库**，两者均归「不适用」但文案分列。
- ⚠️ **路径归一须在 git 判定与 home 折叠间共用同一函数**：`git rev-parse --show-toplevel` 在 Windows 返回**正斜杠**路径（`C:/Users/…/repo`），而 Node `path.resolve` 给**反斜杠**、盘符大小写亦可能不同——第四态判定「文件是否在仓库根之下」若直接 `startsWith` 比较会**恒判「位于仓库外」**、该报的告警全被吞；传给 `git -C <dir> check-ignore -- <绝对路径>` 的路径同样须归一为正斜杠。定案：把「大小写不敏感 + 分隔符归一」提为**模块级共用函数**（`src/git-ignore.ts` 与 `config status` 的 home 折叠同引），`--show-toplevel` 结果与文件绝对路径**两侧都过同一函数**再比较。
- ⚠️ **忽略判定的退出码须区分「不适用」与「真实故障」**：git 对非仓库 / 仓库外 / 真实故障（git 未安装、`safe.directory` 的 dubious ownership、`-C` 路径不存在、参数错误）均返回非 0，若一律归「不适用」即**静默吞掉真实故障**（违背 `C-26`）。定案：exit 0 → 已忽略；exit 1 → 未忽略；exit 128 读 stderr 分支——匹配 `not a git repository` 归「非 git 仓库（不适用）」、匹配 `outside repository` 归「位于仓库外（不适用）」，**其余 stderr 走诊断**（`⚠️` 告警 + 呈现为「忽略判定不可用」，不冒领任何态），并计入 `config status` 的 `warnings`。
- ⚠️ **本地层段值为非对象按未写处理**：写 `"redact": "off"` / `"tasks": 123` 时**不得直接段级替换顶掉团队对象**，须按 `getConfigSection` 既有口径告警 + 整段按未写处理（安全侧优先，与 `C-26` 一致）；合并深度**严格一层**（段 → 字段），字段值为对象时整体替换、不递归。
- 本地层不支持「删除 / 清空团队键」：`null` 与未写等价（团队值保留），是本层字段级浅合并的固有边界；文档须明示，避免用户以为写 `null` 能清空团队值而实际无效果。
- `config status` 与 `tasks check` 共用同一「本地配置文件是否已被忽略」判定函数；两者措辞可不同（status 为陈述、check 为告警），但判据与态分类（未忽略 / 已跟踪 / 非 git 仓库 / 位于仓库工作树之外）必须一致，测试须覆盖四态不漂移。
- ⚠️ **自指关系**：`tasks check` 的「本地配置文件未入库」软告警受 `check.warnings` 支配，而该开关可被本地层（那个未入库的文件本身）设成 `false` → 告警被同一个文件静音、团队无从察觉。定案：**不为该告警开例外**（保持 `check.warnings` 语义一致），改由 `config status` 的对应提示承担第二条自查通道——它**不受任何配置开关影响**（除 `--format` 非法外恒输出）；`docs/config.md` / `docs/cli.md` 须写明这一自指关系与取舍。
- ⚠️ `config status --cwd` 与进程级配置缓存冲突：`loadToolkitConfig` 为单例缓存且查找起点固定 `process.cwd()`（`src/config.ts` L15-16 / L70-87），`--cwd` 指定他目录时必须走「按起点现算、不写全局缓存」的路径，否则返回陈旧结果；`--cwd` 相对路径须先 resolve 为绝对，且「止于 home」比较与文本 home 折叠须**共用同一归一函数**（大小写不敏感 + 分隔符归一），否则 Windows 盘符 / 分隔符差异使边界失效。
- ⚠️ 来源层标注须下沉到**字段粒度**：段内字段级浅合并下同段子键可来源混合（本地层只覆盖 `redact.enabled` 时 `redact.rules` 仍来自项目层），按「段 → 来源层」标注会失真，须以「叶子键 → 来源层」为模型、混合段显式标注。
- ⚠️ `config status --cwd <不存在路径>` 须报错并以非 0 退出，**不静默回落 `process.cwd()`**（回落会给出「起点正确」的错误报告，比报错更危险，与 `C-26` 降级不静默一致）。
- ⚠️ **本地配置文件的定位与忽略判定须同源**：定位走 `src/git-ignore.ts` 的 `resolveLocalConfigPath(startDir)`（内部复用 `findUpward` 且 `stopAtHome: true`），`tasks check`（起点恒为运行 `cwd`）与 `config status`（起点 `--cwd`）都从它取路径；起点不同则两者本就分列（非漂移），起点相同则路径必须完全一致。
- ⚠️ **`config status` 的自指提示项 `level` = warn 且计入 `warnings`**：该提示（「本地配置文件未纳入忽略」）除 `--format` 非法外恒输出、不受任何配置开关影响；其计数使 CI 可据 `warnings` 拦错，同时不被本地层 `check.warnings:false` 静音。
- ⚠️ **降级项的取数须结构化、不依赖 `warnedConfigFallbacks`**：`config status` 的降级项从 `readConfigFile` 产出的结构化记录取，进程级去重集仅供 CLI 打印去重，不得作为 status 的数据源（否则读不到明细、且二次读取被吞）。
- ⚠️ **`stopAtHome` 在 home 不在父链上时退化为「到盘根」**：home 边界只挡 `~/.toolkitrc.local.json` 被当本地层命中；cwd 不在 home 之下时该风险不存在，行为与不设边界等价，须可预期。
- ⚠️ **相对 `tasks.dir` 的解析基准钉死 `process.cwd()`**：`resolveTasksDir` 原样透传该值、由最终 `join` 处决定基准，易被误认为相对配置文件所在目录；`docs/config.md` / `docs/api.md` 须写明，monorepo 子目录运行尤须明确。
- 不新增 `pnpm verify` 冒烟项，沿用既有步骤。

## 设计取舍

- **C-30 / C-31 条文的互引 ID 是否注入对外分发文件**：任务档原拟「`docs/config.md` 表下引 `C-30`」「两行的当前语义列与条文须含内部互引」。经 grep 全仓库实证，`docs/` 与 `skills/` 下现存文件**零 `C-<n>` 引用**（唯一例外 `conventions-spec.md` 作为载体规范本身给出示例行）；C-26 的单一事实源 `docs/cli.md`、C-27 的来源文件 `AGENTS.md` 亦均不含 ID。`conventions-spec.md` §8「内部引用一律写 ID」的作用域限定为**载体内部互引**。故裁定：互引 ID **只写入 conventions 载体**（`index.md`「当前语义」列，属载体内部互引、合规），**不注入对外分发文件**（`docs/config.md`、`changelog-format.md` 只承载条文内容本身）——此为对任务档 L56 / L117 字面要求的**有意偏离**，理由如上，供事后追溯。
- **`新增命令` 按 patch 而非 minor（C-31 例外）**：本任务新增 `toolkit config` 命令，按 semver 惯例应为 minor；依 C-31「配套修补型」定性为 patch（补原作本应具备的配置层配套，非独立新能力），**已知与惯例相左**，对外（变更集 / CHANGELOG）只写用户可感知描述、不写判定依据。
- **本地层忽略告警的自指取舍**：`tasks check` 的「本地配置文件未入库」软告警受 `check.warnings` 支配，而该开关可被本地层（未入库的文件本身）设 `false` 静音；定案不为该告警开例外，改由不受配置开关影响的 `config status` 承担第二条自查通道。
