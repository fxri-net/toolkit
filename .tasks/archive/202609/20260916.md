# CLI 帮助呈现对齐与安全兜底

## 背景

`toolkit --help` 的 Commands 清单里 `skills` 是光杆一行，既无 `[options]` 也无 `[command]`，而同级的 `init [options]` / `tasks [options] [command]` / `changelog [options] [command...]` 都有后缀，观感对不齐。全量排查后发现 6 类同源现象，本轮修其中 4 类：

1. **P1 呈现失配（本轮修复）**：commander `subcommandTerm()` 只拼「名字 + 有非 help 选项才加的 `[options]` + 声明的位置参数」，不认真子命令、不用 `usage()`。`skills` 无自有选项、无位置参数声明，4 个子命令不被计入，父级清单只剩名字；而 `skills --help` 自身 Usage 行是 `toolkit skills [options] [command]`，同一命令两套渲染规则。
2. **P0 副作用缺陷（本轮修复）**：`changelog` 域的 `passThroughOptions(true)` 使 `changelog version --help` 的 `--help` 被当作透传操作数丢弃，命令照跑 `runChangeset(["version"])`（实测输出 changesets 的 `No unreleased changesets found` 后退出；若有待发布变更集会真升级版本号并写 CHANGELOG）；`changelog format --help` 同理会真跑 `formatChangelogs()` 改写 CHANGELOG。
3. **P2 文案不齐（本轮修复）**：全仓库无 `helpOption()` / `helpCommand()` 调用，`-h, --help  display help for command` 是 commander 英文默认值，与 `-v, --version 显示版本号` 及 `docs/cli.md` 的「显示帮助（全局或子命令）」不一致。
4. **P2 行为静默（本轮修复）**：`tasks` 的 `[command]` 是手写位置参数，`tasks bogus` 静默回落成「任务总览」，exit 0 无任何提示。
5. **P3 根描述文案（本轮不做，单独立项）**：根描述只提「任务管理 + 多语言 CHANGELOG」，未含 `init` / `skills` 两域；该句与 README、package.json、docs 站点配置等共 5 处同源，需同批改。
6. **遗留（本轮不做）**：`skills bogus` 报 commander 英文「too many arguments」、未知命令报英文「unknown command」，属 commander 默认错误通道，改动面独立。

## 实施方案

1. `src/help.ts`（新增）提供两个可测函数：
   - `setupHelp(cmd)`：递归遍历命令树，逐命令 `helpOption("-h, --help", "显示帮助")` 并 `configureHelp({ subcommandTerm })`，口径统一为「父级清单条目 ≡ 该命令自身 Usage 行」。⚠️ 必须递归——commander 每个命令各自 `createHelp()`，且 `_helpConfiguration` 只在 `.command()` 建子命令时按引用复制，命令声明完毕后再设置不会回溯。
   - `shouldPrintChangelogHelp(operands)`：判定 changelog 域是否应拦截 `--help` 打印本域帮助。
2. `src/cli.ts`：
   - changelog action 顶部按上述判定提前打印本域帮助并返回（自处理子命令 `version` / `format` 后的 `--help` 不再落入执行分支；其余子命令的 `--help` 仍透传给 changesets）；
   - 命令声明完毕后调用 `setupHelp(program)` + `program.helpCommand("help [command]", "显示帮助")`；
   - tasks action 顶部补子命令白名单（`archive` / `check` / `normalize` / `stats`），表外值报错 exit 1。
3. `src/__tests__/help.test.ts`（新增）：直接调用上述真实实现断言，不复刻其逻辑。
