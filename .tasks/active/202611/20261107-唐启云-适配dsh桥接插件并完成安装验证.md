# 适配 dsh 0.2.x 的桥接插件并完成安装验证

## 背景

官方 `@deepseek-ai/dsh-hooks-claude-code@0.0.1-rc.5` 的 peer 依赖停在 `^0.0.1-rc.5`，被 dsh `0.2.1-rc.3` 的版本校验拒绝，无法安装。社区实现 `@dsh-cc/hooks-claude-code@0.9.2` 的 peer 下限为 `>=0.2.0-rc.2`，已在 desktop profile 安装成功。适配器原先固定写官方包名，需要改为「按本机已安装的桥接包写条目」。

## 实施方案

1. `src/usage/dsh-profile.ts`：
   - `DSH_BRIDGE_PLUGIN` 默认改为 `@dsh-cc/hooks-claude-code`；新增 `DSH_BRIDGE_PLUGINS` 已知清单（官方版优先）。
   - 新增 `profileBridgePlugin()`：按清单取第一个已安装的包名；`profileHasBridgePlugin()` 改为基于它。
   - 标记块渲染与 `upsertToolkitBlock` / `writeToolkitBlock` 接受插件名参数。
2. `src/usage/adapters/dsh.ts`：安装时用已安装包名（缺省用默认 fork）写条目；提示文案说明官方版与 0.2.x 不兼容、桌面版插件页只收 bundle。
3. 文档 `docs/usage/agents.md`：安装命令改为社区版 0.9.2，补版本兼容说明与「条目按已安装包名写入」。
4. 单测：新增「已安装官方包时条目用官方包名」用例。

## 影响范围

- 代码：`src/usage/dsh-profile.ts`、`src/usage/adapters/dsh.ts`
- 测试：`src/__tests__/usage-dsh.test.ts`
- 文档触达：docs/usage/agents.md

## 验证方式

- `pnpm verify`
- 本机：`dsh plugin --profile desktop add @dsh-cc/hooks-claude-code@0.9.2` 安装成功；`hooks install --agent dsh` 后标记块 `name` 为社区包；`hooks status --agent dsh` 无插件告警
- dsh 应用内实测一次技能调用（需用户打开应用）
