# 文档可读性门禁与存量基线

> 计划位置：第 2 个（共 7 个）；前置：20261108-唐启云-文档段落可读性立规；后继：20261108-唐启云-分发清单表格化与重复段落收敛

## 背景

`C-43`（段落级可读性）只是写作判据，没有检测入口就会重演「拆分一次、过半年复发」。仓库既有同类做法是 `scripts/check-consistency.mjs`：纯 Node 脚本、只服务本仓、由 `scripts/verify.mjs` 统一挂载（门禁单源见 `C-22`），因此本条按同一形态落地。

存量有数百处超标段落，一次性清零不现实。改用棘轮策略：脚本按文件记录「允许的超标行数」基线，检查只在超出基线时失败；后续拆句批次每完成一批就把对应文件的基线调低，最后一次删除全部基线转为全量阻断。

## 实施方案

1. 新增 `scripts/check-docs-readability.mjs`：
   - **扫描面**：`README.md`、`AGENTS.md`、`SPEC.md`、`docs/**/*.md`、`skills/**/*.md`
   - **排除**：`docs/changelog.md`（`toolkit changelog doc` 生成物，`C-40` 已豁免）、fenced code block、frontmatter、标题行、表格行、HTML 注释行
   - **行预处理**：剥掉行首列表标记（`- ` / `* ` / `1. `）、引用标记（`> `）与 `⚠️`，再计长度
   - **判据**（与 `C-43` 同值）：① 单行 >120 字符；② 单行全角分号 `；` >2 个
   - **基线**：`scripts/docs-readability-baseline.json`，结构为 `{ "相对路径": 允许超标行数 }`；实测行数 ≤ 基线即通过，超出即失败并打印具体文件与行号；基线中已不存在的文件或已超额的条目提示清理
   - **输出**：违规走 stderr 并 `exit 1`；通过时 stdout 打一行统计（扫描页数 / 基线余量）
2. `scripts/verify.mjs` 增加一步「文档可读性检查」，与既有步骤同形（label + args，无新增环境依赖），插入位置在文档站构建之前。
3. 首次运行后按实测结果写基线文件，保证 `pnpm verify` 当场全绿。
4. 不新增单测：本脚本与 `scripts/check-consistency.mjs` / `check-docs-dist.mjs` 同为仓库自检脚本，同目录既无单测先例，逻辑为纯字符串判定。

## 影响范围

- 不触达文档面：新增脚本与门禁步骤，不改 `docs/**`、`skills/**`、`README.md` 内容
- 触达文件：`scripts/verify.mjs`（加一步）、新增 `scripts/check-docs-readability.mjs`、新增 `scripts/docs-readability-baseline.json`
- 四处 CI 不单独改：它们都调用 `pnpm verify`，步骤清单唯一真源即 `scripts/verify.mjs`
- 不建变更集：`scripts/` 不随包分发（`package.json` 的 `files` 白名单不含该目录），对外行为无变化

## 验证方式

1. `node scripts/check-docs-readability.mjs` 通过，stdout 输出统计
2. 人为把 `README.md` 某行临时加长到 200 字符后重跑，脚本应 `exit 1` 并指出该行；复原后通过
3. `node scripts/check-consistency.mjs` 无告警（确认未打破触达登记口径）
4. `pnpm verify` 全绿
