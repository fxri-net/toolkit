# 注释对齐校验脚本与门禁

> 计划位置：独立任务；前置：无；后继：无

## 背景

注释对齐规则已沉淀进 `fxri-writing-docs`（0.1.4），但只有文档、没有机械校验：gofmt 式的「唯一形态 + CI 校验」只做到前半，
后续任何文档改动都可能让注释列重新漂移，技能正文也如实注明了「暂无 CLI 校验」。本任务补上校验这一环。

## 实施方案

1. 新增 `scripts/check-docs-comments.mjs`（只报不改）：解析围栏代码块，按分组 / 基准 / 目标列校验，违规按 `文件:行号: 期望列 X 实际 Y` 输出，有违规退出 1。
   - 分组：连续、同缩进、同注释标记（`#` / `//`）；空行、整行注释、URL（含 `://`）、非注释行断开。
   - 基准：命令长度取注释标记前文本（去尾空白）；组内 ≤5 行取最长，≥6 行取「不超过中位数 + 10」的最长命令。
   - 目标列 = 基准 + 2；长度 > 基准的行应只留 1 个空格；长度 ≤ 基准的行应停在目标列。
2. 常数集中定义（`BASELINE_TOLERANCE = 10`、`BASE_GAP = 2`），与技能正文逐字对应，改口径只改一处。
3. 检查面与忽略项：`README.md`、`docs/**/*.md`、`skills/README.md`；排除 `docs/changelog.md`（生成物）、`docs/rules/*`（`sync:docs-rules` 生成），
   以及 `docs/cli/skill.md`（11886 / 12000 字符，归一后 12141 会击穿页面体量上限，忽略项注释写明原因）。
4. 按 C-44 配假现场用例（放 `src/__tests__/`）：合规块通过；1 列错位、超基准未留 1 空格、非基准未补到目标列各报出；
   断组四态（空行 / 整行注释 / URL / 缩进或标记切换）不误判；≤5 与 ≥6 两条基准分支各有用例。
5. 挂进 `scripts/verify.mjs` 并行检查清单（11 项 → 12 项），本地与 CI 共用同一份清单。
6. 首次跑通后撤掉技能正文「代码块内联注释对齐暂无 CLI 校验」一句，技能版本 0.1.4 → 0.1.5，同步三处技能表与 `cli-golden` 快照。

## 影响范围

- 新增 `scripts/check-docs-comments.mjs` 与对应测试；`scripts/verify.mjs` 增加一步
- 技能：`skills/fxri-writing-docs/SKILL.md`（校验方式一节 + 版本双写位）、`skills/README.md`、`docs/guide.md`、根 `README.md`、`cli-golden` 快照
- 文档触达：README.md、docs/guide.md、skills/README.md、skills/fxri-writing-docs/SKILL.md
- 无对外 CLI 行为变化；脚本属仓库自检，不发版；技能内容变更需 patch 变更集
- ⚠️ 首次接入可能暴露现存违规：先按实测清单逐条修正或列入忽略并写明原因，不允许为过门禁放宽规则

## 验证方式

- `pnpm verify` 全绿（新步骤 0 违规）；假现场用例全绿
- 手工构造一处 1 列错位，确认脚本报出并退出 1
- `toolkit task check` error 0 / warn 0

## 回滚

删除 `scripts/verify.mjs` 中的一步即回到无校验状态；脚本与用例一并 `git revert`。
