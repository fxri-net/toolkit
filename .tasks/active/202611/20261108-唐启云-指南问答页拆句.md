# 指南与问答页拆句（批次 B）

> 计划位置：第 5 个（共 7 个）；前置：20261108-唐启云-命令参考页拆句；后继：20261108-唐启云-门面与根规则拆句

## 背景

面向「先读一遍再动手」的页面密度最高：`docs/faq.md` 有 26 行 ≥150 字符（全仓单页最多，197 行 / 10,160 字符），`docs/guide.md` 21 行（244 行 / 11,697 字符，紧贴 `C-40` 的 12k 上限）。这些页的读者是第一次接触工具的人，长句的代价比参考页更高。

本批覆盖五页：

| 页面 | 超标行 | 最严重单行 |
| --- | --- | --- |
| `docs/faq.md` | 26 | L180（343）/ L172（262）/ L176（233）/ L142（256） |
| `docs/guide.md` | 21 | L174（355）/ L71（291）/ L145、L176、L178（约 230） |
| `docs/cli.md` | 3 | L56（463，升级提示收口的 6 类豁免） |
| `docs/cli/changelog.md` | 2 | L39（549，8 个分号 0 个句号） |
| `docs/getting-started.md` | 3 | L109（377，一句话复述整个 skills install 交互） |

## 实施方案

沿用批次 A 的三种手法（长括号降级、规则/例外两级、枚举改列表），另加两条本批特有处置：

1. **FAQ 一问答一段**：每个 `###` 下超过 120 字符的答句，拆为「结论一句 + 条件/例外子列表」，答案首句必须能独立读懂。
2. **`docs/cli.md` L56 与 `docs/config/update.md` 去重**：升级提示的豁免清单两页各写一份且措辞不同，本批在 `docs/cli.md` 压成「概况 + 指向 `docs/config/update.md`」，明细只在后者展开（后者已在批次 A 拆过）。

逐页要点：

- `docs/faq.md`：L142/L156/L172/L176/L180 五处为最大段落，先拆；其余按 120 字符阈值顺次清理。
- `docs/guide.md`：L174（三层目标）压缩为结论 + 指向 `docs/cli/skills.md#作用域`；L70–L71、L143–L149、L176–L178 的「项目级激活 / 项目面」重复叙述收敛。
- `docs/cli/changelog.md`：L39 的 `version` 行为按「归类信号 / 分组生成 / 清理规则 / 自检与告警」四段拆分，每段一句主干。
- `docs/getting-started.md`：L109 拆为「默认行为 / 交互两步 / 常用开关 / 另两面」四小段。

## 影响范围

- 文档触达：docs/faq.md、docs/guide.md、docs/cli.md、docs/cli/changelog.md、docs/getting-started.md
- 锚点：`docs/guide.md` 与 `docs/cli.md` 无更新锚点要求（`C-15` 只覆盖 `SPEC.md`、`templates/rules/*.md`、三个规则页）
- 基线：同步下调 `scripts/docs-readability-baseline.json` 中这五个文件的允许行数
- 不建变更集：`docs/` 不随包分发

## 验证方式

1. `node scripts/check-docs-readability.mjs` 通过，五文件超标行数较基线下降
2. `wc -m docs/guide.md` 字符数下降且仍 <12,000（`C-40` 上限）
3. `pnpm docs:build` 通过（改动涉及跨页相对链接与锚点）
4. `pnpm verify` 全绿
