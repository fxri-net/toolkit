# CLI 命令域懒加载

> 计划位置：第 4 个（共 6 个）；前置：`20261119-唐启云-本地口径跳过覆盖率`；后继：`20261119-唐启云-收敛高频命令子进程`

## 背景

CLI 实测（3 次均值）：`node dist/cli.js` 基线约 211ms，`--help` 约 460ms，即启动静态依赖约 250ms。`src/cli.ts` 顶部静态引入 init / skills / tasks / changelog / conventions / config 六个命令域模块，而这些模块又带重依赖；只求 `--help` 或单条命令时无需全部加载。

## 方案

1. `src/cli.ts` 顶部只保留 commander、help、版本提示、更新检查等轻量依赖；六个命令域的注册改为在对应命令域被解析时才动态 `import()`。
2. 命令、参数、help 文案、退出码、`FX_NO_UPDATE_CHECK` 等既有行为全部保持不变；`--help` 路径不加载任何重命令域模块。
3. 复测并记录改动前后 `--help`、`tasks check`、`skills status` 及其他单命令的耗时（各 3 次取中位数）。
4. 属对外可感知的启动性能改进，建 patch 变更集（`优化：` 条目）。

## 影响范围

- 代码：`src/cli.ts`，必要时微调 `src/commands/*.ts` 的注册函数签名（保持行为不变）。
- 变更集：`.changeset/` 新增一条 patch。

## 验证方式

- `node dist/cli.js --help`、`tasks --help`、`changelog --help` 冒烟（verify 内已覆盖三条）。
- `pnpm verify`（含全部命令单测与 CLI 用例）。
- 改动前后耗时对比表记录在完成情况中。

## 回滚

还原 `src/cli.ts`、相关命令模块注册调用与变更集文件，重新构建即可。
