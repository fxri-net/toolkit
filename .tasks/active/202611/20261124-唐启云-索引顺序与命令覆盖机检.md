# 索引顺序与命令覆盖机检

第 3 个（共 3 个）；前置：无；后继：无

## 背景

这轮改版后仍有三个静默漂移口子，全部没有机器守：

- `docs/cli.md` 的「命令总览」与 `docs/concepts.md` 的「能力全景」表是同一事实的两份手写副本；后者由 `docs-diagrams` 用例锁 `COMMAND_REGISTRY`，前者没有覆盖校验——本次改版前它就长期漏掉技能校验 / 技能版本 / 技能来源三个分页。
- `docs/cli.md` 命令总览与 `docs/config.md` 配置分页的行序按「实用性」人工维护；`docs nav check` 只校验 `site-nav.json` 结构，`check-consistency` 只校验两份文档索引的目标页集合，都不看表格行序。
- `docs/index.md` 与 `README.md` 的文档表只校验集合一致，行序与侧栏顺序是否同序无人检查。

结论：索引行序是可用性契约（按频率排序），目前只能靠人工复核。

## 实施方案

新增 `src/__tests__/docs-index-order.test.ts`，全部以 `docs/site-nav.json` 为顺序真源（表格顺序本就是侧栏的投影，不另写一份期望顺序）：

1. **命令总览覆盖 + 顺序**：解析 `docs/cli.md` 命令总览首列 `toolkit <域>`；
   - 集合断言 = `COMMAND_REGISTRY` 中 `stage: current` 的非 `help` 顶层域 + `help`；
   - 顺序断言：深度遍历侧栏「CLI 参考」的链接，按 `/cli/<域>` 映射到顶层域并保序去重（`skill-lint` / `skill-bump` / `skill-sources` 归 `skill`，`docs-theme` / `docs-check` 归 `docs`，`exit-codes` 不映射），表中域序列须与之一致；`help` 固定末行。
2. **配置分页顺序**：解析 `docs/config.md` 配置分页表的链接目标，前若干行须与侧栏「配置参考」子项链接顺序一致；表末的跨组条目（使用情况配置、文档站校验）不参与顺序断言，只校验链接可解析。
3. **两份文档索引与侧栏同序**：把 `docs/index.md` 与 `README.md` 文档表的站内链接解析为 `docs/` 下页面（README 的 `.md` 路径与末尾「完整文档站」外链须排除），
   取「同时出现在侧栏遍历序列与索引表」的子序列，断言两者顺序一致。
4. 用例内不复制侧栏顺序：顺序、映射与遍历都从 `site-nav.json` 与 `COMMAND_REGISTRY` 实时读取；表格解析只认以 `|` 开头的行并跳过表头与分隔行。

## 影响范围

- 新增：`src/__tests__/docs-index-order.test.ts`（约 120 行）。
- 不改任何文档与导航内容；后续新增命令页 / 配置页时，漏登记或行序错位会让用例失败。
- 变更集：无（只加机检，不改变对外行为）。

## 验证方式

1. `npx vitest run src/__tests__/docs-index-order.test.ts` 在当前树通过。
2. 反向验证（执行时人工做一次、不入库）：临时把命令总览两行对调、或从命令总览删掉一行，用例应分别报顺序不一致 / 覆盖缺失；验证后还原。
3. `pnpm test` 与归档后 `pnpm verify` 通过。
