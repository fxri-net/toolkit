# 首页重排

第 5 个（共 7 个）；前置：20261124-唐启云-新增适用场景页、20261124-唐启云-新增核心模型页；后继：无

## 背景

首页承载产品定位「专为多人 + AI 跨项目协作打造」，但当前首屏讲不清「这和我有什么关系」：

- frontmatter `features` 的 11 张卡片讲能力，正文「解决什么痛点」8 行表又讲一遍同一批痛点（卡片说明已是「痛点？→ 做法」句式），
  读者连读两遍同义内容，仍拿不到「我该走哪条路」的入口；
- hero 三个动作是「30 秒上手 / 完整攻略 / GitHub」，缺「先看懂 / 先对号入座」的中间站；
- 想在公司内推广的人，在首页找不到任何面向推广者的入口。

## 实施方案

1. 删除正文「## 解决什么痛点」整节（表头 + 8 行）；删除无入站锚点风险（全仓核查过）。
2. 新增正文首节「按场景进入」：四张卡片式入口（表格或 features 风格区块），每张一句现状 + 一个链接：
   - 个人 AI 重度用户 → `/scenarios#个人-ai-重度用户`
   - 团队 AI 协作开发 → `/scenarios#团队-ai-协作开发`
   - 公司 / 组织内部统一 → `/scenarios#公司--组织内部统一`
   - 我要在公司内推广 → `/adoption`
3. hero actions 调整为三个：`30 秒上手`（brand，指向快速开始）、`一张图看懂`（alt，指向 `/concepts`）、`完整攻略`（alt）；
   GitHub 已由导航栏社交图标承载，hero 不再重复放置。
4. 首页正文次序：按场景进入 → 30 秒上手 → 文档索引 → 环境要求 → 相关仓库文件 → 相关页面；`features` 卡片保持不动。
5. 根 `README.md` 在「30 秒上手」段末加一行：按场景选路径见[适用场景](./docs/scenarios.md)，整体结构见[核心模型](./docs/concepts.md)。
6. 文档索引表的重排与两个新页登记由任务 1、2、4 完成，本任务不重复调整。

## 影响范围

- 触达：docs/index.md（删节、增加场景入口、hero 动作调整）、README.md（加一行链接）。
- 不改 `features` 卡片文案、不改 tagline（tagline 是 `src/about.ts` 的 DESCRIPTION 投影，改动会触发一致性用例）。
- 变更集：patch 变更集，条目为 `- 优化：首页删除与卡片重复的痛点表，改为按场景进入并增加「一张图看懂」入口`。

## 验证方式

1. 首页构建后：hero 三个动作都可点且目标存在；正文首节为「按场景进入」，四张卡片分别落到场景页四个小节与推广页。
2. 场景页四个锚点存在（`pnpm test` 的文档一致性用例覆盖锚点校验）。
3. `node dist/cli.js docs nav check` 通过。
4. `pnpm test` 的文档一致性用例通过（两处索引目标页集合一致、README 链接有效）。
5. 归档后 `pnpm verify`。
