# 改为全局规则上报技能使用

## 背景

Hook 方案依赖各家 Agent 的配置：dsh 的桥接插件虽能加载，但 Hook 进程受运行时文件沙箱限制，写不了家目录下的统计库（诊断输出 `Access to the path ... is denied`）；Trae 还需 IDE 侧额外启用。只要上游配置或沙箱策略变化，采集就会静默失效。改为「全局规则 + 显式上报命令」为唯一主通道，不再判断 Hook 状态、不依赖任何 Agent 的私有配置。

## 方案

1. 新增 `toolkit usage record --skill <名称> [--skill <名称> ...]`（给 AI 调用的上报命令）：
   - 成功时静默（stdout 为空、退出码 0），失败也不阻断任务
   - 是否统计、统计哪些来源 / 技能，全部复用 `usage` 配置（`enabled`、`agents`、`sources`、`skills.mode`），规则里不写死技能范围
   - 字段采集按 `capture.*` 配置；规则只传技能名，触发词 / 参数不由规则转述（避免命令行泄露与模型转述失真）
   - 会话标识优先 `--session`，其次已知环境变量，最后按日期兜底；Agent 无法识别时记 `manual`
   - 支持一次上报多个技能（每批工具调用后合并一次），每条事件独立 eventId；同批同一技能只记一条
2. 对外呈现为**二选一**：规则自报（推荐，跨 Agent）或 Hook 自动（按 Agent，存在配置与沙箱限制）；两者不做仲裁，文档明确二选一，启用一种时移除另一种
3. 重写 `toolkit usage rule` 输出：规则只要求「每批工具调用结束后，若本批用到技能则合并执行一次 record」，不枚举技能、不写死字段；关闭方式是删规则段或 `usage disable`
4. `usage init` 增加接入方式选项：`--channel rule|hook`（交互向导同样询问，默认 rule）；选 rule 时只写采集配置、不安装任何 Agent 的 Hook，并输出 `usage rule` 提示；该路径不依赖本机是否检测到 Agent
5. `usage info` 展示当前接入方式（规则 / Hook）与规则文案入口，便于自查
6. 文档改为主次结构：`docs/usage/agents.md` 以「二选一」组织（规则 / Hook 各自启用、关闭、卸载与限制）；dsh 标注沙箱限制、用规则自报；`docs/cli/usage.md` 补 `record`、`init --channel`、`info` 展示；`docs/rules/usage.md` 同步并更新锚点
7. 本机：卸载 dsh 的桥接插件与 Hook 配置（已完成）；Trae / Copilot 的 Hook 用户已关闭，规则段由用户复制到全局规则

## 影响范围

- 代码：`src/usage/`（record 实现）、`src/usage/rule.ts`、`src/usage/commands.ts`、`src/usage/wizard.ts`（init 的 channel 选项与 info 展示）
- 测试：新增 record 单测（多技能批量、静默、配置过滤、disabled 零写入、入参校验）；init `--channel` 分支用例
- 文档触达：docs/usage/agents.md、docs/cli/usage.md、docs/rules/usage.md

## 验证方式

- `pnpm verify`
- 本机：执行 `usage record --skill a --skill b` 写入两条；关闭开关后执行无记录；stdout 为空
- 规则侧：在 Trae / dsh 各发一次带技能调用的消息，由模型按规则执行 record（需用户配合触发）

## 决策与开放点

- 已定：统计范围、来源与字段一律跟 `usage` 配置走，规则里不写死技能名单与字段
- 已定：规则只传技能名，触发词 / 参数不由规则转述；规则路径不产生这两类字段
- 已定：每批工具调用后合并上报一次；同一技能同批只记一条；不做 `--count`、不做 `--key`
- 已定：Agent 识别不到时记 `manual` 兜底，规则保持通用
- 已定：不做 Hook 状态仲裁、不做会话文件导入，保持与 Agent 无关
- 已定：规则与 Hook 对外二选一；`usage init` 提供 `--channel` 选择，选规则时不装 Hook 但仍写采集配置
- 已定：本机卸载 dsh 的桥接插件与 Hook 配置（已完成）；Trae / Copilot 的 Hook 由用户关闭
- 已定：T3「适配 dsh 桥接插件」归档为已放弃（运行时沙箱限制），插入形式的修复保留在代码中
