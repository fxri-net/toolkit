# 统一交互层与全量接线

> 计划位置：第 2 个（共 2 个）；前置：20261121-唐启云-修复交互取消卡死与取消退出码口径；后继：无

## 背景

上一任务只修 `toolkit scope` 的取消卡死并把取消统一到 130，交互能力仍散在四处：`src/prompts.ts`（加载与取消判定）、`src/skills/prompt.ts`（技能多选与确认）、`src/scope/wizard.ts` 与 `src/usage/*`（各自直接调 inquirer）。结果是同一种交互在不同命令里表现不一致——某个功能支持的按键 / 退出码 / 文案，另一个功能没有。本任务把交互能力收敛成一个可复用层，并全量接线。

## 实施方案

### 阶段 A：统一层与全量接线（先完成、可独立验收）

1. 交互层收敛：把 `src/prompts.ts` 升级为唯一交互入口，导出 `INTERACTIVE_EXIT = 2`、`CANCEL_EXIT_CODE = 130` 等常量，以及 `isInteractive()`（唯一 TTY 判定）。
2. 非 TTY 统一策略：新增 `requireInteractive({ action, hint, fallback })`——有非交互等价路径时走 `fallback`（不报错），没有则 stderr 输出 `⚠️ 当前环境不支持交互（action）：hint` 并以退出码 2 结束；`scope` 无参非 TTY 由「打印帮助 + 0」改为该口径。
3. 提示封装：新增 `ask.select / ask.checkbox / ask.confirm / ask.input`，统一分页（默认 15，可显式覆盖）、`checkbox` 的 `required: false`、`askWithBack` 的 ESC 返回、取消抛统一异常；命令层用 `runInteractive(action, fn)` 收口——取消 130、其它错误 `⚠️` + 1。
4. 选项词汇收敛：`choices.withBack()` / `choices.withExit()` 统一生成「← 返回」「退出」（末位），`keep` 类选项统一为「保持现状」；空结果页统一为「返回 / 退出」两种出路。
5. 诊断统一走 stderr：取消与提示文案统一为「已取消，未修改任何文件」（数量类补一句），全部 `console.error`。
6. 全量接线：`scope`（wizard / add / remove / mount / gate）、`usage`（menu / uninstall / upload setup）、`skills`（install / uninstall / bump 确认）、`rules compose` 全部改走统一层；`skills install` 在「技能选择 → 目标选择 → 确认」之间支持 ESC 回退；`scope mount` / 内容闸门不新增参数化入口，非 TTY 统一由 `requireInteractive` 报 2。
7. 文档：`docs/cli.md`（非 TTY 与退出码 2）、`docs/cli/scope.md`（非 TTY 口径变更）、`docs/cli/skills.md`、`docs/cli/rules.md`、`docs/cli/usage.md`、`docs/cli/exit-codes.md`（2 与 130 并列）。
8. 变更集：`.changeset/unified-interaction.md`（patch，`scope` 非 TTY 退出码与部分交互文案变更，按统一口径记为修复）。
9. 测试：交互层单测（TTY 判定、非 TTY 走 2、取消 130、ESC 返回、返回项末位、分页默认）；各域交互用例迁移到统一 mock。

### 阶段 B：usage init 步骤机（依赖阶段 A）

10. `src/usage/wizard.ts` 的十余步直线 `await` 改为步骤索引 + 每步取值缓存，ESC 回到上一步，默认值与文案保持不变，末步预览与确认逻辑不动。
11. 补步骤机测试：前进 / 返回上一步 / 中途 Ctrl+C 以 130 收口，三条路径各自覆盖。
12. 文档：`docs/cli/usage.md` 补充 `init` 支持 ESC 回上一步。

两阶段同属本任务：阶段 A 完成后即可独立验收与提交，阶段 B 在 A 之上追加；变更集随阶段 A 建立，阶段 B 复用同一变更集描述。
