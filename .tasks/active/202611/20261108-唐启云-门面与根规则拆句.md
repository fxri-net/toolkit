# 门面与根规则拆句（批次 C）

> 计划位置：第 6 个（共 7 个）；前置：20261108-唐启云-指南问答页拆句；后继：20261108-唐启云-技能文档拆句与门禁收紧

## 背景

门面文件的长段落伤害最大：`README.md` L76 单段 917 字符，把安装形态、tier 分层、两步交互、6 个跳过交互参数、外部来源、作用域、`prepare` 钩子塞进一句话，是本次投诉的起点；读者在 GitHub 首屏看到的就是它。

根规则两份同样是长句密集区：

| 文件 | 超标行 | 最严重位置 |
| --- | --- | --- |
| `README.md` | 4 | L76（917）/ L13（217）/ L35（204） |
| `AGENTS.md` | 13 | L15（484）/ L51（472）/ L25（431）/ L12–L14（311–321） |
| `SPEC.md` | 12 | L15（615）/ L40（493）/ L17（396）/ L20（363） |

`AGENTS.md` 与 `SPEC.md` 是给 AI 读的规则，同样需要短句：一条规则一个子项，比一句话串五个条件更少歧义。

## 实施方案

1. **`README.md` L76**：拆为「分发形态 / 安装交互两步 / 跳过交互的参数 / 外部来源 / 作用域」五个子项；L13 的镜像说明、L35 的「之后」流程同样拆句。
2. **`AGENTS.md`**：质量门第 1–6 条各自拆为「要求 + 反例/配套」两段；「协作流程约束」里的长条（L40–L52）按主语拆子项。语义逐字保留，不做条文增删——本仓 `AGENTS.md` 是规则层，任何语义变化都不属本任务范围。
3. **`SPEC.md`**：同法拆分，并**更新首行更新锚点** `> 规范更新时间 YYYY-MM-DD HH:mm` 为本批次变更时刻（`C-15` / 质量门第 6 条：内容变更即抬锚点，同批改动用同一时间，不带秒）。
4. **变更集**：`README.md` 与 `SPEC.md` 随包分发，建一条 patch 变更集，条目写 `- 文档：…`。

## 影响范围

- 文档触达：README.md、AGENTS.md、SPEC.md
- 锚点：`SPEC.md` 首行更新锚点必须随内容变更刷新；`templates/rules/*.md` 与三个规则页不触达，锚点不动
- 变更集：`.changeset/` 新增 patch 条目
- 不触达 `docs/**`、`skills/**`、代码：语义与命令契约零变化，只改句子结构与段落切分

## 验证方式

1. `node scripts/check-docs-readability.mjs` 通过，三文件超标行数下降
2. `node scripts/check-consistency.mjs` 无 error / warn（`README.md` 属触达面，核对已登记）
3. `git diff -U0 README.md AGENTS.md SPEC.md` 人工复核：确认只删标点与断句、未删任何能力描述
4. `pnpm verify` 全绿
