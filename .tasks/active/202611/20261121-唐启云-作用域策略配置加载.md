# 作用域策略配置加载

> 计划位置：第 2 个（共 5 个）；前置：20261121-唐启云-作用域策略判定内核；后继：20261121-唐启云-作用域策略命令面

## 背景

判定内核只接受内存中的策略列表。现有 `scope/load.ts` 采用「最近一份 activation 整段覆盖」，无法表达「全局策略 + 项目追加 / 覆盖」；
本任务把各层策略、档案与旧字段编译结果合并后交给内核，并保持「离项目越近优先级越高」的既有直觉。

## 实施方案

1. 按全局 → 项目 → 本地逐层读取 `activation`，每层产出带层标记的策略；最近一份旧 `activation` 目录字段编译为同层基线策略，避免改变现有整段覆盖语义。
2. 解析新字段 `policies`：逐条校验 `id`、`name`、`when`、`skills`、`effect`，非法项告警剔除；`id` 跨层唯一，重复时保留高层并告警；
   手写规则缺 `id` 时按层 + 内容哈希派生稳定 id，内容一改 id 即变，加载时告警提示显式写 `id`；`name` 只作可读标签，允许重复；无条件（`when` 为空或全空数组）的规则属兜底规则，
   除旧字段编译产物外一律告警；规则按全局 → 项目 → 本地拼接，层与声明顺序随规则保留。
3. 解析 `skillProfiles`：档案名 + `allow` / `deny`，键与模式沿用 `compilePattern` 校验；同名档案按最近层整份覆盖。
4. 旧 `skills` 规则只取最近一份 activation，编译为同层技能策略；技能名是否存在交给命令层按包内清单校验。
5. `ScopeReport` 增加 `profiles` 与 `policies` 来源字段，供 `scope status --skills` 与 JSON 输出使用；未知档案、非法模式等结构性问题进入现有 warnings。
6. 加载期一次编译：模式预编译、具体度预计算、规则按优先级排序一次，进程内缓存；只有存在 `gitRemotes` / `markers` 规则时才读 git 远端或查标记；
   `scope guard` 快速路径不得引入技能包、命令注册表等重模块。
7. 补多层合并、档案覆盖、旧字段编译、非法项与 id 重名剔除单测；增加「父目录 glob + 两个兄弟项目（含新建目录）」用例，锁住新增项目自动继承；
   加性能用例：200 条规则加载 + 判定在宽松预算内，guard 快速路径保持轻量。
