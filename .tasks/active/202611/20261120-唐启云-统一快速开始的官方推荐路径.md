# 统一快速开始的官方推荐路径

> 计划位置：第 2 个（共 2 个）；前置：20261120-唐启云-运行时兼容-Node-18；后继：无

## 背景

官方推荐的使用方式是三步：**全局安装 CLI → `toolkit skills install` → 组合并配置自己需要的全局规则**；
团队项目再走 devDependency + `--scope project` 的版本锁定分支。

现状与这条路径相反：README 与文档站首页的「30 秒上手」都用 `pnpm add -D` + `pnpm exec toolkit`，安装节把 devDependency 标为推荐、
全局排第二；规则组合只出现在能力矩阵与文档深处，快速开始里完全没有这一步。实测在空目录执行 `pnpm exec toolkit`
报 `ERR_PNPM_RECURSIVE_EXEC_NO_PACKAGE`——按现有「30 秒上手」操作的全局安装用户会直接失败。

目标：让「30 秒上手」与全部入口页呈现同一条官方路径，devDependency 降为团队备选，并补上「规则组合完粘到哪里」的落地指引。

## 方案

### 1. 口径基线（全仓唯一默认路径）

```bash
pnpm add -g @fxri/toolkit     # 1. 全局装 CLI（npm 用户 npm i -g）
toolkit skills install        # 2. 装技能
toolkit rules compose         # 3. 组合并复制全局规则
```

进入具体项目后再 `toolkit init` 建任务区；团队项目改用 devDependency + `toolkit skills install --scope project`，版本随仓库锁定。

### 2. README.md

- 「30 秒上手」改为上述三步（每步一行注释）：`pnpm add -g @fxri/toolkit` → `toolkit skills install` →
  `toolkit rules compose --preset recommended --copy`；第三步下一行说明「把剪贴板内容粘贴到所用 agent 的全局规则」，
  并给回落写法「剪贴板不可用时去掉 `--copy` 手动复制」（`--copy` 失败会以非 0 退出）
- 补一行团队分支：`pnpm add -D @fxri/toolkit` + `toolkit skills install --scope project`，版本随仓库锁定
- 删除现有的 devDep 安装 + `pnpm exec toolkit init/tasks` 组合，后续任务闭环说明保留
- 「安装」节顺序改为：全局（默认）→ devDependency（团队）→ 临时执行
- 「AI 技能包」节首行加一句「安装步骤见上文 30 秒上手」
- 四种包管理器的全局命令用一行注释指向快速开始，不在 README 内展开四份代码块

## 验证方式

- `pnpm verify`：含文档站构建死链、`docs-consistency` 相对链接与锚点、可读性（单行 120 字符 / 正文 150 行 / 12k 字符）、skills 一致性、`tasks check`
- `node dist/cli.js docs nav check`：确认导航结构未被改动破坏
- 空目录验证：`toolkit --version` 走全局路径可用，`pnpm exec toolkit` 仅出现在「项目内安装」语境
- grep 确认「30 秒上手」相关代码块中不再出现 `pnpm exec toolkit`（项目内说明行除外）
- 比对 README 与 `docs/index.md` 的三步命令逐字一致（两处均为 `skills install` +
  `rules compose --preset recommended --copy`，防止一处改动后漂移）
- 人工通读快速开始：三步命令可复制即执行，规则落点表说明「以官方文档为准」

## 取舍与风险

- 全局优先会让团队出现版本漂移，因此团队分支（devDependency + `--scope project`）必须保留并写清适用场景，不能只留一条路
- 规则落点表会随 agent 工具版本变化，只写入口名称与检索方式，不写死绝对路径
- 快速开始压缩后只链接 guide 既有章节，不迁移内容（guide 已无字符余量，新增即触发 C-40 硬校验失败）
- 现有 FAQ / handbook 已部分正确，改动以「收敛到真源 + 去重」为主，不做整篇重写
