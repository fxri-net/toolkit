# 交互同类面收敛

> 计划位置：第 2 个（共 2 个）；前置：20261123-唐启云-交互列表简介单行；后继：无

## 背景

第 1 个任务统一了技能安装 / 卸载的选项排版。仓库内还有同类交互面存在长文案换行、主次不分：
目标多选（label + disabled 原因）、作用域向导的技能 / 项目多选、`upgrade` 迁移项（`id｜action` 整句）。
按「展示基建收敛单模块」的既有约定，统一复用 `prompt-line.ts`，不各写截断；
设计边界按 playbook 的「编码核心规范」（`fxri-code-profile-core`）「架构统一与表达从权」执行。

## 实施方案

1. **目标多选**（`src/skills/prompt.ts` 的 `buildGlobalTargetChoices` / `buildProjectTargetChoices` / `promptTargetSelection`）：
   label 超宽按 `truncateMiddle` 中段省略（末段可辨）；预算扣 `3`（前缀）+ disabled 原因显示宽；原因继续由 inquirer 以 disabled 文本渲染（整行暗色，组件约束）。
2. **作用域向导 · 技能多选**（`src/scope/wizard.ts`）：`[技能] 名称` 后跟暗色单行简介（取 `listPackageSkills()` 的 `description`），`short` 只放名称。
3. **作用域向导 · 项目多选**：`名称 · 相对路径 · 非 git` 单行截断，路径走中段省略，非 git 标记保留在尾部。
4. **升级迁移项**（`src/commands/upgrade.ts`）：改走 `cli-ui` 的 `askCheckbox`（补齐 ESC 逐级返回与统一取消语义）；
   候选行 `id｜action` 单行截断（action 保留前段），`short` 用完整 `id` 保证答案行信息不丢失。
5. 答案行折叠复用任务 1 的基座行为（超过 6 项折叠），各面不再自写。
6. 文档：`docs/cli/skill.md`（目标选择）、`docs/cli/scope.md`（向导列表）、`docs/cli/upgrade.md`（迁移项）逐篇核对并同步。
7. 测试：目标 / 向导 / 升级各自补「80 列单行、超宽省略、中段省略、答案行仅名称 / 完整 id」用例；`pnpm verify`。
8. 变更集 patch：`优化：交互列表同类面单行收口`。

## 已确认取舍

- 目标多选、作用域向导技能 / 项目多选、`upgrade` 迁移项一并做单行收敛
- 各面提交后的答案行同样不夹带简介；`upgrade` 属细节从权，答案保留完整 `id`
- 路径类（目标目录、项目相对路径）统一中段省略，保留末段辨识度
- 答案行超 6 项折叠复用交互基座，各面不重复实现
