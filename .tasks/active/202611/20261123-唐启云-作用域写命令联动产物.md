# 作用域写命令联动产物

> 计划位置：第 3 个（共 4 个）；前置：20261123-唐启云-产物与guard按目录矩阵；后继：20261123-唐启云-矩阵视图与旧配置迁移

## 背景

现在 `scope list add/exclude/remove/default/reset`、`scope policy *`、`scope skills *` 只写配置，技能产物不会跟着变；用户必须再手动跑 `toolkit skill install`，且过程中看不到「哪些技能会从全文变入口壳 / 从入口壳变全文 / 变不安装」。这是声明式配置与产物之间的断层，成熟工具（Terraform plan/apply、pnpm add 自动装包、Homebrew 自动 link、direnv 自动应用）都要求「预览 → 应用 → 报告」闭环。

## 实施方案

1. 抽出「产物收敛计划」服务：基于矩阵解析结果与当前产物，逐技能算出目标形态（full / gated / off）与动作（写全文、写入口壳、`--prune` 清理），只列**有差异**的技能。
2. 所有改变（技能, 目录）结论的写入口接入，逐个点名避免漏面：
   - `scope wizard`（含 `scope mount` 写入的作用域）、`scope list add/exclude/remove/default/reset`、`scope policy add/remove/reset`（含 `--delivery`）、`scope skills allow/deny/profile/reset`；
     `scope skills profile` 改名 / 删除档案时按引用该档案的策略重算形态，不只处理名单类命令。
   - 写前预览同时展示「配置变更」与「技能形态变更」（如 `fxri-plan-task：全文 → 入口壳`），并给出受影响技能数；
     规则带目录条件时标明生效目录（避免被读成全局生效）；某个安装面没有产物时显式打印「项目面：未安装，无动作」，不省略该行；
   - 确认后先写配置、再应用产物动作；`--dry-run` 只预览；`--yes` 跳过确认；
     非 TTY 下：带显式参数的写命令按现有口径直接执行（不阻塞脚本与 CI），裸命令缺参数则报错退出、不写配置——沿用各命令现有交互判据，联动不额外加确认；
   - 默认自动联动，提供 `--no-link` 仅供高级用户关闭；各写命令 help 静态写明「写入后自动收敛技能产物，`--no-link` 关闭」，使预告不只存在于运行时；
     使用 `--no-link` 时向 stderr 补一行「已只写配置，产物未联动，可重跑 `toolkit skill reconcile`」，不静默跳过。
3. 顺序与失败语义（参照声明式工具的收敛模型）：配置原子落盘在前、产物收敛在后；收敛失败时产物状态只会比配置**更宽**（全文残留），
   技能仍可用，属安全降级——因此不退配置、不伪造成功，退出码非 0 并提示「配置已写入，产物未完全收敛，可重跑 `toolkit skill reconcile`」；
   反向顺序（先产物后配置）失败会留下「配置允许、产物是入口壳」的不可用态，明确不采用。
4. 过程与结果报告：逐技能输出成功 / 失败 / 跳过；无差异时只报「产物已一致」；收敛内部调用安装核心时不再写作用域配置、不重复触发联动，防递归。
   项目面归属账（`.toolkit/state.json`）只在产物写入成功后同步形态字段，失败不记账，避免账实不符、下次体检凭空报差异。
5. 幂等：无差异时不写产物、只提示「产物已一致」；重复执行不重复生成。
6. 手工改配置与低层写入口：`config set skillDelivery.*` / `config set activation.*` 不自动联动，但打印漂移提示；新增 `toolkit skill reconcile`（或 `skill install --reconcile`，支持 `--scope project`）供手工改配置、队友 pull 项目层配置后一键收敛；`toolkit status` 继续给漂移提示。
   `reconcile` 只对齐已装产物的形态与归属，不改选择集、不新增未选技能——要加装技能仍走 `skill install`，避免「顺手装一堆」的意外。
7. 两类「移除」的区别写进文档，不改现有安全边界：作用域白名单移除技能 → 声明式产物自动收敛为入口壳 / 不安装；
   取消安装选择或目标 → 已装产物默认保留（`status` 标「未选择但已安装」，`--prune` 才清理）。`skill uninstall` 与 `skill remove` 已同步选择集（`src/skills/install/global.ts` L450 / L460），本次不重复改造，仅回归验证。
8. 安装面映射：`--layer global` 只收敛全局面，`--layer project` 只收敛项目面（产物随 git 分发，写全局层去动项目面会造成意外 diff）；
   `--layer local` 同时影响两面（项目面也读本地层），默认收敛两面——本机偏好写后应当立即在本机生效，
   但在 `CI` 或非 TTY 下项目面只报告不写盘（与 `prepare` 同一安全口径，避免流水线产物与仓库不一致）。
   仓库里没有项目面产物（没跑过 `--scope project`）时该面零动作，因此只有已装过项目面技能的仓库才可能多出 `git status` 改动。
9. 并发：产物收敛复用现有技能操作锁（全局面 `skillsLockFile`、项目面 `projectSkillsLockFile`），锁被占用时不等待、不静默——按失败路径报「配置已写入，产物未收敛」并非 0。
10. 测试：白名单加入/移除触发 full↔gated、`off` 触发清理；`profile` 改名后形态重算；向导结束即收敛；`--dry-run` 不写盘；失败路径与「配置已写入」提示、失败不更新归属账；`--no-link` 提示；非 TTY 带参直接执行 / 缺参报错；层映射只动对应安装面；CI 下项目面只报告；锁占用；幂等；报告内容；递归不触发二次收敛。

## 验证方式

- 单测 + 临时 home 集成：加入白名单后自动把受影响技能转入口壳；移除后按矩阵转回全文或清理；失败路径退出非 0
- 手工：分别写 `--layer global` 与 `--layer project`，核对只有对应安装面产物变化；占用锁后重跑核对提示与退出码
- `pnpm verify` 全绿；`node dist/cli.js task check` error 0 / warn 0

## 回滚

移除自动联动调用与报告、恢复只写配置行为即可；`--no-link` 保留为兼容开关。
