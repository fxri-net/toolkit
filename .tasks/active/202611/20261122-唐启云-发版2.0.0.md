# 发版2.0.0

> 计划位置：已移出当前计划（用户后续独立安排）；前置：无；后继：无

## 搁置

- 搁置原因：用户要求把发版从当前计划剔除，后续独立安排
- 重启条件：用户明确发起 2.0.0 发版并给出 publish 授权
- 进度锚点：版本消费已撤回（`package.json` 1.17.8、22 份变更集在位），折叠清单与远端 CI 核对结论见本档「实施记录」
- 搁置日期：2026-11-22

## 背景

本轮修复与退出码单一真源落地后，与既有 3 个 major 变更集一起发版；发版的 publish 与推送不可逆，须逐次授权。

## 实施方案

0. 前置门：开发任务全部归档；代码推送到 gitee / github / origin，确认远端 CI 全绿。
1. 本任务先归档并提交——归档是消费变更集的前置条件，任务档不悬挂到发版之后。
2. `release audit` 列净变更候选并人工合并，然后 `release bump` 生成 2.0.0 CHANGELOG。
3. 人工润色后 `release changelog --history`、`pnpm sync:changelog-doc`。
4. `pnpm verify` 全绿后单独提交版本与 CHANGELOG，再打 `v2.0.0` 轻量标签并核对。
5. `pnpm publish`（需授权）；推送按授权另执行。

## 影响范围

- `package.json`、`CHANGELOG.md`、`docs/changelog.md` 与归档页、`.changeset/`（消费）
- 不改代码与技能内容

## 验证方式

- `release audit` 无遗漏候选；`pnpm verify` 全绿；`release mirror --check` 通过
- 标签存在且指向发版提交

## 回滚

发版前可由 `release bump` 的产物单提交回退；已 publish 不可回滚，只能发补丁版本。
