# 收敛高频命令子进程

> 计划位置：第 5 个（共 6 个）；前置：`20261119-唐启云-CLI命令域懒加载`；后继：`20261119-唐启云-文档构建前移实测`

## 背景

CLI 实测（3 次均值）：`skills status` 约 1214ms、`tasks check` 约 879ms，明显高于其余命令（570–760ms）。两者都涉及 git 判定与文件遍历；`conventions status` 已在入口壳处做过一次批量 gitignore 判定，其余路径可能仍逐文件起子进程，或在本可短路处仍做全量扫描。

## 方案

1. 先用临时探测（不改仓库、不入库）定位子进程热点：统计各命令执行期间的 `git` 子进程次数与耗时占比，锁定造成秒级开销的具体调用点。
2. 按实测结果收敛：可短路处先读状态文件/存在性再决定是否深入；git 判定改为一次批量调用或进程内缓存，避免按文件重复起进程。
3. 输出格式、告警文案、退出码、`--format` 等对外行为保持不变。
4. 属对外可感知的性能改进，建 patch 变更集（`优化：` 条目）。

## 影响范围

- 代码：`src/skills/`、`src/tasks/`（按实测热点确定具体文件），可能涉及共用 git 工具函数。
- 变更集：`.changeset/` 新增一条 patch。

## 验证方式

- 改动前后对同一仓库现场执行 `toolkit skills status`、`toolkit tasks check`，输出逐字一致（diff 为空）。
- `pnpm verify`（含 conventions / tasks / skills 既有单测）。
- 耗时复测 3 次取中位数并记录。

## 回滚

还原被改动的 `src/` 文件与变更集，重新构建即可。
