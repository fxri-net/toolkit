# 隐私扫描与门禁接入

> 计划位置：第 2 个（共 4 个）；前置：20261123-唐启云-隐私路径归一与写盘联动；后继：无

## 背景

上一档解决了「写盘时归一」，但历史存量、手工改文件、AI 直接编辑仍会漏；只有把扫描挂进 `pnpm verify` 才是不可绕过的门禁。
同一套扫描要能服务两类仓库：开源仓库要求 error，业务仓库默认 off 时不产生任何噪音。

## 实施方案

1. 新增 `toolkit privacy scan [--fix] [--format json]`：扫描 `.tasks/`（含 `archive/` 与 `conventions/`）、`.changeset/`、`docs/`、`skills/`、`templates/rules/`、`README.md`、`SPEC.md`、`AGENTS.md`；
   排除 `node_modules` / `dist` / `.git`；输出 `文件:行:类型`；`--fix` 只自动归一任务档与规范载体，`docs/` 与 `skills/` 只报告（不擅自改文档语义）。
   `--fix` 作用于归档块时**只做路径归一**（属事实更正类最小改写），不改其他内容。
2. 严重级按范围分级：`.tasks/`（`archive/` 与 `conventions/`）与 `.changeset/` 为 `error`（变更集内容会进 CHANGELOG 并随包分发）；
   `docs/`、`skills/`、`templates/rules/`、`README.md`、`SPEC.md`、`AGENTS.md` 为 `warn`——
   文档命令示例天然含路径写法，一律阻断会把合法示例误判。总档位 `off` 时整次扫描不执行。
3. `task check` 复用同一扫描：`archive/` 与 `conventions/` 的违规按档位报 error / warn，`active/` 只提示（符合 C-14 两阶段）。
4. `scripts/verify.mjs` 增加该步骤，本地与四处 CI 共用同一清单；`toolkit status` 的体检区块接入，`off` 时整节省略。
5. 文档：新建 `docs/cli/privacy.md`（命令、档位、扫描范围、`--fix` 边界），同步 `docs/cli/task.md` 与 `docs/config.md`。

## 影响范围

- 代码：`src/commands/privacy.ts`（新）、`src/privacy/scan.ts`（新）、`src/commands/task.ts`、`src/tasks/validate.ts`、`src/status.ts`、`scripts/verify.mjs`、`src/command-registry.ts`
- 测试：`src/__tests__/privacy-scan.test.ts`（新）、`src/__tests__/status.test.ts`、`cli-golden` 快照
- 文档触达：docs/cli/task.md、docs/config.md
  - 两篇均已同步（命令入口、档位语义、扫描范围与 `--fix` 边界）；另新建 `docs/cli/privacy.md`（新页不在既有触达面内）
- skills 触达：无（技能未描述扫描细节，只经 `pnpm verify` 薄引用）
- 变更集：patch

## 验证方式

- 假现场：合规通过 / 违规报出 / `off` 无输出 / `warn` 退出 0 / `error` 非 0 / `--fix` 幂等
- 本仓 `node dist/cli.js privacy scan` 归零；`pnpm verify` 含新步骤且全绿
- 命令注册表与 golden 快照同步

## 回滚

从 `scripts/verify.mjs` 撤掉该步骤并删除命令注册即可；扫描实现可保留。
