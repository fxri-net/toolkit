# 文档站页面收尾一致性

第 7 个（共 7 个）；前置：无；后继：无

## 背景

全站自建页面统一以「## 相关页面」收尾（单行 `- 参考：[…](./x) · …`），供读者在页尾横向跳转。
核查发现两类体例偏离：

- 5 个页面缺该节：`docs/cli/privacy.md` 与 `docs/usage/` 的 index / privacy / schema / agents。
- `docs/cli/skill.md` 的「目标选择」「外部来源」「作用域」三节各只有 2 行，都写「一句事实 + 一个跳转」，把同一主题拆成三个碎节，
  读者要在三处之间来回；三节都含独有事实（目标优先级、`--source` 行为、`--scope` 缺省判定），合并时须原样保留。

逐节核查后判定不改的两处：`docs/handbook.md`「八、隐私与安全」与 `docs/cli/rule.md`「用途与场景」虽短，但承载的是
脱敏默认行为与预设 / 缓存口径等成句事实，属正常小节而非空壳，保持原样。

## 实施方案

1. `docs/cli/privacy.md`：补「## 相关页面」，指向 配置参考 · 隐私脱敏、任务区、退出码。
2. `docs/usage/index.md`：补「## 相关页面」，指向 使用情况配置、Agent 接入、隐私与数据边界、事件 Schema、CLI 参考 · 技能使用情况。
3. `docs/usage/privacy.md`：补「## 相关页面」，指向 技能使用情况概览、使用情况配置、事件 Schema、CLI 参考 · 技能使用情况。
4. `docs/usage/schema.md`：补「## 相关页面」，指向 技能使用情况概览、使用情况配置、隐私与数据边界。
5. `docs/usage/agents.md`：补「## 相关页面」，指向 技能使用情况概览、使用情况配置、隐私与数据边界、推荐技能使用情况规则。
6. `docs/cli/skill.md`：「目标选择」「外部来源」「作用域」三节合并为「分发目标与来源」一节，三条独有事实逐字保留、链接原样搬迁，
   位置仍在「技能选择」之后；`faq` 引用的 `skill#策略与内容闸门` 不动。

格式沿用站内既有写法：`- 参考：[显示名](./路径) · [显示名](./路径)`，链接文案用显示名、不带标识。

## 影响范围

- 触达：docs/cli/privacy.md、docs/usage/index.md、docs/usage/privacy.md、docs/usage/schema.md、docs/usage/agents.md、docs/cli/skill.md。
- 补节与合并碎节，不删任何事实；各页行数不增。
- 变更集：patch 变更集，条目为 `- 优化：统一页尾体例，补齐缺失的相关页面并合并技能分发的碎节`。

## 验证方式

1. 5 个页面均出现「## 相关页面」节，且新增链接可解析到存在的页面。
2. `docs/cli/skill.md` 合并后三条事实（目标优先级、`--source` 行为、`--scope` 缺省判定）逐条仍在，`skill#策略与内容闸门` 仍可定位。
3. `node dist/cli.js docs nav check` 通过，页面体量告警不新增。
4. `pnpm test` 的文档一致性用例通过（无失效锚点）。
5. 归档后 `pnpm verify`。
