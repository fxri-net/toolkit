# 全局规则统一分类与文件迁移

## 计划位置

toolkit 2 / 2；前置：无（与「usage 向导记忆」无文件冲突，按序执行）；目标版本：1.16.2。

## 背景

当前三份可复制全局规则分散在三处：`docs/ai-rules.md`、`docs/commit-rules.md`、`docs/usage/global-rule.md`。前两篇有统一页头与「> 规则更新时间 …」锚点，usage 规则页是裸文案、无锚点、且「可选」写在标题里。用户要求三篇归入同一分类，并按方案 B 迁移文件。

## 实施方案

1. **文件迁移**（`git mv`，内容随迁）：
   - `docs/ai-rules.md` → `docs/rules/ai.md`
   - `docs/commit-rules.md` → `docs/rules/commit.md`
   - `docs/usage/global-rule.md` → `docs/rules/usage.md`
   - 新增 `docs/rules/index.md`：三篇规则索引（适用对象、复制方式、锚点自查）。
2. **usage 规则页对齐**：页面补齐「推荐 …规则 / 目标读者 / 解决什么问题 / 规则全文（可直接复制）」结构；「可选」移到页面引言（复制块之外）；复制块首行补 `> 规则更新时间 YYYY-MM-DD HH:mm。…` 锚点；标题改为 `## Skill usage（技能使用情况）`。
3. **规则文案同源**：`src/usage/rule.ts` 常量与 `docs/rules/usage.md` 复制块保持同文；`toolkit usage rule` 输出随之更新。
4. **锚点纪律**：`AGENTS.md` 质量门第 6 条与 `.tasks/conventions/index.md` C-15 的规则页清单纳入 `docs/rules/usage.md`；conventions `history.md` 先留痕、再更新索引当前语义。
5. **导航与链接**：`.vitepress/config.mts` 新增「全局规则」分组（索引 + 三篇）；全量更新引用旧路径的文档、README、skills references 与测试。
6. **测试**：`docs-consistency.test.ts` 的规则页路径与锚点断言、`usage-cli.test.ts` 的规则标题断言同步；文档站死链检查覆盖新路径。
7. 新增变更集，`patch`。

## 影响范围

- 文档：docs/rules/index.md、docs/rules/ai.md、docs/rules/commit.md、docs/rules/usage.md、docs/.vitepress/config.mts、docs/index.md、docs/handbook.md、README.md、docs/usage/index.md（链接）。
- 代码：`src/usage/rule.ts`。
- 测试：`src/__tests__/docs-consistency.test.ts`、`src/__tests__/usage-cli.test.ts`。
- 规则层：`AGENTS.md` 质量门第 6 条、`.tasks/conventions/index.md` C-15、`.tasks/conventions/history.md`。
- skills：`skills/fxri-plan-to-task/references/conventions-spec.md` 与 `conventions-templates.md` 中引用规则页路径的措辞；若需改技能正文，按规则递增技能版本。
- 旧路径 `docs/ai-rules`、`docs/commit-rules`、`docs/usage/global-rule` 迁移后 404，接受，不做重定向页。
- 无触达：`SPEC.md`（锚点仍在原位，内容不变）、`docs/usage/global-rule` 之外的 usage 功能页。

## 验证与回滚

- `pnpm verify` 全绿；`pnpm docs:build` 无死链。
- 手工核对三篇规则的页头结构一致、复制块首行均为锚点；`toolkit usage rule` 输出与 `docs/rules/usage.md` 复制块逐字一致。
- 回滚：单提交 `git revert`；文件为 `git mv`，回滚即恢复原路径。

## 决策记录
