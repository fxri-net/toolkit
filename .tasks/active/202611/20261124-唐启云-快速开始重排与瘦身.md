# 快速开始重排与瘦身

第 3 个（共 7 个）；前置：20261124-唐启云-新增适用场景页；后继：无

## 背景

`docs/getting-started.md` 共 235 行，最短路径「30 秒上手」在 L166。它前面依次是：解决什么问题（9 行）、谁适合用（17 行）、
几个术语（14 行）、安装（83 行，占全页 35%）、只想在部分项目生效（17 行）、配置全局规则（15 行）。

首页 hero 的「30 秒上手」按钮直达本页，读者首屏看到的是痛点叙述与长安装对比，最短路径要滚过大半页才出现。
「只想在部分项目生效」「配置全局规则」属进阶用法，却排在最短路径之前。
成熟文档站的梯度是「最短路径 → 详细安装 → 概念 → 进阶」，本页顺序与之相反。

「谁适合用」6 行角色表按场景归类更合适，已随「适用场景」页迁出（前置任务），本页改为页首一句链接，不再重复角色说明。

## 实施方案

1. 首节改为「30 秒上手」（约 30 行）：只给一条安装命令（默认 `pnpm add -g @fxri/toolkit`）+ `toolkit setup` +
   进项目说「初始化任务区」，其余包管理器与方式对比全部留在完整安装——同一组四条安装命令不在页面里出现两次。
2. 原「安装」节降为「完整安装」详解，保留既有三种方式的代码块、升级命令、nvm / fnm 绑版本坑、团队 devDependency 与内网说明。
3. 章节顺序改为：30 秒上手 → 完整安装 → 几个术语 → 只想在部分项目生效 → 配置全局规则 → AI 用户 → 相关页面；
   「谁适合用」整节移交适用场景页，本页页首只留一句「不确定自己属于哪类？见[适用场景](./scenarios)」。
4. 「解决什么问题」9 行压成 2–3 行导语，并入页首「目标读者」段，不再单列节。
5. 同步入站锚点（标题改名则链接跟着改，不留死锚点）：
   - `getting-started#安装`：handbook L9、faq L19 / L23 / L52、packages L54、rules/ai L83
   - `getting-started#_30-秒上手`：handbook L18、cli/setup L45（同时核对该锚点与 VitePress slug 是否一致，不一致按正确写法统一）
   - `getting-started#谁适合用`：faq L225 改指 `./scenarios`（该小节迁出后原锚点失效）
   - `getting-started#ai-用户-让-ai-替你操作`：faq L136
