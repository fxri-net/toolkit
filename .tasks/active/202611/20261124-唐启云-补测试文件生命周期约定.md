# 补测试文件生命周期约定

第 3 个（共 4 个）；前置：无；后继：无

## 背景

覆盖率门禁改为改动行判定后，补测频次会上升。当前仓库只有「孤儿测试会因 import 失败而报错」这一道自然拦截，
没有任何「测试文件归并 / 退休」的约定或机制：同一模块的新用例可能按任务各建一个文件，源模块删除后旧用例也可能残留，
长期会让 `src/__tests__/` 随任务线性膨胀，拖慢门禁并制造虚假的安全感。

需要一条仓库级规范把「测试文件跟着被测模块走」定下来，并明确冗余用例的盘点时点；不引入 mutation testing 等重工具。

## 实施方案

1. 在 `.tasks/conventions/testing.md` 新增 `C-56. 测试文件按被测主题归并`：
   - 映射：按被测主题建文件（如 `tasks/validate` 可拆 `validate-line` / `validate-import` 等主题文件；接口或命令页面对应 `skills-lint-cli` 这类入口文件）。
   - 补测：只在既有同主题文件追加用例；仅当被测主题确实不存在对应文件时才新建，**不按任务、日期再起一个**。
   - 退役：源模块删除或合并时，同批删除 / 合并其测试文件，不留孤儿用例与失效 mock。
   - 盘点：每版发布前人工过一遍冗余——重复断言（同一行为在两个文件各测一遍）、只测实现细节、对应行为已移除的用例，删除或合并。
   - 存量：不强制批量合并既有碎片（如 skills 19 个、scope 15 个），只约束新增；确需合并时单独评估。
   - 反例：同一模块在三个任务里各建一个 `xxx-2.test.ts`；同一行为在 `conventions-status` 与 `validate-conventions` 两处各断言一遍；模块删除后测试仍引用已删实现；为刷改动行覆盖率写只走主路径的空断言。
   - 理由：覆盖率按改动行判定会提高补测频次；不归并则测试文件随任务线性膨胀，重复断言还会让「改一处漏一处」成为常态。
2. 索引与留痕：`index.md` 增加 C-56 行（当前语义写「写或补测试时：按被测主题归并到既有测试文件、源删测删、每版盘点冗余」）；`history.md` 追加新立记录（日期 + 来源任务）。
3. 不新增机检：孤儿测试由 import 失败天然拦截；用例是否冗余无法机械判定，盘点作为发布前人工检查项（写进条目，不另挂脚本）。
4. 不把条文复述进 `AGENTS.md`——规范载体是单一事实源，AGENTS 已要求动手前读 `conventions/index.md`。

## 影响范围

- 触达：`.tasks/conventions/testing.md`、`.tasks/conventions/index.md`、`.tasks/conventions/history.md`。
- 只加规范，不改代码与测试；后续补测行为按新条目执行。
- 变更集：无（仓库内部规范，无对外行为变化）。

## 验证方式

1. `node dist/cli.js convention status` 通过（索引与分册一致、无形态告警）；`task check` 0/0。
2. 索引行与 testing.md 小节 ID 一致，`history.md` 留痕齐全。
3. 归档后 `pnpm verify`。
