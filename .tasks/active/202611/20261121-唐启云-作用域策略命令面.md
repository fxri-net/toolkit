# 作用域策略命令面

> 计划位置：第 3 个（共 5 个）；前置：20261121-唐启云-作用域策略配置加载；后继：20261121-唐启云-技能矩阵向导

## 背景

统一策略模型允许「纯路径 / 纯远端 / 纯标记」与「技能维度」两类规则；只做 `scope skills` 会让前者只能手写 JSON，
与「策略条目」模型不对称。本任务补通用命令面，并保留 `scope skills` 作为技能维度快捷视图；写盘沿用 scope 既有「计划 → 预览 → 确认 → 结果块」口径。

## 实施方案

1. 新增 `scope policy` 子命令组：
   - `list`：列出来源层、`id`、`name`、`when`、`skills`、`effect` 与当前目录生效结果；旧字段编译出的规则标注 `legacy` 只读，提示用 `scope` 既有命令修改；支持 `--format json` 与 `--at <dir>`；
   - `add`：`--effect allow|deny`，条件 `--paths` / `--subpaths` / `--markers` / `--git-remotes`，技能维度 `--mode` / `--profile` / `--allow` / `--deny`，可读标签 `--name`（任意），稳定标识 `--id`（缺省自动生成且不可变）；
   - `remove`：优先 `--id`；`--name` 仅在该层唯一时可用，跨层同名或缺省歧义时要求显式 `--layer`；`reset`：按层与路径批量清除，无 `--id` / `--paths` 时须显式 `--all` 且需 `--yes`；`--all` 只清 `policies` 段，旧 `activation` 字段用 `scope reset` 处理。
2. `scope skills` 保留为技能维度快捷视图（`list` / `allow` / `deny` / `profile` / `reset`），底层复用同一计划与写盘模块；`allow/deny` 等价于带技能维度的 `policy add`。
3. `scope status` 增加 `--skills` 与 `--at <dir>`：列出目标目录全部技能与允许 / 拒绝结论及来源；`--at` 同时作为配置层定位起点（按该目录向上找配置），只改判定视角、不改进程 cwd；`--format json` 输出结构化字段。
4. 稳定标识：CLI 生成的规则必须写 `id`，跨层唯一、不可修改；`name` 只作可读标签；`remove` / `reset` 按 `id` 操作，guard 原因显示 `id` 与 `name`。
5. 校验并告警：未知档案、非法模式、空条件兜底规则、跨层 `id` 重复、按包内技能清单校验技能名；`deny` 未给技能模式时提示会拒绝该范围全部技能，需 `--yes` 才写入；错误文案统一「原因 + 未写入配置」。
6. 帮助写清层优先级（local > project > global）→ 具体度 → deny → 后写、覆盖语义（不合并多规则）、子目录失败关闭、非技能维度也能用 `scope policy` 表达；补 `cli-golden` 与命令单测。
