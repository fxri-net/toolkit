# 技能矩阵联动与文档

> 计划位置：第 5 个（共 5 个）；前置：20261121-唐启云-作用域策略命令面、20261121-唐启云-技能矩阵向导；后继：无

## 背景

矩阵只有配合内容闸门才真正限制正文；未开闸门、技能已装但从未被任何项目允许等情况需要显式提示，否则用户会以为限制已生效。
本任务收口联动告警、文档与变更集。

## 实施方案

1. 闸门联动：配置了矩阵但 `skillsInstall.gate` 未开启时，`scope status` / `scope skills list` 输出提示「矩阵已配置，但正文仍全量加载」；
   策略限制了某技能、但该技能未被闸门覆盖（`gate` 规则排除或技能声明 `metadata.gate: false`）时逐项告警「策略无效：技能仍全文加载」。
2. 死技能告警：`skills status` 与 `scope skills list` 汇总「已安装但矩阵中任何规则都不允许」的技能；只提示不自动删除。
3. guard 联动验证：任务 1 已在判定结果写入规则 `name`（缺省 `policy:<序号>`）/ `profile:<名>` 原因，本任务只验证 guard 输出与退出码 3 契约，不重复实现。
4. 文档：
   - `docs/config/activation.md` 增加「策略规则」「档案」「优先级与合并」「子目录」「软限制边界」五节与示例；
   - 说明 `when` 同字段 OR、跨字段 AND，优先级为层（local > project > global）→ 同层具体度 → deny → 后写覆盖；
   - 说明 `subpaths` 按 cwd 匹配、在项目根执行时 allowlist 规则按拒绝处理（失败关闭），以及用 `scope skills list --at` 查看；
   - 说明规则是覆盖而非叠加：项目要追加技能时引用同一档案并补增量；旧字段编译出的规则只读，`scope policy reset` 不清旧字段；
   - 说明规则标识：`id` 为跨层唯一的稳定机器键（CLI 生成、不可变），`name` 为可读标签；删除与 guard 解释按 `id`；手写规则建议显式写 `id`，否则内容变更后 id 会变；
   - 说明 `scope policy` 与 `scope skills` 的分工：前者覆盖全部策略维度，后者是技能维度快捷视图；
   - 说明父目录 glob（如 `~/work/**`）自动覆盖其后新建的项目，无需逐项目配置；项目自带 `activation` 时按最近层整段覆盖，是唯一例外；
   - `docs/cli/scope.md` 补 `scope policy`、`scope skills` 与 `status --skills`；
   - `docs/cli/skills.md` 说明策略与内容闸门、项目面安装的关系；
   - `docs/cli.md` 术语表补充「策略 / 档案」。
5. 变更集按 patch 记录（设计缺陷补全口径），并补 `cli-golden` 与文档断言。
