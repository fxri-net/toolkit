# 新增核心模型页

第 4 个（共 7 个）；前置：20261124-唐启云-文档站导航按实用性重排；后继：20261124-唐启云-首页重排

## 背景

用户反馈：项目太复杂、看完一脸懵逼，想要结构图 / 架构图 / 思维导图；同时分层感受不同——轻度用户看完整图觉得复杂，
重度用户看简图觉得不够。现状是全站零图示：术语表 6 行、工作流总览 15 行，五件套（任务 / 规范载体 / 技能 / 规则 / 配置与作用域）
分散在 5 个分页，读者要读 5 页才能拼出心智模型。

参考成熟设计：Vite「Why Vite」、Next.js 项目结构、Vercel 的「Choose your path」都用「先给全局图 + 按人物路径分流 + 细节渐进展开」，
而不是一张图包打天下；思维导图适合个人发散、不承担检索，站点导航已由侧栏与文档索引承担，故不采用导图图片。

## 实施方案

### 一、同一页承载两种粒度（不做两个页面）

1. 页首「两条路径」：轻度（只想让 AI 按规范干活）3 步；重度（任务协作 + 规范沉淀 + 发版）4 步。每步都是链接，读者不必先看图。
2. 「一张图看懂」：默认只显示**概览图**（三层、约 8 个节点），节点可点、悬浮显示「点击查看 · 目标页」。
3. 概览图下接 `<details>展开完整结构</details>`：展开后是**能力全景表**（全部命令域）× 4 列（域 / 一句话 / 入口命令 / 命令页），
   重度用户拿全量，轻度用户默认看不到。
4. 「一条任务的一生」：横向流程图（说需求 → 出方案 → 建档 → 执行 → 校验 → 归档 → 规范沉淀），每步标注对应命令并可点。
5. 「五件套怎么配合」：关系图 + 五件套表（件套 / 解决什么 / 存放位置 / 入口命令 / 谁维护）。
6. 「三个最容易混淆的点」：装了 CLI ≠ 装了技能；任务区 ≠ 规范载体；全局规则是快照、升级后要重新组合。
7. 「深度了解」：`::: details 仓库结构` 目录树 + 指向 API 参考与 AGENTS 的链接。
8. 页尾指向「适用场景」：本页讲清结构，适用场景页回答「我属于哪类、走哪条路」，两页互不复制路径细节。

### 二、图示实现（零依赖、可点、亮暗自适应）

- 新增 `docs/.vitepress/theme/components/diagrams/`：`ConceptMap.vue`（三层结构）、`TaskJourney.vue`（任务旅程）、`ModelMap.vue`（五件套关系），
  沿用 `RuleComposer.vue` 的既有做法（页面内 import 使用，不改 `index.ts` 与 `custom.css`，避免 `docs theme check` 报主题漂移）。
- 节点链接数据抽到同目录 `links.ts`（`{ id, label, to, note }[]`），组件与测试共用同一份，避免图与表两处维护。
- 所有站内跳转用 `withBase()` 拼接（站点 base 为 `/toolkit/`，裸 `/cli/task` 在 GitHub Pages 子路径下会 404）；节点整块可点，键盘可聚焦。
- 视觉统一用 VitePress 令牌（`--vp-c-text-1` / `--vp-c-bg-soft` / `--vp-c-divider` / `--vp-c-brand-1`），亮暗自动适配；
  `viewBox` + 宽度 100% 等比缩放，窄屏可读。
- 新增 `docs/concepts.md`（H1 与 frontmatter title 均为「核心模型（concepts）」），承载上述内容，约 130 行。

### 三、覆盖与跳转的机检兜底（新增 `src/__tests__/docs-diagrams.test.ts`）

1. **覆盖**：能力全景表的命令域集合 === `COMMAND_REGISTRY` 中 `stage: current` 且非 `help` 的顶层域；新增命令漏登记即失败。
2. **覆盖不复制**：技能与配置不在页内复制清单，分别指向 `packages`（技能源）与 `config`（配置字段）单一真源，避免第二份会漂移的列表。
3. **跳转**：`links.ts` 中每个 `to` 都必须解析到 `docs/` 下存在的页面（带锚点时校验锚点）；
   现有 `docs-consistency` 只校验 markdown 渲染出的 href，覆盖不到组件内部链接，故单列此用例。
4. **图与表一致**：概览图节点 `id` 与全景表行一一对应，图里加的块必须进表，反之亦然。

### 四、登记

- `docs/site-nav.json`：指南组首位加「核心模型」→ `/concepts`；顶栏「指南」下拉同批加为首项（当前下拉与侧栏指南组逐项镜像）。
- `docs/index.md` 与根 `README.md` 的文档索引同批加一行（F-29 只机检目标页集合，漏登即失败）。
- `docs/tsconfig.json` 的 `files` 补三个组件，保证 `typecheck:docs` 覆盖新代码。

## 验证方式

1. `pnpm docs:build` 成功；概览图、流程图、关系图在亮色与暗色下文字与描边均可读，节点点击能到目标页。
2. `pnpm test` 通过，其中新增用例覆盖：命令域覆盖、`links.ts` 跳转可解析、图与表一致。
3. `pnpm typecheck:docs` 通过（三个组件纳入类型检查）。
4. `node dist/cli.js docs theme check` 通过（未改主题模板）；`node dist/cli.js docs nav check` 通过（顶栏 5 项、侧栏 7 组）。
5. `pnpm test` 的既有文档一致性用例通过（两处索引目标页集合一致、锚点有效）。
6. 归档后 `pnpm verify`。
