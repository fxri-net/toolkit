# 新增内网推广页

第 6 个（共 7 个）；前置：20261124-唐启云-新增适用场景页；后继：无

## 背景

典型传播路径是「某个员工自己用着好 → 想在公司内推广 → 不知道怎么简洁清晰地介绍给别人和领导」。
现有文档全部面向使用者（怎么装、怎么用），没有任何一页面向推广者与决策者：没有可直接复制的一段介绍、没有试点方案、没有对「安全 / 成本 / 与现有工具冲突」的回答。
这类角色是开源工具在组织内落地的关键节点，缺这一页，传播会停在「口头推荐」并迅速流失。

参考成熟设计：1Password / Linear / Vanta 等产品的「Rollout guide」都包含：一句话价值、给不同听众的讲稿、试点范围与指标、决策者 FAQ、推进清单。

## 实施方案

1. 新增 `docs/adoption.md`，H1 与 frontmatter title 均为「内网推广（adoption）」，约 110 行，面向「推广者 + 决策者」，不写命令细节。
2. 内容结构：
   - **一句话介绍**（≤60 字，可直接复制到群公告 / 邮件）：把对话里的方案与交付变成仓库里可校验、可分发、可迁移的资产。
   - **两版讲稿**：30 秒（问题 → 做法 → 效果各一句）与 3 分钟（现状痛点 / 它怎么解决 / 试点怎么开始）。
   - **试点方案**：选 1 个仓库、2 周、3 个指标（任务留档率、返工与重复沟通次数、沉淀出的规范条数）；给出成功与止损判据。
   - **决策者问答**：数据存在哪（默认全本机，统计默认关闭）、要不要全员装（可只在试点仓库用 devDependency）、
     与 Jira / Confluence 是否冲突（管的是 AI 会话里的方案与交付，不替代工单与文档站）、许可与成本（MIT）、
     安全与脱敏（`redact` 默认开、`privacy` 扫描本机路径）、试点失败怎么退（仓库内文件删掉即还原）。
   - **推进清单**：选试点仓库 → 装 CLI → `toolkit setup` → 项目内 `toolkit task init` → 跑两周 → 复盘三项指标 → 决定是否推广。
   - **常见阻力**：「我们已经有 Jira」「AI 写的东西能信吗」「会不会把代码传到外面」——每条给一句事实回答并链到对应页。
3. 事实口径以既有页面为单一真源：隐私与数据边界见 `usage/privacy`、脱敏见 `config/redact`、本机路径见 `cli/privacy`、成本与许可见仓库 `LICENSE` / `package.json`；不夸大、不新增承诺。
4. `docs/site-nav.json`：指南组第 3 位加「内网推广」→ `/adoption`（适用场景之后）；顶栏「指南」下拉同批加为第 3 项。
5. `docs/index.md` 与根 `README.md` 的文档索引各加一行（F-29 只机检目标页集合）。

## 影响范围

- 新增：docs/adoption.md。
- 触达：docs/site-nav.json、docs/index.md、README.md（与任务 1 同文件，排在其后）。
- 与「适用场景」分工：场景页回答「我属于哪类、走哪条路」，本页回答「怎么说服别人、怎么小范围试」；不复制场景路径。
- 变更集：patch 变更集，条目为 `- 新增：补「内网推广」页，提供一句话介绍、讲稿、试点方案与决策者问答`。

## 验证方式

1. `node dist/cli.js docs nav check` 通过（顶栏仍 5 项，指南下拉加入后仍 ≤8）。
2. `pnpm test` 的文档一致性用例通过（两份索引目标页集合一致、锚点有效）。
3. 人工核对：讲稿与 FAQ 中的安全 / 隐私 / 成本表述与 `usage/privacy`、`config/redact`、`cli/privacy`、`LICENSE` 一致，无夸大承诺。
4. 归档后 `pnpm verify`。
