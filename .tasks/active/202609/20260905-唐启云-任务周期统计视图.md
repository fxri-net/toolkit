# 任务周期统计视图

## 背景

用户要求评估工时统计能力：精确打卡型工时与「AI 全程自主、零负担」定位冲突（AI 无法代填真实人工时长），明确不做；周期统计基于现有 created/completed 结构化数据可零字段推导，用户拍板纳入 1.7.0。服务对象：项目经理（吞吐与排期回顾）、技术负责人（成员负载）。

## 实施方案

- `tasks` 增加统计视图（`tasks stats` 子命令或 `--view stats`，实现时定口径后统一）：
  - 周期指标：已完成任务的平均/最长完成周期（completed − created）、周期分布分段；active 任务只统计滞留时长
  - 吞吐指标：按月/按 owner/scope 维度的完成数汇总
  - 复用 query 层现有行数据与过滤参数（`--owner`/`--scope`/`--since`/`--until`），不新增字段
- 导出联动：统计结果是否纳入 CSV/XLSX/JSON 导出（实现时定，至少保证 `--format json` 可读）
- 文档同步：cli.md 命令字典补统计条目；getting-started「谁适合用」边界行已预写「打卡型工时统计不提供（周期统计 1.7.0 起提供）」，实现后去掉版本前缀标注

## 影响范围

- src/tasks/（query/list/cli 层新增统计渲染）；docs/ 文案同步；skills 是否需要感知（统计属人用能力，AI 技能预计不涉及，实现时确认）；无破坏性变更

## 验证方式

- 单测：周期计算边界（同日任务、缺 completed 跳过、跨月归档口径）
- CLI 冒烟：空任务区 / 有过滤 / archived 视图
- 文档与实现一致性由 p3 验收矩阵「能力双向核对」行兜底
