# 编写 docs 八篇文档体系

## 背景

现有 README/SPEC 无法支撑新用户自助上手。按需求拆分为双形态内容（GitHub 直读 + VitePress 站点同源），能力前置、链接跳详情、去重收敛。

## 实施方案

docs/ 下新建八篇：

1. `index.md` 站点首页：是什么/解决什么痛点/能力矩阵/文档索引
2. `getting-started.md` 新手指南：30 秒上手、零基础术语、安装三方式对比（项目 devDep / 全局 / 独立 pnpm，含 nvm/corepack 切版本陷阱）、能力前置链接
3. `guide.md` 完整攻略：方案落盘（任务如何产生）、会话归档、Git 纳管范围（.tasks 整体入库、.toolkitrc.json 建议提交、.archive.lock 忽略）、项目级强制激活模板、三平台部署发布、多语言 CHANGELOG
4. `cli.md` CLI 参考：tasks/changelog/init 全命令、参数、默认值、退出码、help footer 说明
5. `api.md` Node API 参考：按 src/index.ts 实际导出编写，纯 CLI 则并入 cli.md（执行时确认）
6. `config.md` .toolkitrc.json 参考：字段枚举、脱敏规则、scope 校验
7. `faq.md` FAQ：工具与 skills 的区别、.tasks 入库范围、node 切版本全局包丢失、只在公司项目激活、会话归档边界等（匿名化，不留真实人名）
8. `ai-rules.md` 推荐全局规则：源自作者自用全局规则三层转化（通用 AI 协作规则原样 / toolkit 专属工作流视角转换 / 安装升级校验命令直接可用），去标识处理；升级后开新会话 ⚠️ 强调

同步：SPEC.md 瘦身为规范摘要+站点链接；各能力页开头统一「解决什么问题」小节。

## 影响范围

- 新增 docs/ 八篇；SPEC.md 瘦身；README 入口页（独立任务）
- npm 包 files 白名单暂不含 docs/，不影响产物

## 验证方式

- 相对链接可达（站点构建死链检查兜底）
- 与真实能力一致性核对：cli.md 逐命令对 src/cli.ts、config.md 逐字段对 .toolkitrc.json 解析代码
