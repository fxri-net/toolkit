# 文档体系重构与上手体验优化

## 背景

现有文档（README/SPEC）与真实能力、skills 存在覆盖缺口：新用户不知道如何上手、不知道项目对自己有什么用；缺快速上手指南、FAQ、Git 纳管范围说明；node 多版本用户遇到全局安装丢失问题；缺会话归档能力；CLI 安装/升级后无引导。本任务统一解决，覆盖 31 项需求与 3 位用户反馈素材。

## 目标

1. 文档双形态：GitHub 直读 + VitePress 站点（本地搜索、多平台部署），内容同源
2. 新用户 30 秒看懂（getting-started）、老用户查得到（FAQ + 完整攻略）
3. 新增 fxri-session-recap 技能（一句话归档本次会话/恢复上下文）
4. CLI 上手体验：help footer 链接、toolkit init、升级检查提示
5. 依赖修正：commander 15 → 14.0.3（Node 20 兼容）
6. 发版前三者一致性验收：文档、真实能力、skills 完全一致

## 实施方案

分 Phase 执行，每个任务完成后自动归档并独立提交 git，中途不确定点与用户确认：

- **P0 依赖修正**：commander ^15.0.0 → ^14.0.3（engines >=20 对齐），重新生成 lockfile，全量回归
- **P1 文档**：docs/ 八篇（index/getting-started/guide/cli/api/config/faq/ai-rules）；README 重构为入口页；SPEC.md 瘦身为规范摘要+站点链接；内容含痛点与行业定位、工具与 skills 的区别、Git 纳管范围、安装方式对比（nvm/corepack 陷阱）、项目级激活模板；FAQ 匿名化收录用户素材
- **P1 会话归档**：新增 skills/fxri-session-recap（场景 A：归档本次会话 → 结论进任务文件 → 走归档流程；恢复上下文 → 读 active+最新归档）；文档写明跨会话边界
- **P1 skills 复查**：现有 2 个技能探测顺序写醒目、重复内容收敛、metadata.version 递增
- **P1 站点**：VitePress devDep；docs/.vitepress/config.mts（中文主题、sidebar/nav、本地搜索、base 用 VITEPRESS_BASE 环境变量可配）；deploy-docs.yml（GitHub Pages）；.gitlab-ci.yml pages job（自托管 GitLab）；Gitee 写手动构建步骤进文档；CI check job 追加 docs build（逐次全跑）
- **P2 CLI**：addHelpText 文档链接 footer；toolkit init（.tasks 骨架 + .gitignore 片段含 .archive.lock + 输出指南链接）；升级检查（命令末尾异步查 registry、24h 缓存、静默失败）
- **P3 验收**：三者一致性验收矩阵逐项核对（CLI↔文档、CLI↔skills、skills↔文档、安装↔package.json、链接↔真实 URL、版本号对齐、配置↔config.md）；**完成后等用户确认才发版**

## 影响范围

- package.json/lockfile、README.md、SPEC.md、docs/（全新）、.gitignore、.github/workflows、.gitlab-ci.yml、src/cli.ts、skills/（1 新增 2 复查）
- npm 包产物不受影响（files 白名单不含 docs/）
- 版本：minor（1.6.5 → 1.7.0）

## 验证方式

- 每 Phase 全量门禁：typecheck / lint / test / build / CLI 冒烟 + docs build 死链检查
- commander 降级后重点回归 CLI 全命令冒烟
- P3 验收矩阵逐项打勾后才归档；发版动作等用户明确确认

## 收尾项

- 全部子任务完成后执行 P3 验收，结果报给用户确认
- 用户确认后：changeset minor → 发版 → 三远端推送
