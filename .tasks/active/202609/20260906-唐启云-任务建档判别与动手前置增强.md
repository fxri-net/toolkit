# 任务建档判别与动手前置增强

## 背景

AI 在「方案已确认、准备动手改仓库文件」时可能跳过建档直接执行（本会话已发生一次），根因是「先查后写」只在建档触发场景生效，未覆盖全部动手场景。需把建档评估提升为所有仓库改动任务的强制前置，并补齐同主题任务的增量判别：归档任务不可变，有增量必须重新建档并标注来源链。

## 实施步骤

1. fxri-plan-to-task SKILL.md（1.0.8 → 1.0.9）：
   - description + 「何时使用」补触发扩展：「用户确认方案后准备动手改仓库文件」也是适用场景
   - 工作流第 1 步「先查后写」扩为「动手前置：建档评估」，补完整判别表：
     - active 有同主题：补充/细化 → 更新原文件；已分叉 → 问用户拆新 or 合并
     - active 无、archive 有：无增量 → 提示已归档不重复建档；有增量 → 重建 + 正文首行来源链 `延续 {归档任务名}（见 archive/{YYYYMM}/{YYYYMMDD}.md）`；仅时间/内容错误 → 走模式三修正不建档
     - active/archive 均无：建档后再动手（硬前置）
   - 增量判别口径：新方案含原任务不存在的新需求点 = 有增量；完全同描述同范围 = 无增量；拿不准列差异问用户
   - 归档块不可变：不向已归档块追加内容
2. references/task-spec.md：协作约定补「归档任务不可变、延续走新任务 + 来源链标注」
3. AGENTS.md 协作流程约束 + ai-rules.md 稳定纪律：同款「动手前建档评估」一句话
4. 变更集：minor（plan-to-task 触发场景 + 流程扩展，能力级）
5. 收尾：本任务归档 → conventions 沉淀 → 提交（先给用户确认）

## 影响范围

- 无 CLI 变更
