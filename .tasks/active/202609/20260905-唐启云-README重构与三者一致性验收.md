# README 重构与三者一致性验收

## 实施方案

### A. README 重构为入口页

- 首屏：是什么/解决什么痛点/行业定位（多人 + AI 协作的工作记忆方案）
- 30 秒上手（安装 → init → 建档 → 归档最短路径）
- 能力矩阵前置，全部以链接跳 docs/ 对应篇
- 文档索引（八篇目录）、skills 说明、与 docs/index.md 同源适配互相链接
- SPEC.md 瘦身配合：规范摘要 + 站点链接
- 美化：badges、能力矩阵表、分节导航、风格与 docs 八篇统一（与 docs 任务的美化要求同批执行）

### B. 三者一致性验收矩阵（发版前最后一步，逐项打勾）

| 方向 | 核对项 |
| --- | --- |
| CLI ↔ 文档 | 命令/参数/默认值/退出码与 cli.md 逐项一致；示例输出与真实输出一致 |
| CLI ↔ skills | 探测顺序与真实调用路径一致；工具缺失指引与实际能力匹配 |
| skills ↔ 文档 | 流程描述同义；触发词与快速上手演示一致 |
| 安装/升级 ↔ package.json | 命令与 bin 名/engines/包名对应；开新会话提示两边一致 |
| 能力输出 ↔ 链接 | help footer、init 输出、README、deploy 配置的站点 URL 与真实 base 一致 |
| 版本号 | skills version ×3、package.json、changeset、文档说明同批对齐 |
| 配置 ↔ config.md | .toolkitrc.json 实际字段与 config.md 枚举一致 |

### C. 收尾（等用户确认后才执行）

- changeset minor（1.6.5 → 1.7.0）→ 发版 → 三远端推送
