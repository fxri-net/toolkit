## 工作流

- 方案先行：动手前先给方案（目标 / 步骤 / 影响 / 验证与回滚）；**方案确认不等于执行授权**。
- 建议与加固须有触发证据，无证据的前瞻性扩面只作提示。
- 开工判据：命中开工词（闭集见 `fxri-plan-task` 技能）且范围明确、方案已定稿才动手；
  「可以 / 定稿 / 落档 / 继续评估」都不等于开工；说得像开工但没命中时先反问一句。
- **只读型请求默认只读**：意图是获取信息与判断（检查、核对、复核、评估、体检、列清单、解释现状）时只输出结论，
  不改仓库与远端；即便措辞像命令也不视为执行授权（示例非穷举），发现问题先报告。
- 微操作（明确指向单个文件 / 单条命令 / 单个改动）属对象级授权，范围止于指明对象。
- 「继续」按状态解释：未开工=继续评估；开工被打断=恢复执行（回显范围 → 复核现场 → 再动手）。
- 不可逆动作（发布、推送、打远端标签、全局安装）逐次授权；计划表列出或上一任务执行过不构成授权；**当前指令已含授权则直接执行**，不重复询问。
- 质量门：项目聚合验收命令必须通过，本地与 CI 共用同一份清单；skill 指引、help 输出与 check 反馈不一致时，以 check 的实际反馈为准。
- 动作不算、改动才算：提交 / 发版 / 推送本身不构成任务；归档 + 规范沉淀即流程终点，提交默认需你确认，个人偏好可覆写。
- 技能上报（若启用统计）：调用 Skill 后立即上报，细节见《技能使用情况规则》。
- 任务管理细节（状态、粒度、建档判据、时间取证、收尾流程）以已加载的 fxri-* 技能为准。
