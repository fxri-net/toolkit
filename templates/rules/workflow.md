## 工作流
- 收到涉及代码编写、文件修改、命令执行等动手操作的任务时，不要立即开始。先输出结构化的实施方案，明确包含：
  - **目标**：要做什么，解决什么问题
  - **实施步骤**：具体的技术选型、文件变更清单或伪代码
  - **影响范围**：可能受影响的模块、接口或依赖
  - **验证与回滚**：如何测试，以及出错时的恢复方案
- 等待用户明确确认方案后，再动手执行；**方案确认不等于执行授权**——只读检查（查看状态、grep、体检）可在规划态执行，写文件、提交、发版、推送等改动状态的动作须有明确授权
- **只读型请求默认只读**：意图是获取信息与判断（检查、核对、复核、评估、体检、列清单、解释现状）时不改动仓库或远端状态，只输出结论；即便措辞像命令（如「检查一遍」「三方一致做一下」）也不视为执行授权，发现问题先报告、改不改由你决定。判据看意图与最终动作，措辞只是线索（示例非穷举）
- 不可逆动作（发布、推送、打远端标签、全局安装等）默认逐次授权；**当前指令已含授权则直接执行**，不必重复询问；计划表列出或上一任务执行过不构成授权
- **方案落盘与会话记忆**（依赖 `@fxri/toolkit` 及其 fxri-* skills，随 agent 自动加载；**细节一律以已加载的最新 skill 为准**，本规则只保留稳定纪律）：
  - 执行顺序：先尝试 `pnpm exec toolkit`（npm 用户 `npx toolkit`，优先项目级），失败则尝试 `toolkit`（全局）
  - 涉及任务建档、方案记录、会话收尾、上下文恢复或需求落地时，**优先走已加载的 fxri-* skill** 完成任务管理全流程，不跳过、不另起一套格式：建档/过程更新走 fxri-plan-to-task；落档后的任务复核走 fxri-plan-review；会话收尾与恢复走 fxri-session-recap；发版走 fxri-release-changelog
  - 稳定纪律（不随版本变）：
    - 规划先行：方案确认后、动手前，涉及多个任务时先给出纯展示的开发计划表——跨端、跨仓的任务同表列出并标明所属仓库与执行先后；表只作展示与排序，不落档、不进任务正文（任务粒度与表结构以已加载的 fxri-plan-to-task 为准）
    - 逐仓逐任务建档：每个将产生仓库文件改动的仓库，按任务清单逐个独立建档（无任务区先初始化），全部建档后再改第一处文件；只读参与的仓库不建档；一任务一档、多人共用一份，实施步骤留在正文不升格
    - 动手前先做建档评估：涉及仓库文件改动的任务，先查 active/archive 判同主题（active 有同主题更新原文件、archive 有同主题且本次不产生仓库文件改动则不重复建档直接执行、均无则先建档再动手；判别细节以已加载的 fxri-plan-to-task 为准）
    - 动作不算、改动才算：提交 / 发版 / 推送 / 部署等收尾动作本身及其固有产物不构成任务、不单独建档
    - 跨仓库改动各自归档：任务档是仓库自述，只记本仓的改动与动机；跨仓库是会话属性而非仓库属性，同一会话涉及多仓时各仓各自建档归档，不在一仓记录里承载另一仓的工作痕迹（判据取视角——描述的是不是本仓的改动；依赖包名/接口名等本仓事实照写，细则以 fxri-plan-to-task 为准）
    - 质量门：`toolkit tasks check` 必须通过；skill 指引、help 输出、check 反馈三者不一致时，以 check 实际反馈为准，不绕开门禁
    - 验收与 CI 同源：验收步骤清单只保留一份真源（项目内一条聚合命令，本地与全部 CI 共用），不在规则文件或 CI 配置里另抄一份步骤枚举
    - 任务时间字段按四级时间源取证，禁止用收尾时刻冒充任务真实发生时刻（口径以 fxri-plan-to-task references 为准）
    - 按序交付、逐任务提交：按计划表顺序推进，前置未完成或阻塞未解除时下游不开工；计划调整先更新展示表再继续；每个任务完成即走完该仓的归档、验收与提交，不跨任务攒批
    - 归档 + 规范沉淀即任务流程终点；**任务收尾的 git 提交自动执行**（作者个人收紧，可参考可裁剪：先归档与沉淀、后提交，归档文件与规范载体、代码变更落在同一 git 提交）；推送与发版默认需用户明确，当前指令已含授权则直接执行
  - 项目初始化：新项目（无 `.tasks/` 任务区）首次落盘前先执行 `toolkit init` 建骨架（幂等，已存在不覆盖），再走建档流程
  - 不可用时：
    1. 若因 `@fxri/toolkit` 或对应 Skills 未安装/未加载导致不可用，在对话中明确提示用户执行安装命令（见下方「环境与版本」），**不自行尝试全局安装**；用户确认环境就绪后再继续落盘
    2. 若确认无需落盘，将方案以 Markdown 完整输出到对话，提示用户可手动保存到 `.tasks/`；不阻塞任务执行，确保方案内容不丢失
- **技能上报（仅当启用技能使用统计时）**：每次调用 Skill 工具后立即按《技能使用情况规则》执行 `toolkit usage record --skill <技能名>`；该命令只写本机队列，不改仓库 / 远端，不受只读与授权纪律限制。
