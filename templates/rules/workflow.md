## 工作流

- 方案先行：动手前先给方案（目标 / 步骤 / 影响 / 验证与回滚）；删除 / 清理 / 覆盖等不可逆动作须写明影响对象、不可恢复部分、回滚与需确认项；**方案确认不等于执行授权**。
- 建议与加固须有触发证据，无证据的前瞻扩面只作提示。
- 授权判据：执行指向明确（开始 / 开工 / 处理 / 搞定 / 直接改 / 授权，示例非闭集）+ 范围唯一 + 方案已定稿才动手；
  同句只读诉求、方案未定稿、范围不唯一都不构成授权；「可以 / 定稿 / 落档 / 继续评估」也不等于开工。
- **只读型请求默认只读**：意图是获取信息与判断（检查、核对、复核、评估、体检、列清单、解释现状）时只输出结论，
  不改仓库与远端；即便措辞像命令也不视为执行授权（示例非穷举），发现问题先报告。
  同句含执行段时先交付只读结论，执行段按授权判据处理。
- 微操作（单文件 / 单命令 / 无派生改动）属对象级授权，范围止于该对象；多文件同步先回方案态。
- 「继续」按状态解释：未开工=继续评估；开工被打断=恢复执行（回显范围 → 复核现场 → 再动手）；新会话无上下文时按恢复现场处理，只读。
- 不可逆动作（发布、推送、打远端标签、全局安装）逐次授权；计划表列出或上一任务执行过不构成授权；**当前指令已含授权则直接执行**，不重复询问。会话级显式授权仅本次会话有效。
- 质量门：项目聚合验收命令必须通过，本地与 CI 同一份清单；skill / help 与 check 不一致时以 check 为准。
- 动作不算、改动才算：提交 / 发版 / 推送本身不构成任务；归档 + 沉淀即终点，提交按规则或授权执行。
- 目录能否用跑一次 `toolkit scope status`，同会话复用；入口壳未激活即停。
- 任务管理细节以已加载的 fxri-* 技能为准。
